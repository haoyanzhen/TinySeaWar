# 特别行动：海军战术难题与关卡设计

## 1. 功能与边界

本文负责「特别行动」的模式定位、战术难题设计原则、行动局势、固定编成候选、敌方任务、胜败条件与人机协作迭代方式。它是 `15` 系列的主题分册；教学、常规挑战与自定义仍见 [15](15_battle_level_design.md)。

依据2026-10-02用户决策：特别行动面向人的多样化策略，可以规则化、困难且需要多次破解；**不采用程序代打、自动搜索或 AI 胜率来调整设计平衡，不设置模拟通关率门槛**。由用户实际游玩反馈，与设计者共同迭代。程序验证仍负责实现正确性，不负责裁定难题是否有趣、够难或值得采用。

公共战斗与操作见 [10](10_game_core_mechanics.md)、[11](11_game_operation_design.md)，角色能力见 [14](14_character_balance_design.md)，AI设计见 [16](16_enemy_ai_behavior_design.md)，体验原则见 [17](17_play_design.md)，设施与天气见 [18](18_facility_weather_effect_design.md)。未来新增字段与任务结算分别进入 [22](22_scene_environment_data_schema.md)、[23](23_level_progress_data_schema.md)、[24](24_ai_data_schema.md)及相应Domain设计，不能由本文绕过规则直接实现。验收边界与 [36](36_balance_testing_design.md)衔接；当前实现与验证状态只见 [00](00_project_status.md)。

下列关卡是第一版设计候选。编成、部署关系、时间窗与解法均是供人试玩的假设；不是可解性证明，也不是已接入声明。设计编号 `SO-01` 至 `SO-06` 不是已注册的运行时ID。

## 2. 模式定位与玩家契约

**定位：围绕鲜明的作战局势，让玩家运用情报、机动、火力、设施和时机，破解难题并学会迁移使用其中的作战思路。**

- 一级入口顺序为教学、挑战、特别行动、自定义；特别行动卡片直接列出，不按舰队规模分章。
- 各行动独立开放，固定舰队在关内试用，不要求挑战通关或角色持有，不新增长期数值养成。
- 卡片显示局势、核心矛盾、玩法标签、双方规模、难度描述、预计战斗时长、任务与设施收益。首次思考及重试时间不计入战斗时长；发布预计值须来自人类试玩。
- 难度初标「艰难／险局／极难」，均为作者预期。不得把AI低胜率写成难度依据，也不承诺按编号越来越难。
- 默认允许战术暂停、群体命令与手动开火。考验计划、判断与调整，不以取消暂停或提高操作频率制造门槛。
- 记录通关与不同打法；首版不绑定角色解锁，不设必须同局完成的全套精通。提示使用可单独记录，但不剥夺通关。
- 玩法简报与作者解法分开。本文的「候选破解」不直接出现在初始卡片；玩家主动请求提示后才逐级提供。

## 3. 历史作战思路的取用

历史提供「为什么这样组织行动」的依据，不提供游戏必胜答案。下表只提炼局部思路，不把某一次行动概括成某国永恒的性格或能力。

| 思路与历史依据 | 可转译的作战问题 | 游戏中的取舍与边界 |
|---|---|---|
| 日本萨沃岛夜战：夜战突然性与先雷后炮，[H1] | 如何在暴露前建立有效攻击位置 | 保持隐蔽与提前输出冲突；沿用现有开火暴露，不增加国籍夜战加成。 |
| 美国维拉湾：雷达辅助接敌、隐蔽雷击与后续交战，[H2] | 如何把情报变成攻击角度和脱离机会 | 先发现不等于自动获胜；不复刻史实舰数或伤亡。 |
| 英澳对意大利马塔潘角：航空、追踪与夜间接敌配合，[H3] | 如何把不同兵力的作用连接起来 | 可借鉴情报与火力衔接；岸站接管是游戏抽象，非该战役史实。 |
| 德国海峡突围：利用时机、掩护与恶劣天气完成转移，[H4] | 何时承担穿越危险海域的风险 | 天气帮助接近，也妨碍自身航行与攻击；不把风暴设计成鱼雷增益。 |
| 英德日德兰作战计划：诱出部分兵力、避免同时面对整个主力，[H5] | 如何集中局部优势，又识别对方诱敌 | 借鉴任务牵制与兵力分离，不引入未存在的「横切T字伤害加成」。 |
| 英国基座行动：付出交战代价，把关键补给送达马耳他，[H6] | 如何区分打赢交火与完成任务 | 护送与损失取舍适合独立目标；几秒维修不是历史事实。 |

历史尺度须压缩：舰队作战中的数小时乃至数日转为短局中的阶段；控制岸上设施解释为控制近岸水域、协助友方接管；维修与补给解释为抽象服务。不增加陆战、人员、燃料经济或真实后勤仿真。

## 4. 战术难题设计原则

### 4.1 每关先写一个必须破解的矛盾

先确定「照常集中推进为什么会吃亏」「玩家能改变哪一个条件」「改变它要放弃什么」，再选择天气、设施和舰队。每关一个核心矛盾、一个辅助条件；不能把全部机制叠上去作为高难度。

允许明显不对称的兵力、位置和任务压力。敌方较强必须可从编成、部署与公开任务推断，不能暗加命中、无敌、装填或观测权限。

### 4.2 规则明确，局势可以未知

出击前公开胜敗、时限、保护对象、已知设施效果、天气趋势及敌方任务概要；敌人实时位置、未发现雷道和装填状态仍按公共观察规则隐藏。若简报提供敌编成，那是静态情报，不等于持续追踪。

需要推理的信息应留下线索：固定巡逻的重复接触、护航者回撤、公开气象预报、岸炮有效炮线、敌方主动开火。不能靠第一次毫无线索的瞬杀告诉玩家唯一规则。

### 4.3 规则化的是任务承诺，不是僵死动作表

敌人可以被规定守一处、护一舰、追击到一条任务边界或按公开时间出动；接敌、射击、避碰和技能仍走公共规则。任务承诺造成可利用的弱点，而敌人仍能根据合法接触作局部反应。

专属行为必须声明：目标、触发所需信息、承诺范围、退出条件、失去目标后的搜索与返回。任务切换需有持续性，避免玩家用边界往返让敌人无限掉头。敌方不得读取玩家指令队列、未发现单位或未发现鱼雷来反制。

### 4.4 多解是设计目标，不是未经验证的结论

每关提出至少两个有不同代价的候选方向，供人尝试；不规定必须按作者顺序击沉或必须使用主题设施。某关最终只有一类可行思路时，应坦诚标为专门战术题，不能伪称自由解法。

合法的新解法原则上保留。玩家绕开设施、集中突击或牺牲护航舰获胜，不因为偏离预案就被补丁封堵。只有规则漏洞、不可执行的反制或用户明确认为破坏体验时才讨论修改。

### 4.5 难在决策，不难在等待与故障

一次失败可以消耗计划，但不应要求重复长时间无事航行。出生点要能迅速进入观察与部署，保留转向、制动和放弃行动的余地；不是把所有人贴脸出生。

窄路只用于少数明确的伏击主题，仍遵守共享水域和替代航路原则。无安全航迹、靠泊失效、命令丢失和未知规则拒绝归为技术问题，不能当成困难设计。

### 4.6 学会原理，而不是记住秒数

第一次破解鼓励复现观察到的规律。通关后可选择手工设计并公开的变体：交换设施侧、改变护航配置、改变天气开始阶段等，每次只改变一个关键条件。迁移问题是「还能否识别机会」，而不是重复同一时间轴。

默认重试保留关卡版本、初始态与种子，帮助比较计划；玩家可另选新种子。固定种子不保证不同命令产生相同随机序列，不把某一炮幸运命中作为解法条件。

### 4.7 人决定设计是否成立

AI不会破解不构成降难理由，AI偶然通过也不构成可玩性证据。没有真人通关时，状态只能是「待破解」，不能宣称必然可解。发布前至少有一条在正常玩家权限下由人完成、能解释关键因果的通关记录，并由用户决定是否接受难度；这不是人口胜率指标。

### 5.2 胜敗与边界

- SO-01至SO-05采用击沉敌旗舰为胜、己旗舰沉没为败，同Tick双方旗舰沉没沿用公共平局，时间耗尽沿用公共超时结算；不为促使设施使用另加失败条件。
- SO-06是新增护送任务，具体成功、保护失败、时限与同Tick优先级见第6.6节，不能以普通旗舰战静默代替。
- 主动退出记未完成；失败不扣长期资源。主题行为与打法记录不修改主胜败。
- 默认不开启主武器自动发射，副武器沿公共默认；SO-02开局明确展示隐蔽开火管理，玩家可自行开关。不得用关卡锁强迫先雷后炮。
- 设施占领不覆盖击沉规则；接管对象逐关显式列出，不继承母地图全部设施。雷达情报不允许炮弹穿岛，天气不消除已经成立的攻击事实。

## 6. 六个行动设计

### 6.1 SO-01「雾港夺台」

**玩家简报**：雨夜中敌方重炮封住内湾，通信站连接雷达。控制站点能提前掌握关键海域，但分兵会让正面主力处于劣势。目标：击沉敌旗舰，保护己旗舰。

**核心矛盾**：取得情报需要分兵；集中火力又容易在未知位置遭遇重炮。辅助条件为固定雨夜。历史思路参考H2/H3，岸站接管为游戏转译。

**战场布置**：采用新月湾式宽湾口实例，己方西南、敌主力东北；通信站在北侧近岸，交互水域足够转向；雷达覆盖内湾与北路，南侧外海保留可用绕行。岛岬遮挡炮线，不能让雷达与岸炮一起覆盖所有道路。首版只配置通信站与关联雷达，不带机场、岸炮和维修；雷达初始敌控激活，通信站夺取后显式转移雷达，双方可反占。

**敌方任务**：厌战与基洛夫维持内湾支援；鞍山负责已知站点争夺，宁海护卫接近区。鞍山根据合法占领状态或友方观测发现威胁后尝试反占；宁海受击可以迎击但不无限追到南外海。失去雷达后按己方残影搜索，不继续读取玩家真实位置。上述分工是待接入行为契约。

**候选破解**：①天狼星与一艘驱逐掩护夺台，另一组牵制，利用新接触择机合流；②放弃站点，经雷达覆盖外侧集中切入；③接近压制通信站，利用暂时失联窗口打击旗舰，不长期守点。各路线都承担时间、少打多或暴露成本，尚未验证。

**应学会**：侦查优势必须接上兵力部署；压制与占有是不同投入。不能把「夺台」设为必做任务。

**试玩重点**：雷达第一次改变了哪条指令？夺台后是否形成不可逆滚雪球？南路是否只是更长的必败路线？若失败是绕路/靠泊故障，先修执行，不削弱敌军。

### 6.2 SO-02「夜海剪刀」

**玩家简报**：敌方巡洋舰队沿岛链巡航，正面炮战不利。利用夜色部署雷击，决定何时暴露，以及发射后怎样脱离。目标沿公共旗舰战。

**核心矛盾**：近距离雷击更可靠，却使脆弱驱逐暴露；两翼交叉增加对方转向代价，也增加己方分散风险。辅助条件为晴朗夜间，避免把恶劣海况误当雷击奖励。参考H1/H2。

**战场布置**：采用散岛群式开阔中心，岛体只在侧面提供接近遮挡。己方在西南，敌方沿东侧南北巡逻，北南两端均可接近和退出；不以窄口强迫命中。己方初始处于可观察部署而未被迫炮战的位置；简报只给巡逻海域，不给实时坐标。

**敌方任务**：兴登堡与基洛夫维持主队，宁海近护、鞍山前出搜索；遇已发现威胁可转向与追击，离开护航范围后返回。未发现的鱼雷不提前闪避；主队不是固定轨道靶，受攻击后可改变航向并搜索。

**候选破解**：①两翼错时雷击，第一组迫使转向，第二组利用新航向，发射后立即脱离；②单翼集中雷击，保留一舰侦查与掩护撤退；③先打护航打开接近面，再重新建立接触攻击旗舰。交叉雷道必须考虑友舰安全及公共发射合法性，不能用穿越友舰的假设构造答案。

**应学会**：按观测到的转向调整后续攻击，把雷击威胁转成位置收益。可以先炮后雷，不能用硬顺序失败否定新打法。

**试玩重点**：玩家是否能主动控制暴露？错过首轮后还有没有调整空间？成功是否依赖某个幸运落点？对准固定秒数获胜只能作为一次过程记录，不能作为关卡成立依据。

### 6.3 SO-03「风暴窗口」

**玩家简报**：敌航母控制外海，气象预报给出风暴过境阶段。提前进攻可能遭受空袭，等待又会让敌方守队完成部署。目标沿公共旗舰战。

**核心矛盾**：抢攻换先手，等待换接近掩护；风暴也限制己方航空、航速和雷击可靠性。辅助条件为两条接近路线。参考H4的时机思想，不复刻突围任务。

**战场布置**：宽岛间海域，外路短但暴露，内路受岛岸遮挡但需转向；不配置其他设施。企业在东北有展开水域，敌护卫分布在两个接近方向；玩家西南出生，不应在无法观察和准备时直接遭到首轮致命攻击。布局按当前航空射程审核。

**天气候选**：复用0秒晴朗、60秒阴云、120秒雷雨、180秒雨、240秒晴朗的过境顺序，此后保持晴朗，不无限循环等同一窗口。出击简报公开全阶段，局内持续可查，临近切换提醒。阶段时间只是首轮假设，可以依据人的反馈整体调整。

**敌方任务**：航母持续保持与已知威胁的合理间距，护卫控制接近区；航空攻击使用公共天气合法性。晴朗恢复后按正常侦察与装填恢复压力，不给予额外预存齐射；风暴中仍允许护卫追踪与交战，不全队停机。

**候选破解**：①风暴前以航空和炮击削弱一翼，风暴中穿过缺口；②保存攻击，利用风暴转移到近距离侧翼，在后续条件改善时交战；③先击破护卫形成持续接触，不把首个风暴当唯一机会。百眼巨人提供可选择的窗口工具，禁飞期间仍需保护和机动。

**应学会**：气象阶段改变的是行动机会与准备成本；等待本身不产生胜利。

**试玩重点**：玩家是否真的为窗口调整位置？风暴是否只是长时间失去按钮？遗漏首个窗口能否继续作战？在途攻击与新发射的天气语义必须可见，不能制造「风暴会替我清空飞机」的误解。

### 6.4 SO-04「危港轮换」

**玩家简报**：旗舰厌战以45%最大耐久开局，敌方正在接近。中立维修泊位位于侧湾；需要决定由谁拖住敌人、是否维修，以及何时重新投入。目标沿公共旗舰战。

**核心矛盾**：主力离场能保存战力，却把交战压力交给护航舰。辅助条件为初始战损。H6启发保存关键力量的取舍；本关不是历史补给战复刻。

**战场布置**：采用宽湾口与侧湾，玩家西侧、敌方东侧；维修点置于西北侧湾，入口可被对手绕行威胁，岛岬阻挡直接炮击但不能完全隔绝压制。首版仅维修，不叠加补给、水雷与机场。双方可以占领使用；敌方也不得因站点在玩家附近而被禁止靠近。

**敌方任务**：俾斯麦与基洛夫维持正面压力，愤怒与宁海根据已知服务/接触尝试侧翼逼近；失去接触搜索入口，不全知追踪坞内目标。敌人有合理伤损时可以争取维修，不抢占己方满血单位无需的泊位。

**候选破解**：①护航掩护旗舰维修，再轮换承伤单位；②先让较快舰控制站点，主力维持交战，获得局部喘息后入泊；③完全放弃维修，以受损旗舰的现有火力配合雷击尽快决胜。不得用“必须维修一次”锁住第三种方向。

**应学会**：服务收益需扣除航行、转向、读条、离场火力与重返成本；保护主力不等于让她永远远离交战。

**试玩重点**：失败来自决策还是靠泊执行？完成维修后是否实际改变了下一轮选择？反复维修是否拖成消耗循环？若发生，先调整入口压力和路线关系；新增服务次数/库存属于另议规则，不能在本关暗设。

### 6.5 SO-05「双钩诱敌」

**玩家简报**：敌人以两翼巡逻队掩护中央主力。全队正面交战劣势明显；轻舰可能把你引向更强火力，也可能被你牵离支援。目标沿公共旗舰战。

**核心矛盾**：追击能获得局部战果，也会延长支援距离；诱敌同样会分散自己的兵力。辅助条件为两翼与中央的有限支援距离。参考H5。

**战场布置**：两座短岛分隔北、南观察面，中部保持宽通道；己方西侧，敌主力东侧中央。北翼基洛夫/鞍山，南翼宁海/愤怒，中央俾斯麦/兴登堡。两翼真实航行回援，不能瞬间加入同一炮战；也不能远到永远不能互援。

**敌方任务**：两翼在已知航段巡逻；发现可交战目标后在各自职责区内追击，离区或失联搜索一段有限范围后回撤。中央主力在己方观测确认威胁接近防区后支援，不因玩家点选旗舰而响应。任务边界由巡逻区/防区表达，精确退出阈值在配置冻结时写明，不能随玩家表现移动。

**候选破解**：①以一艘驱逐暴露牵住一翼，主队打另一翼并迅速合流；②不追退却巡逻队，绕其回援路线形成拦截；③先用侦查确认中央动向，再集中攻击尚未得到支援的主力侧面。敌人不必每次咬钩，玩家必须确认诱导是否实际发生。

**应学会**：局部优势来自敌我到达时间与任务承诺；识别假退却，及时结束自己的追击。

**试玩重点**：是否真有不同局部态势，还是六舰立即聚成一团？敌方是否被边界抖动玩坏？若人用合法快速集中直接破局，应保留并讨论其价值，不自动提高敌方追踪权限或取消弱点。

### 6.6 SO-06「最后一程」

**玩家简报**：光辉必须穿过封锁区抵达东侧撤离水域。其余四舰可掩护、牵制或清除拦截者；击沉敌旗舰不能代替护送成功。辅助条件为北侧隐蔽长路与南侧暴露短路。参考H6，天气突围思路参考H4但本关不再叠加动态天气。

**核心矛盾**：投入兵力消灭威胁会拖慢或暴露护送；追求全部击沉可能丢掉任务。光辉是既有战斗航母，不冒充没有定义的运输舰，不增设平民单位或货物系统。

**战场布置**：西侧出发、东侧撤离，中央有短岛提供遮挡；两条路在东侧前重新汇合，撤离区足够舰体完整进入。胜利在东北支援，兴登堡/鞍山巡逻短路，基洛夫/宁海巡逻长路；全部开局已存在。上方路线更长但不因名字「隐蔽」获得额外隐身。

**敌方任务**：拦截组保持通路任务；合法发现光辉后优先威胁她，未发现时处理当前接触、守路与搜索。被诱离后可按承诺范围返回，但不获知另一侧未发现目标。胜利沉没后其余守队仍继续任务，不能因普通旗舰终局提前结束。

**新增任务契约**：光辉存活，整个实际舰体进入公开撤离区并连续停留5秒即成功，不要求其他舰同行，也不要求停止航行；离区则该次停留计时清零。光辉沉没立即失败；600秒到期未完成失败，不使用普通超时比分。每Tick先结算公共战斗事实，再判光辉存活；同Tick沉没优先失败；仍存活且完成撤离则成功，包括完成时刻恰好等于时限；其后才判超时失败。敌旗舰沉没不触发胜利，护航舰损失不单独失败。

**候选破解**：①主队清短路，光辉保持安全间距后通过；②护航分队在短路建立合法接触牵制，光辉与近护走长路；③先压制航空支援再通过，但必须承担耗时。所有计划均需在终点前面对真实拦截，不通过脚本清场保证成功。

**应学会**：用任务而非击沉数量定义成功；决定何时结束交战、带关键单位离开。

**试玩重点**：玩家是否因追击而丢失护送机会？护航单位的牺牲是否出于选择？撤离区边界和5秒进度是否清楚？未实现完整撤离及旗舰例外结算前，不得换成击沉旗舰版本并宣称本关已接入。

## 7. 专属行为与新增能力边界

敌方无需具备通用解题能力；它需要可靠执行所承诺的战术，并对玩家合法可见行动作有限反应。高层任务编排与底层公共AI分开：前者决定守哪、追多远、何时回援；后者承担航行、交战、避险和合法技能。玩家全程保持正常控制，不以预制解题脚本代替。

| 设计需求 | 实施边界 |
|---|---|
| 六关固定编成、独立部署 | 使用正式角色配置，逐关生成与审核，不改公共角色值来补难度。 |
| 雷达转移、维修、天气 | 复用公共机制，配置行动独立布局与时间线；已有机制不等于行动组合已验证。 |
| 分区巡逻、有限追击、护卫、回援、服务压迫 | 新的关卡行为需求，先对齐16/24；不能只写角色说明就当作有专属AI。 |
| SO-06撤离、保护失败、敌旗舰死亡后继续 | 新增任务事实与终局优先级，进入10/23及目标Domain、t02；严禁仅更换HUD文字。 |
| 一级入口、试用、行动进度、不同打法记录 | 新增模式与进度契约，明确存档兼容；不把挑战关顺序精通或解锁链当作已支持。 |
| 简报、任务提示、来源反馈、分级提示 | UI只呈现真实状态与已授权情报；雷达/维修贡献不能由画面猜测。 |

所有原型需冻结初始位置与航向、各任务区域、交互点、时间事件、敌行为转换条件及采用的航空模式。本文的相对位置用于关卡制作，不是已审核坐标；最终坐标先证明规则合法，再交由人判断布局是否有趣。

## 8. 与用户共同迭代的方法

### 8.1 一次只解决一个设计问题

顺序建议SO-01 → SO-02 → SO-03 → SO-04 → SO-05 → SO-06，这是制作顺序，不是解锁顺序。先交付一关可操作原型和简报，由用户选择优先破解的主题；不一次制作六关后再索取笼统评价。

每轮流程：冻结版本与种子 → 用户不看作者解法尝试 → 记录判断和操作阻碍 → 共同解释原因 → 提出小范围修订 → 用户重试。用户主动想看提示时随时提供，不要求先失败固定次数。

反馈优先询问：原计划是什么、根据什么线索、在哪个时刻改变判断、动作有没有执行、哪里有新想法、哪里只剩等待或碰运气。允许文字、录像或现场描述，不强迫填写长表。

### 8.2 根据失败类别修改

| 观察 | 处理原则 |
|---|---|
| 路线、服务、命令或判定没有按规则执行 | 修复实现；原尝试标记技术受阻，不据此降低难度。 |
| 关键规则从未告知或视觉传达错误 | 补简报/反馈；不直接削弱敌人。 |
| 规则理解了，但玩家仍愿意尝试新计划 | 可以保留困难，继续共同探索，不以失败次数触发自动降难。 |
| 玩家认为只有等候、机械重复或赌命中 | 优先调整接敌/支援距离、窗口、敌任务与重试成本；是否改编成由反馈决定。 |
| 出现作者没想到的合法解法 | 记录其思路并保留；讨论能否迁移，不立即封堵。 |
| 多次尝试仍无法说明可行路径 | 保持「待破解」；可提供作者候选方向，但不能把纸面推演宣布为可解。 |

不设目标胜率，不根据通用AI输赢调整兵力或时间。修改可以涉及布局、任务条件、敌行为、编成及提示；公共角色数值/公式仍走其本身的设计流程。原则上每轮只动一个主要矛盾，必要的组合变更应明确列出，保留旧版本以便解释差异。

### 8.3 提示与迁移

提示分三层，默认关闭：①指出值得观察的现象；②指出需要权衡的关系；③给出一种候选计划与风险，不给逐Tick答案。例：SO-05先提示「注意巡逻队何时回撤」，再提示「追击距离会改变支援时间」，最后才提供分队牵制的安排。

通关后先请玩家描述成功原因，再提出一个公开的手工变体。能在变体中调整原理是学习的有力证据，但不强迫所有关卡都完成迁移才能记首通。没有人实际完成的变体仍标「待试玩」。

### 8.4 记录与采用

每轮最少保留：关卡/规则版本、种子、用户是否看过提示、计划与关键调整、结果、技术阻碍、用户评价、修改内容及原因。通关时间和损失只作事实，不转为自动评分或人口统计结论。

阶段使用「设计候选 → 可试玩原型 → 待破解/迭代中 → 用户认可」，技术就绪单独标注。用户认可基于正常权限下的实际体验；不因文档完整、程序通过或AI偶然获胜自动提升。平衡修改直接依据人的反馈，程序事实只帮助解释发生了什么。

## 9. 程序验证只守实现边界

允许检查：资源引用、出生合法性、实际航行和靠泊、观察权限、敌方任务触发与退出、天气边界、命令执行、暂停/重开、胜敗同Tick、任务时限、进度保存和性能。可以针对人的具体失败记录复现技术问题。

不运行用于调平本模式的AI胜率矩阵、20种子接受门禁、自动寻找最佳编成或解法搜索。脚本能完成一个功能流程，只证明该流程的代码执行，不证明玩家能发现它、任务可解或难度合适。人的攻略可用于定位实现回归，不能变成要求全部玩家照抄的正式解法。

发布检查分开记录：技术是否按规则工作；用户是否完成并理解至少一种打法；用户是否接受挑战与重试成本。缺任何一项都保留相应未完成标记。多解性只有在不同计划被人验证后才宣称成立。
