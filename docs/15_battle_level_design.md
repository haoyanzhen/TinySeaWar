# 教学、挑战与自定义战斗关卡设计

## 1. 文档功能与边界

本文是 Tiny Sea War 教学、挑战与自定义战斗的关卡意图真源，负责定义模式入口、进度、关卡地图配方、固定舰队、遭遇阶段、目标、取消条件、增援、奖励和目标胜率，即“每个关卡使用什么内容并要求玩家完成什么”。

特别行动由独立分册 [15-2_special_operations_design.md](15-2_special_operations_design.md)负责：以历史海军作战思路构造面向人的战术难题，依据用户试玩反馈迭代，不套用本文挑战关的目标胜率、AI代打调参与解锁链。本文负责模式总入口，其逐关设计不在此复制。

本文不重复定义核心战斗、角色数值、AI 算法、环境效果、Domain 字段、模拟样本方法或当前实施状态。对应真源为 `docs/10_game_core_mechanics.md`、`docs/14_character_balance_design.md`、`docs/16_enemy_ai_behavior_design.md`、`docs/18_facility_weather_effect_design.md`、`docs/35_scene_combat_domain_design.md`、`docs/37_environment_runtime_domain_design.md`、`docs/38_facility_combat_domain_design.md`、`docs/36_balance_testing_design.md` 和 `docs/00_project_status.md`。目标、增援与进度的安全技术表达见 `docs/technical/t02_level_objective_reinforcement_progress_solution.md`。

本文采用 20 套时间天气海面、10 类岛屿模板和局部环境区作为设计基线。设计项是否已进入数据、菜单、运行时和验收，只以 `docs/00_project_status.md` 为准，不在本文维护易过期的完成度副本。

一级入口设计为：`教学`、`挑战`、`特别行动`、`自定义`。`挑战`点开后分为 `小型海战`、`中型海战`、`大型海战`，分别对应第二至第四章。特别行动直接展示独立开放的行动卡片；入口与内容是否已接入只见 `00`。

- 第一章为 8 关教学章，依次教学选择与移动、主要武器、弹药与技能、战列压制巡洋、雷击驱逐伏击主力舰、侦查共享、编队控制和综合指挥。
- 第二至第四章各 5 关，基础规模分别为 `3v3`、`5v5`、`11v11`，固定双方舰队，不提供战前编成入口。
- 挑战关可以使用接替增援增加敌军总数，但同时在场敌舰不得超过章节规模；因此仍保持小型、中型、大型战斗的操作负荷。
- 增援属于关卡完整编成，全部预备单位 Cost 必须计入该方总 Cost；表格对增援关分别标出初始 Cost 与全部 Cost。
- 难度优先通过阵容克制、总 Cost、出生队形、接替增援、任务条件和 AI 协同调整，不修改角色 HP、伤害、装填、射程、侦查或命中属性。

本稿中的目标胜率是后续调参指标，不是已经得到的模拟结果。未通过固定种子批量模拟和人工验证前，不得在项目状态中标记为完成。

## 2. 模式入口与进度

| 一级入口 | 二级入口 | 内容 | 编成规则 |
|---|---|---|---|
| 教学 | 8 个训练关 | 基础概念与操作 | 双方舰队固定，教学舰可临时试用。 |
| 挑战 | 小型海战 | 第二章，5 个 3v3 关卡 | 双方舰队固定，最多 3 艘同时在场。 |
| 挑战 | 中型海战 | 第三章，5 个 5v5 关卡 | 双方舰队固定，最多 5 艘同时在场。 |
| 挑战 | 大型海战 | 第四章，5 个 11v11 关卡 | 双方舰队固定，最多 11 艘同时在场。 |
| 特别行动 | 独立行动卡片 | 规则化战术难题，设计见15-2 | 固定编成、关内试用，独立开放，依据用户试玩迭代。 |
| 自定义 | 1v1、3v3、5v5、11v11 | 自选地图、舰船、旗舰和敌军 | 只能选择已解锁舰船，遵守单位数与 Cost 上限。 |

进度规则：

- `T-01` 至 `T-08` 默认全部开放，玩家可以按推荐顺序学习，也可以直接选择需要复习的概念。教学完成状态不作为挑战入口前置。
- 小型、中型和大型海战三个挑战分类默认分别开放 `S-01`、`M-01`、`L-01`；每个分类内部成功完成一关后开放同分类下一关，互不要求先完成较小规模章节。
- 失败不扣除资源。首次通关奖励只发放一次，重玩用于练习、计时和后续星级扩展。
- 教学关中的舰船均可作为关卡内试用；完成指定教学关会解锁对应的教学奖励舰，未作为奖励的试用舰不会提前进入自定义战斗选择列表。
- 长期存档不保存局内战斗，也不保存教学关完成状态；只保存挑战关成功状态和已解锁舰船 ID。教学舰船奖励通过“已解锁舰船集合”幂等写入，因此重玩不会重复发放。

## 3. 地图与部署契约

### 3.1 地图组合结构

关卡地图不再引用晴昼、阴云、黄昏三档旧别名。每张正式地图由以下五部分组成：

```text
地图尺寸
+ 20 套正式 ocean_palette 之一
+ 开阔海面或 10 类 terrain_template 之一
+ 可选 environment_zone_set
+ 可选 facility_layout
+ 经过导航与吃水校验的出生/增援方案
```

- `ocean_palette` 同时决定海面表现和全局时间天气战斗 Profile，不允许只换画面而继续使用旧规则。
- 岛岸会真实阻挡水面舰船、鱼雷、炮弹和水面光学视线；浅水、礁滩与航道继续按舰种吃水标签结算。
- 局部海雾、飑线、高海况、背风水域、月光水域、强流和潮汐在全局时间天气结果上叠加，双方与 AI 读取同一公开环境。
- 未在关卡表中写明的设施默认关闭，避免地形关卡自动继承港湾岸炮、机场或补给收益。

十类岛屿模板都必须配置独立 `terrain.map.*`、审核出生点、三档共享导航图、3v3 等 Cost 验证入口和小地图遮罩。`terrain.map.harbor_mouth` 指定为包含局部环境、设施与水雷的完整近岸战术验证模板；其余九图用于分别验证硬地形、浅水/航道、视线与投射物阻挡、导航、AI 接敌和表现，不自动继承港湾设施或局部环境。

`level.prototype_harbor_3v3` 是 AI、出生侧和设施的等 Cost 验证入口，配置 `require_equal_fleet_cost = true`。基线编成为双方各 `12 Cost`：玩家为岛风、雪风、阿芙乐尔，敌方为基洛夫、鞍山、宁海；加载校验必须拒绝预算不相等的验证编成。港湾设施布局在第 30 秒启动雷达；占领通信站触发本地图专属的岸炮/机场/雷达系统接管，敌方重新占领同样生效。该规则随自定义选择港湾继承，不扩散到显式关闭设施的正式挑战。

### 3.2 二十套正式海面

正式天气 × 时段 ID、数值和组合体验只在 `docs/18_facility_weather_effect_design.md` 定义。本文只负责把这些 ID 分配给具体关卡；教学与挑战合计至少使用一次全部 20 套正式组合，旧兼容别名不得进入新关卡数据。

### 3.3 十类岛屿模板

新版 `6144 × 3456` 十图采用 **8 张普通地图＋2 张窄路特色地图**。普通地图的海岸主要负责攻击遮挡和战场分割；大小舰共享绝大部分海域，岛间、内湾与外海保持宽连接。只有港湾入口、双岛长海峡通过少数较短入口制造快速切入的伏击风险，同时保留较慢的外绕和撤退路线。此分配只针对 `_16x9` 新版及其 M/L 派生实例，旧版教学、小型挑战不随之重绘。

| 新版模板（ID 后缀 `_16x9`） | 岛体构成 | 战术用途与修改要求 |
|---|---|---|
| `scattered_islands` 散岛群 | 四角四岛 | 删除全部中央、边缘碎岛；四处台地缩成贴岸带，中央与四侧开水连通。 |
| `broken_atoll` 破碎环礁 | 三块分离主岛 | 删除堵口碎礁和内湖浅水；岛间宽通，保留断续遮挡。 |
| `ring_lagoon` 环岛泻湖 | 三段主岛弧 | 三处宽开口、中央深水；取消六窄入口与浅水核心要求。 |
| `crescent_bay` 新月湾 | 一座缩短、张开的弧岛 | 宽湾口、深水内湾和外侧回旋空间。 |
| `offset_large_island` 偏置大岛 | 一座偏置主岛 | 缩小岛体、减少突出岸角；取消东侧三片大浅水，东侧连续展开。 |
| `central_sandbar` 中央沙洲 | 一座缩短长岛 | 删除卫星岛，首尾和两侧均留出宽阔机动空间。 |
| `long_archipelago` 长岛链 | 三座错位短长岛 | 删除栅栏式连续排列；平行航路之间可大范围横向、斜向转移。 |
| `dual_channel_reef_line` 双航道礁线 | 两座错位斜长岛 | 两个明显推进方向之间保留宽横向转换，不成为第三张限路图。 |
| `harbor_mouth` 港口入口（特色） | 两座主岬角 | 入口局部狭窄，港内深水且可展开；外侧可绕行、撤退。 |
| `double_island_long_channel` 双岛长水道（特色） | 两座主岛 | 中央较短海峡承担伏击风险，首尾扩大，外侧绕行较慢但通畅。 |

验收必须区分局部可占位、从双方部署区/外海连续可达、入口是否共享同一瓶颈，以及实际转向/编队能否完成。封闭内湖不能计入外海可达面积；仅一条路线的两条相邻采样线不能计作两个入口。普通图不要求穿越陆地或任意两点直线可达，但不允许靠大片浅水、碎岛栅栏把大舰固定到少数路线。面积与路径阈值用于发现问题，不能替代逐图拓扑及实航核对。

### 3.4 局部环境使用原则

| 环境 | 关卡用途 |
|---|---|
| 海雾 `SeaFog` | 制造局部短接触窗口，强化侦查共享和伏击。 |
| 飑线 `RainSquall` | 作为有公开移动趋势的临时低能见度、高风速区域。 |
| 高海况 `HighSea` | 压低外海机动、命中与航空效率，推动路线选择。 |
| 背风水域 `LeeWater` | 在恶劣天气下提供可争夺的稳定航路。 |
| 月光水域 `MoonlitLane` | 为夜间提供局部观察优势，但不穿透岛岸。 |
| 强流 `StrongCurrent` | 改变舰船、鱼雷和路线成本，形成顺逆流差异。 |
| 潮汐水域 `TidalWater` | 控制浅水区域的阶段性进入窗口。 |

教学前四关不叠加复杂局部环境；之后每次最多新增一种环境概念。挑战关允许组合两至三类局部环境，但必须提供边界、标识和移动趋势。

### 3.6 出生与增援方案

坐标使用地图宽高归一化比例，实际烘焙时转为世界坐标。关卡舰队名单从左到右依次占用 `P1...Pn` 或 `E1...En`；`★` 为旗舰。所有点必须落在合法深水或对应吃水可通行区域，并与岛岸保持舰体半径和导航安全余量。

| 方案 | 玩家槽位 | 敌军槽位 |
|---|---|---|
| `SP-OPEN-1` | P1 `(0.36W,0.50H)` | E1 `(0.64W,0.50H)` |
| `SP-OPEN-2` | P1/P2 `(0.28W,0.42/0.58H)` | E1/E2 `(0.72W,0.42/0.58H)` |
| `SP-WE-3` | P1 `(0.22W,0.50H)`；P2/P3 `(0.18W,0.34/0.66H)` | 以地图中线左右镜像 |
| `SP-WE-5` | P1 `(0.20W,0.50H)`；P2/P3 `(0.17W,0.34/0.66H)`；P4/P5 `(0.22W,0.20/0.80H)` | 以地图中线左右镜像 |

| `SP-SN-3` | P1 `(0.50W,0.78H)`；P2/P3 `(0.42/0.58W,0.84H)` | 以地图中线上下镜像 |

左右接敌方案默认玩家朝东、敌军朝西；上下接敌方案默认玩家朝北、敌军朝南。若归一化候选点落入模板硬地形、非法浅水或环境禁入阶段，地图制作必须在同一出生区内移动并回写最终坐标，不能在运行时随机寻找落点。

关卡舰队成员可通过可选的 `weapon_group_states`，按该舰实际挂载的 `weapon_group_id` 将本场战斗初始状态声明为 `Enabled` 或 `Disabled`；省略的武器组默认启用，且该局部状态不得写回舰船或武器 Definition。

接替增援使用敌方出生边界的 `RN`、`RS` 两个安全点：左右接敌地图位于东侧北/南入口，上下接敌地图位于北侧西/东入口。增援点与时间必须通过整段导航和吃水校验；增援只有在达到表内时间且敌方在场数量低于章节上限时才进入。

关卡目标白名单、23 关稳定 `objective_set_id`、教学阶段控制、接替增援调度和进度存档的完整契约见 `docs/technical/t02_level_objective_reinforcement_progress_solution.md`。本文的通关表仍是关卡意图真源；技术契约只规定安全表达和持久化方式。

### 3.7 中大型挑战的地图制作约束

M/L 十关统一从对应 `terrain.map.<模板名>_16x9` 的 `6144 × 3456` 正式岸线派生关卡实例，保留 `2.6 × 3.2` 作者变换；中型旧稿的 `5120 × 2880` 不再使用。规模差异由舰数、部署与职责表达，不通过缩小同一岸线制造窄水道。不得改变共用自定义地图的出生槽、环境或设施；挑战实例单独保存覆盖项及其导航、碰撞场引用。具体对象字段见 `22`，制作流程见 `47`。

`SP-*` 比例点是设计候选，不是已经审核的坐标。制作时必须提交每舰最终位置、航向、吃水档、首段航路和 RN/RS 接入路线；整条路线需在规则几何上连通。下面的“中央、左翼、后卫”均指相对己方接敌方向的职责，不要求越过非法水域保持阵形。M/L 全部设施、机场任务、静态/动态水雷默认关闭；M-01 也只使用港湾地形与两类环境，不继承港湾验证关的设施布局。

## 4. AI 与胜率验收口径

### 4.1 AI 等级

AI 等级沿用简单、标准、困难三档。等级只改变决策间隔、评分项、技能阈值和协同程度，不提供额外视野或属性加成，也不改变共享导航候选、预测窗和预算。

- `简单`：用于教学和低压入门。
- `标准`：用于常规挑战，具备目标选择、基础集火和重武器预留。
- `困难`：用于后段挑战，具备更完整的交叉攻击、技能错峰和目标预留。

表内 AI 等级同时应用于双方。真实游玩时玩家直接控制己方；批量平衡测试时双方均使用 `LatestRuntimeAI` 且使用同一等级，避免用“玩家侧更聪明”伪造目标胜率。该实验策略必须在首个 Tick 前显式授予双方完整 AI，并覆盖之后实际入场的接替增援；这项模拟授权不改变真实游玩中的玩家受限辅助。敌我可以采用不同合法战术方案，但观察权限和决策质量必须相同。

### 4.2 胜率与时长

- 教学关目标胜率为 `100%`，挑战五关目标胜率依次为 `60%`、`45%`、`30%`、`20%`、`10%`。
- 教学关完成时间的第 10 百分位必须 `>=10s`，防止目标在玩家理解提示前被击沉；不得用无敌、锁血或伤害倍率实现这一要求。
- 挑战关目标容差为 `±5` 个百分点，10% 目标关为 `±3` 个百分点。
- 若结果偏离目标，依次调整任务条件、出生距离与队形、接替增援时间、敌方总数与阵容 Cost，最后才调整双方同档 AI 等级。不得直接修改角色基础数值。

样本量、固定种子、教学确定性策略、侧别限制、报告产物和人工指定规则只由 `docs/36_balance_testing_design.md` 定义。

### 4.3 挑战任务结算

挑战关以表内任务为唯一胜利条件；任务全部完成时立即判定玩家胜利并结束战斗，不再要求继续清场。任务采用增量状态，HUD 持续显示已完成步骤、当前步骤和仍有效的保护条件。敌旗舰沉没只有在任务明确要求时才构成胜利事实，不作为所有挑战关的通用提前胜利条件。

挑战任务一般不设置倒计时。失败主要来自任务被取消，例如己方旗舰或指定保护目标沉没、要求存活的单位沉没，或其他已明确不可恢复的条件。普通挑战的击沉顺序改为可选精通，未达成不影响通关、舰船奖励和章节开放；相同 Tick 完成多个顺序目标视为同时满足，不人为判定先后。真正需要严格顺序取消的特殊任务必须单独标注，并另行提供停火与在途攻击风险反馈。只有关卡名称、说明和 HUD 明确强调限时时，才配置任务时限；时限结束且任务未完成时立即失败。运行时仍可保留防止无限对局的技术保护上限，但达到保护上限记为无效/待调参样本，不伪装成任务限时失败。

### 5.0 玩家学习顺序与训练情境

- T-01 按选择、镜头跟随、布置航点的证据顺序推进；到达与输入分别验证，不能仅凭点击次数代替航行。

三关的普通 `time_limit` 都只是技术保护上限，触发时样本无效，不按剩余 HP 选出胜者。正式确定性策略只能按上述顺序提交玩家可执行的合法命令；T-04 策略在真实首次接触后通过公共瞄准合法性检查手动发射主炮，随后继续公共战斗。

教学阶段在 `engagement_unlocked=false` 时同时锁住玩家阵营的自动武器实际开火，避免首次接触同一 Tick 被自动攻击事实抢先；HUD 仍可展示本关将教学的自动能力与开关状态。首次接触或必做事实完成后再按表内能力恢复。

教学验收时必须记录每个必要动作是否发生。只靠自动交火获胜但没有完成教学动作时，关卡不结算为通关。

### 7.1 M-01 港湾扩编：分兵还是集中

- **开局部署**：胡德居中，圣地亚哥与重庆在原胡德候选点前方 256、左右各 256 单位提供支援，雪风前出侦查，海狮沿外侧深水迂回；实际出生仍在南侧安全区，不让海狮出生在潮汐捷径内。敌方厌战由北侧主航路推进，纽伦堡/逸仙屏护，愤怒/沃德争取侧面接触。
- **交战过程**：先用雪风确认主航路接触，再决定由胡德带巡洋舰集中压制，还是让雪风利用涨潮窗口短切、与海狮形成另一雷击方向。潮态改变后，已进入的单位可以撤出，不因关潮被判沉没或直接取消任务。
- **取舍与反制**：集中火力更容易保护胡德，但让厌战维持有利炮线；分路可能迫使敌主力转向，却会使前卫短暂离开支援。潮汐捷径不适合当前吃水时直接走外侧主路，通关不要求使用捷径。
- **任务反馈**：简报/HUD 为“击沉厌战；胡德须存活”。只在地图显示公开潮态和可进入边界；不把设施占领或潮汐等待加入任务。首次成功解锁基洛夫并开放 M-02。
- **本关验收重点**：五舰均可参与交战；每种潮态均有合法接敌路径；集中与分路均存在可执行的取胜机会，不能以潮区卡住作为难度来源。

### 7.2 M-02 泻湖护航：护航资源如何分配

- **开局部署**：保持北南接敌；双方航母占后侧外翼 P4/E5，并配置向本方外环深水移动的首段合法航向。我方基洛夫在原厌战候选点前方 256、侧方 256 单位支援，圣地亚哥以原凤翔候选点采用相同偏移护航。敌方纽伦堡和百眼巨人形成后层，俾斯麦带愤怒/沃德形成前层；护航关系会随合法接触与威胁重新评估。
- **交战过程**：厌战/基洛夫争取主入口炮线，鞍山侦查另一入口；圣地亚哥靠近凤翔时可稳定后卫，但前方缺少一份近距支援。中央雾区只缩短合法观察，不让任何舰穿过浅水或隔岸攻击。
- **取舍与反制**：可直接集中攻击俾斯麦尽快结束，也可沿外环打击百眼巨人以减少支援压力并争取精通。追航母会拉长护航距离，凤翔必须随战线调整位置，不能靠停在地图角落无限拖延。
- **任务反馈**：“击沉俾斯麦；厌战、凤翔须存活”；可选行单独写“先击沉百眼巨人，再击沉俾斯麦，不影响通关奖励”。提前击沉俾斯麦立即胜利；保护舰同 Tick 沉没则取消。解锁欧根亲王并开放 M-03。
- **本关验收重点**：凤翔能在合法航空窗口参与，且能够使用中央深水与三处宽开口撤离；敌方护航必须依据可见威胁调整，不能预知玩家绕行。

### 7.3 M-03 群岛雷击：先拆侧翼还是突击主力

- **开局部署**：我方中央为胡德与重庆，上翼为圣地亚哥/雪风，下翼为海狮。敌方愤怒、鞍山由 E4/E5 分入上下外航道；凤翔位于后卫，衣阿华与兴登堡通过中央深水接敌。
- **交战过程**：雪风先探明一翼，利用月光区维持共享接触；胡德和巡洋舰争取局部优势，海狮选择另一侧合法雷击位。敌轻舰暴露后，可先消灭侧翼，也可趁其离开主力时突击衣阿华。
- **取舍与反制**：顺流推进更快，但掉头与鱼雷横流修正更难；留一艘巡洋舰掩护海狮撤离，会减弱正面炮线。两翼目标仅为精通，不强制玩家在夜间逐艘追杀。
- **任务反馈**：“击沉衣阿华；胡德须存活”；精通为“愤怒、鞍山均先于衣阿华沉没”，两驱逐内部无顺序。同 Tick 三舰沉没可以完成精通。解锁厌战并开放 M-04。
- **本关验收重点**：两翼可独立接敌并接回主队，海狮有正常上浮攻击与补氧撤离空间；残影消失后不能再次出现反复横跨中线的搜索循环。

### 7.4 M-04 风暴猎场：有限损失下集中突破

- **开局部署**：厌战与圣地亚哥居中，基洛夫提供侧面炮火，岛风占前翼，百眼巨人由 P5 转向后侧深水。敌岛风与 U-47 从不同通行航路接近，俾斯麦在原候选点后移 256；兴登堡以原俾斯麦候选点为基准，前方 256、侧方 256 单位支援；敌岛风以相同基准前方 512、另一侧 384 单位前出，百眼巨人留后。
- **交战过程**：先争取一片背风水域，让主力在较稳定海况下集中处理一侧威胁；岛风可侧击俾斯麦或牵制敌雷击单位。`60s` 后若有空位，沃德从北入口补充侦查与近距压力；它不是必杀目标。
- **取舍与反制**：快速绕岛抢攻可减少长期消耗，但多线暴露容易耗尽两舰损失余量；保守守岛需承担鱼雷封路并逐步转移。背风不恢复雷雨造成的航空限制，双方航母可利用的航空窗口完全遵守公共规则，不能预设持续空袭。
- **任务反馈**：“击沉俾斯麦；厌战须存活；最多损失 2 艘”，显示当前损失 `n/2`。损失第二舰仍可继续；第三舰或厌战沉没立即取消。只授予精锐章展示和 M-05 开放，无新增舰船奖励。
- **本关验收重点**：第三舰与目标同 Tick 沉没仍失败；沃德等待空位不堵塞终局；无航空输出时必须区分天气合法限制与 AI/导航故障，不能据零输出随意补伤害。

### 7.5 M-05 海峡封锁：突破后如何收束

- **开局部署**：胡德/重庆构成南口主队，圣地亚哥/雪风沿一侧展开，海狮走另一条合法深水边线。北口衣阿华与兴登堡压制主航道，圣地亚哥/岛风掩护，U-47 争取侧向雷击位。
- **交战过程**：先选择穿飑线缩短暴露，或在背风区保持可靠接触；击破护航后，决定立即消灭衣阿华，还是先积累击沉数。胜利最早 `120s` 从北侧东入口 RS 接替，不要求等待她入场才能获胜。
- **取舍与反制**：先击沉旗舰会削弱敌主力，但若累计不足四舰，战斗继续；先清护航更便于一次收束，却让衣阿华持续开火。潜艇不能被要求在转换深度期间发射鱼雷。
- **任务反馈**：两个并列必做步骤为“击沉衣阿华”“累计击沉敌舰 `n/4`”，衣阿华计入四舰，初始敌舰与实际入场胜利同样计数；唯一保护条件是胡德存活。胜利未入场不计损失，也不额外延迟结算。
- **本关验收重点**：可由初始五舰中的任意四舰（包含衣阿华）完成，或由增援补足计数；目标顺序不影响通关。首通解锁岛风、兴登堡、俾斯麦、胜利并记录中型海战完成，不要求随后进入大型章。

### 8.1 L-01 舰队展开：用三个方向指挥十一舰

- **部署分工**：建议主力为胡德/厌战/兴登堡，前卫为雪风/岛风/天狼星，后卫为百眼巨人/圣地亚哥/重庆，欧根亲王与 U-47 组成侧翼。它们是可多选的职责建议，不要求新增一键编组、自动护航或跨组同步开火功能。
- **槽位基线**：P1 `(0.18W,0.50H)`；P2/P3 `(0.18W,0.38/0.62H)`；P4/P5 `(0.15W,0.26/0.74H)`；P6/P7 `(0.21W,0.30/0.70H)`；P8/P9 `(0.24W,0.42/0.58H)`；P10/P11 `(0.12W,0.36/0.64H)`。敌方左右镜像；名单逐项入槽。L-01 敌衣阿华、基洛夫覆盖为原厌战候选点前方 256、左右各 256 单位支援。此表细化 SP-WE-11 的候选点，L-02 至 L-05 复用，最终点须满足 3.7 的制作门禁。
- **交战过程**：前卫绕沙洲两翼建立接触，主力选择一侧展开；敌厌战/衣阿华形成炮线，轻舰先接触，凤翔/海狮补充远端与侧面压力。随后可集中一翼制造局部优势，或用两翼观察避免主力被绕后。
- **取舍与反制**：集中一侧减少镜头切换，但另一侧会丢失持续观察；全队同时走两侧会削弱旗舰周围屏护。中央沙洲必须保留可掉头的主力航路，不要求十一舰在同一窄口列队。
- **任务反馈与验收**：“击沉厌战；胡德须存活”。首次通关记录铜章、开放 L-02；检验多选指令、战术暂停计划、画外接触与鱼雷提醒的可读性，以及两条路线的交通，不以玩家逐舰持续微操作为通过条件。

### 8.2 L-02 岛侧航空走廊：保护航母还是加速斩首

- **明确敌槽**：E1 圣地亚哥、E2 天狼星、E3 基洛夫、E4 欧根亲王、E5 雪风、E6 鞍山、E7 企业★、E8 沃德、E9 胜利、E10 海狮、E11 百眼巨人。三航母初始朝己方后侧开水转移，后续依据合法观察选择攻击窗口；E7/E9 属于侧翼部署，不声称它们天然是安全后排。
- **交战过程**：我方百眼巨人与圣地亚哥/重庆构成后卫，其余主力可沿开阔侧快速推进或沿岛后减少接触。敌方三航母制造持续支援压力，巡洋与驱逐屏护接近路线；没有共享观察的航母不得凭空攻击隐藏目标。
- **取舍与反制**：直接攻击企业可以立即终结战斗；先处理胜利与敌百眼巨人可减轻支援并争取精通，但让旗舰承受更长消耗。把天狼星留给己方百眼巨人会提高护航密度，同时减少前线侦查和近距火力。
- **任务反馈**：“击沉企业；胡德、己方百眼巨人须存活”；精通单列“胜利和敌方百眼巨人均先于企业沉没”。敌我同名舰必须带阵营标识，不能把击沉敌百眼巨人误读成保护条件失败。首通记录银章、开放 L-03。
- **本关验收重点**：两条路线都有合法共享接触；三航母不能造成无法理解的画外瞬时伤害。默认航空规则与显式 Physical 模式不得混算胜率；全圈实体防空等 B 模式能力不作为默认关卡成立前提。

### 8.3 L-03 双航道巨炮：诱导重舰转向

- **明确敌槽**：E1 大和★、E2 俾斯麦、E3 衣阿华、E4 兴登堡、E5 欧根亲王、E6 雪风、E7 愤怒、E8 沃德、E9 海狮、E10 圣地亚哥、E11 天狼星。轻舰分走双航道，三战列保持能互相支援的深水炮线，不被脚本锁死在岸后。
- **交战过程**：我方胡德/厌战/兴登堡牵制一条通道，雪风/岛风/天狼星观察另一条；潜艇选择有撤离空间的雷击位，后卫保持航道外缘。玩家可以先拆除敌雪风与海狮，也可利用三战列调整炮线的机会突击大和。
- **取舍与反制**：穿越外侧高海况会降低攻击稳定性，却能避开正面集火；集中背风航道更稳定，也更容易受到鱼雷封路。敌方能以合法观察重分配护航，不能强制暴露未发现潜艇来保证任务推进。
- **任务反馈**：“击沉大和；胡德须存活”；精通为“雪风、海狮均先于大和沉没”，两者内部无顺序。首通解锁衣阿华、记录金章并开放 L-04。
- **本关验收重点**：大和和双方重舰在各自路线均可转向、交战和回撤；即使海狮长时间隐蔽，玩家仍能直接击沉大和通关，不能被可选精通拖成强制反潜搜索。

### 8.4 L-04 风暴群岛合围：保住后卫并打穿一翼

- **部署分工**：我方胡德/厌战/兴登堡为主力，百眼巨人/圣地亚哥/天狼星为受保护后卫，欧根亲王/重庆为机动支援，雪风/岛风/U-47 侦查和侧击。敌 E6 圣地亚哥、E8 雪风走上外航道，E7 重庆、E9 岛风走下外航道；衣阿华/俾斯麦/胡德/兴登堡/欧根亲王为中央压力，U-47/企业在后侧接入。
- **交战过程**：两翼接触形成后，玩家选择集中一翼击破，或保持两侧屏护等待飑线移开。`210s` 后愤怒从北入口接替，给已经薄弱的一翼带来新增侦查与雷击压力，不能瞬移到玩家背后。
- **取舍与反制**：派巡洋舰追击可以扩大突破，但可能让敌驱逐绕到己方百眼巨人；护卫全留后方又会让旗舰独自承受高 Cost 主力。雷雨期间企业与百眼巨人的航空必须服从 Severe 条件，敌方“航空错峰”只在合法窗口存在时成立。
- **任务反馈**：“击沉衣阿华；胡德、百眼巨人须存活”，分别显示两艘保护舰状态；不要求清理所有包抄舰。首通解锁企业、记录精锐章并开放 L-05。
- **本关验收重点**：击破一翼能实际换来接近敌旗舰的路线，后卫能跟随战线迁移；检查画外侧翼威胁提示和十一舰交通。长期零航空贡献须单独解释，不把高 Cost 或低目标胜率当作机制有效的证据。

### 8.5 L-05 雷夜环礁终局：分配火力并完成收束

- **部署分工**：衣阿华/俾斯麦/大和/胡德为主力，企业/胜利/圣地亚哥为后卫，兴登堡/重庆为支援，岛风/U-47 为前卫与雷击侧翼；按表内名单占槽。敌大和/俾斯麦/衣阿华构成重炮核心，其余舰按护航和侧击职责围绕深水入口展开。
- **交战过程**：先由前卫建立东口/月光水域接触，重舰沿审核深水路线展开；可从外环逐步削弱护航，也可穿越入口强流压迫大和。敌胡德和海狮最早分别在 `180s/300s` 入场，必须各有空位；满员时保持等待。
- **取舍与反制**：提前击沉大和削弱主力，却可能留下大量分散目标；先累积击沉再集中旗舰更便于收束，但暴露时间更长。两航母是受恶劣天气约束的支援资源，不承诺雷雨夜持续起飞，仅利用出击前公开的雷雨过境时间表。
- **任务反馈**：并列显示“击沉大和”和“累计击沉敌舰 `n/8`”，大和计入八舰。保护条件只有衣阿华存活；企业或胜利沉没不会单独取消。敌初始十一舰已足以满足任务，无须等待两个增援；未入场预备舰不计损失。
- **本关验收重点**：先沉旗舰、先满八舰、同 Tick 同时完成均正确结算；两波可在不同空位依次入场，不能变为 13v11。首通只解锁大和并记录大型海战完成。最终难度来自火力分配和旗舰保护，不能来自不可接近目标、潜艇停滞或无限追逐。

### 8.6 十关共用的结算与简报约定

- M/L 全部要求己方旗舰存活。同 Tick 同时满足完成与取消事实时，先按保护条件取消；它们使用任务结算，不套用普通战斗的双方旗舰同沉平局。M-04 的两舰损失额度不允许牺牲旗舰。
- 击沉数量只统计唯一敌方实体的真实沉没，含已入场增援，含敌旗舰；不统计预备、撤销波次或重复事件。M-05/L-05 在旗舰已沉但数量不足时继续，敌方剩余单位继续合法交战，不能提前停止 AI。
- 可选精通不要求停火/锁血，不影响主目标、奖励、下一关和章节完成。两成员前置组内无顺序；同 Tick 满足前置组与最终目标视为完成。未满足精通的胜利仍完整发奖。
- 接替的最早时间、入口和空位条件在简报与 HUD 公开；已发现单位的观察规则保持不变，不能因公开波次而显示未发现单位实时位置。无需特定前舰沉没，只需本方空位；结束时取消全部 Pending 波。
- 所有章节首关独立开放，章内逐关推进。铜/银/金/精锐章是该关完成事实的展示名称，不新增货币、物品或存档字段；章节完成由本章五关完成事实派生。
- 无任务倒计时；后续运行配置使用 `1200s` 技术保护上限，触及上限为技术无效，不发奖。大图航行耗时应通过合法部署调参处理，不能把技术超时作为难度手段。
- 表内“护航、双翼、完整协同”等是待验证的战术意图，不是已经存在的可配置 AI Profile。必须先以现有合法 AI、阵容和部署证明，确需新方案时按 `16/24` 补实现；不得以强制瞬移、全知索敌或临时属性改动替代。

自定义自动敌军按2026-10-02用户要求使用预先设计的完整阵容池：先由玩家实际编成Cost与所选难度计算敌方Cost闭区间，再从相同舰数、区间内且地图出生合法的完整阵容中等概率抽取一套，不按玩家具体角色暗中选择克制队。首版112个候选、区间参数、旗舰/模块搭配、预览、重抽与重开语义见[15-1自定义阵容设计](15-1_custom_battle_roster_design.md)。同规模双方上限一致，满预算困难档也不允许超上限；空候选集拒绝出击，不回退旧固定敌军。手动分别设置双方舰队保留为后续独立模式。

玩家先选战斗规模，再选已完成该规模出生、导航和性能验收的地图实例；海面组合与局部环境预设作为地图选项，不允许任意叠加产生未经校验的极端效果。阵容设计优先补足侦查、主力输出和基本反航空/反潜能力，低预算队允许公开弱点；自定义战斗不发放挑战进度和舰船解锁。阵容池、难度匹配与敌军预览已接入，当前验证与真人/平衡待验收状态见00。

十张近岸 `TerrainMap` 均固定保存双方 `1..11` 编号槽。1v1、3v3、5v5、11v11 分别取每侧前 `1/3/5/11` 个槽；所有槽按大型深吃水舰半径 `46`、同阵营分离距离、地图边界、硬地形和共享导航验证。该契约只表示出生和导航入口合法，不代表所有 11v11 地图已完成节奏、平衡或绝对性能验收。

## 10. 关卡内容验收

本节的目标胜率与正式平衡要求适用于本文教学和常规挑战；特别行动的设计验收采用15-2的人类破解与反馈流程，仍保留公共实现正确性检查。

### 10.1 静态检查

- 23 个关卡均包含编号、地图、双方舰队、AI 等级、出生或增援、通关标准、目标胜率和完成奖励。
- 第二至第四章各 5 关；初始同时在场单位数分别为 3、5、11，接替增援不会突破对应同时在场上限。
- 23 套关卡配方覆盖全部 20 套正式时间天气海面，并使用全部 10 类岛屿模板；旧海面别名不得进入新关卡数据。
- 每个岛屿关卡均需验证硬地形、浅水/航道、炮弹/鱼雷/视线阻挡、局部环境边界、出生点与增援路线。
- 所有舰船 Cost 与 `docs/14_character_balance_design.md` 一致；舰船解锁最终覆盖第一期 24 名角色。
- 教学必要动作通过事件记录验收，不使用提示弹窗是否关闭来代替操作完成。

### 10.2 动态调参边界

关卡进入胜率测试前必须先完成地图、出生、增援、任务与导航合法性。调参顺序保持为“任务条件 → 地图与环境 → 部署 → 增援 → 敌军数量/Cost → 同档 AI 等级”，不得通过角色私有属性覆盖伪造难度。具体实验、报告、样本和人工可读性验收只按 `docs/36_balance_testing_design.md` 执行；正式数据字段与运行时进度分别同步到 `docs/23_level_progress_data_schema.md`、`docs/00_project_status.md`。

### 10.3 中大型挑战的实施交接与退出条件

设计交付覆盖十关的唯一玩法意图、阵容/Cost、目标/取消、地图配方、战术过程、增援、奖励和逐关验收重点；不等于正式数据、导航审核或实战验收完成。稳定关卡 ID 为 `level.challenge.m01..m05/l01..l05`，目标与波次 ID 沿用 t02；角色奖励沿用获取清单，不因地图实例新增而更换进度 ID。

| 门禁 | 必须交付的证据 |
|---|---|
| 数据与地图 | 每舰唯一实体 ID、舰船引用、旗舰、Cost 重算；地图和环境实例、最终坐标/航向、RN/RS 路线、所有实际吃水及潮态的合法接敌和撤离证据；未配置设施不从母图泄漏。 |
| 目标与进度 | 每关成功/保护失败；M-04 的第二/第三舰损失边界；M-05/L-05 两目标的不同完成顺序；组内无序精通与同 Tick；空位等待、两波争用、终局取消；首次/重复首通和保存失败重试。 |
| 行为与性能 | 单局冒烟后进入小样本，观察每舰参战、航空合法限制、潜艇攻击循环、分路接回、旗舰死后剩余 AI、搜索与增援；发现卡住、零贡献或技术无效先解决原因。大型关额外完成十一舰整场交通、带画面与 t00 性能门禁，不用短片/3v3 结果替代。 |
| 正式平衡 | 按 36 的授权、样本和停止规则实施；同档双方 LatestRuntimeAI、固定任务侧，默认航空模式独立记录；60/45/30/20/10% 只是目标，不能由 Cost 比或历史小型关推算。 |
| 真人体验 | 首次、学习后重试、熟练玩家分别记录；验证每关至少两种可执行决策、取消原因可理解、暂停和多选足够完成指挥，1080p/1440p 目标/保护/画外威胁可读。 |

实施顺序为 M-01 → M-02/M-03 → M-04/M-05，完成中型操作与目标验证后再做 L-01 → L-02/L-03 → L-04/L-05；这是制作顺序，不是玩家解锁前置。尚无可运行正式数据的关卡保持菜单“筹备中”，不得仅添加奖励来源或纸面设计就开放入口；可玩接入后可用于内部验证，正式发布仍需独立完成行为、平衡与人工验收。


## 自定义环境变化预设

自定义战斗默认固定环境，继续允许选择全部 20 套天气与时段。可选「风暴过境」或「昼夜轮转」，选中时由预设确定初始环境，固定天气选择禁用并显示初始值；菜单展示完整时间表，切换前 10 秒预告。

| 预设 | 阶段时间（秒）与环境 | 终点行为 |
| --- | --- | --- |
| 风暴过境 | 0 晴朗白天 → 60 阴云白天 → 120 雷雨白天 → 180 雨天白天 → 240 晴朗白天 | 保持晴朗白天 |
| 昼夜轮转 | 0 晴朗凌晨 → 60 晴朗白天 → 120 晴朗黄昏 → 180 晴朗夜间 | 240 秒回到凌晨并循环 |

暂停冻结环境时间，重开恢复初始阶段。教学和其余挑战保持固定环境；M-04、M-05、L-04、L-05 使用下述独立挑战时间线，不复用自定义预设。

### 中大型挑战雷雨过境与作者数据

M-04（昼）、M-05（晨）、L-04（昏）、L-05（夜）初始雷雨，60 秒转同一时段雨天，240 秒恢复雷雨，300 秒再次转雨并保持；提前 10 秒公开预告。以上时间线替代对应小节的固定雷雨描述，是获授权的初始调参基线；局部飑线和高海况照常叠加，Severe 禁飞不变，源点/目标点均须通过公共航空规则。其余六关保持固定天气。

可复现作者入口为 `tools/levels/build_challenge_levels.py`；十个实例保持正式 6144×3456 海岸几何及作者变换，独立出生、导航、碰撞场与环境引用，显式关闭设施。候选投影到半径 46 深吃水最大连通分量并保持至少 180 间距；最终坐标和航向见生成的关卡数据，投影/Cost 证据见 `data/terrain/authoring/challenge_deployment_evidence.json`。静态可达不替代实际交通与撤离验收。运行部署 v3 是第 0 组原候选投影基线；当前逐关覆盖与累加替换由 `tools/levels/challenge_balance_selection.json` 选择。前方取朝敌方向，支援舰以原旗舰候选点（M-02 圣地亚哥以凤翔）为基准；替换舰继承被替换舰的候选点，再统一投影和校验。v2 潜艇前移未稳定改善，已回退；角色公共属性、奖励和目标胜率不因候选选择改变。
