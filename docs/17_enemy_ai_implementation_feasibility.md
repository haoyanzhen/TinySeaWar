# 敌方 AI 程序实现可行性评估

## 1. 评估目标

本文评估 `docs/16_enemy_ai_behavior_design.md` 各项设计在当前 Godot 原型上的实现可行性，并给出可落地的裁剪顺序。

首轮目标评分、模式切换、技能阈值和边界处理的量化公式见 `docs/18_enemy_ai_quantitative_implementation.md`。

评估以当前代码为基线，不假设已经存在导航网格、阵型系统、岛屿碰撞、航空实体、完整潜航或 AI 配置加载器。结论用于安排开发优先级，不改变玩法目标。

## 2. 当前程序基线

现有 `scripts/application/battle_session.gd` 已具备：

- 固定 Tick 和固定种子。
- 单位位置、航向、航速、转向速度和单一移动目标点。
- 地图矩形边界钳制。
- 单位圆形碰撞半径和重叠后位置分离。
- 阵营共享侦查、当前可见目标和 3 秒最后已知位置残影。
- 基于舰种、旗舰、距离和剩余 HP 的稳定目标评分。
- 自动武器、手动主要武器命令、技能命令与合法性校验。
- 实体鱼雷位置、航向、速度、寿命和碰撞。
- 战斗事件、基础统计和批量模拟入口。

当前 AI 实际只有：

```text
选择一个可见目标
  -> 远于期望距离：直接驶向目标
  -> 过近：直接反向退开
  -> 距离合适：原地停留
  -> 技能冷却完成：立即尝试释放
```

主要缺口：

- AI 每个战斗 Tick 都决策，没有独立低频调度和运行时记忆。
- 移动状态只保存一个目标点，没有航点队列、到达航向、速度档位或打断恢复。
- AI 直接读取战斗内部状态，尚无明确的阵营可见只读视图。
- 没有 AI Profile/Mode 数据类别、加载校验和关卡绑定。
- 敌方不会自动提交 `ManualPrimary` 主要武器命令，很多角色的核心武器无法按设计使用。
- 没有阵位、编组、目标预留、技能用途标签和模式切换原因。
- 鱼雷实体存在，但没有“某阵营是否已发现该鱼雷”的规则；公平规避条件尚不成立。
- 单位碰撞只做事后重叠分离，没有前瞻避碰、让路权或卡住检测。
- 地图只有矩形尺寸和海况，没有岛屿、可通行区域、视线遮挡或地形类型。
- 当前潜艇没有完整的 `depth_state`、氧气更新与反潜闭环；航空也未形成完整可拦截航空实体闭环。

## 3. 评估等级

以下工作量按一名熟悉项目的开发者估算，仅表示相对量级：

| 等级 | 含义 | 粗略量级 |
|---|---|---|
| `S` | 可在现有函数附近扩展，风险低 | 0.5-2 人日 |
| `M` | 需要新增稳定状态或服务，并补自动测试 | 2-5 人日 |
| `L` | 跨移动、感知、数据或协同系统 | 1-2 周 |
| `XL` | 依赖尚不存在的地图/领域子系统 | 2-4 周以上 |
| `Blocked` | 前置玩法尚未实现，不应现在开发 | 前置完成后重估 |

同一项若有“简化版”和“完整版”，分别给出等级。

## 4. 基础架构可行性

| 设计项 | 可行性 | 当前支撑 | 主要缺口 | 建议 |
|---|---|---|---|---|
| 规则优先级 | `S` | AI 命令集中在一个更新阶段 | 没有显式意图/打断对象 | 使用固定枚举优先级和单个 `active_interrupt`，不要先做通用行为树 |
| 低频 AI 决策 | `S` | 固定 Tick、稳定排序 | 当前每 Tick 运行 | 增加舰队与单舰累计计时器，先固定 0.5s/2s 两档 |
| AI Runtime State | `M` | `BattleState` 已集中保存战斗状态 | 没有模式、任务、编组和记忆容器 | 在会话内新增 `ai_state_by_faction/unit`，不塞入 View 节点 |
| 阵营可见 AI View | `M` | 已有 `snapshot(viewer_faction)` 与 contacts | 快照缺少己方武器状态等决策信息；投射物未过滤 | 新增专用只读 `AIObservation`，只暴露合法敌情和己方完整状态 |
| AI 配置加载 | `M` | Registry 已能扫描 JSON 类别并校验引用 | 没有 `ai_profiles/modes/rules` 类别 | 增加单一 `ai` 类别即可，首轮不拆多个目录 |
| AI 主要武器命令 | `M` | `_fire_primary_weapon` 和合法性校验已存在 | 缺少预测落点与 AI 提交逻辑 | 先对可见目标当前位置/简单提前点提交相同命令 |
| 可重复测试 | `S` | 固定种子、稳定 ID、测试入口已存在 | 未记录 AI 决策 | 增加模式、任务、切换原因事件后即可覆盖 |

结论：基础架构可沿现有 `BattleSession` 增量实现，无需引入第三方行为树或推倒 Domain。不过继续把所有逻辑写进 `_update_ai_intents()` 会很快失控，至少应拆出 `AIController`、`AIScorer` 和 `AISteering` 三个纯逻辑对象。

## 5. 通用行进规则可行性

### 5.1 航路与航速

| 设计项 | 简化版 | 完整版 | 说明 |
|---|---:|---:|---|
| 直线/侧切/外扩航点 | `M` | `L` | 先用最多两个中间航点和解析几何；障碍寻路需要独立系统 |
| 航点队列 | `M` | `M` | 将单一 `target_position` 扩为 `waypoints`、`current_index`、`arrival_radius` |
| 转弯前减速 | `S` | `M` | 简化版按剩余距离和航向差减速；完整版需估算转弯半径 |
| 速度档位 | `S` | `M` | 先支持 `Cruise/Full/Slow` 三档目标速度比例 |
| 到达航向 | `M` | `M` | 航点需保存期望离开方向；对鱼雷射角和脱离很有价值 |
| 目标短时拦截点 | `S` | `M` | 可由可见位置差估算速度；必须在失去侦查后冻结 |
| 航路打断与恢复 | `M` | `L` | 首轮只保留原任务 ID，危险解除后重新规划，不恢复旧坐标队列 |

可行结论：开阔海域短航路高度可行，也是所有侧翼、脱离和编队行为的共同前置。首轮不需要 Godot `NavigationServer2D`；矩形无障碍地图使用少量解析航点更简单、可测试、确定性更好。

### 5.2 航向与武器协同

| 设计项 | 可行性 | 说明 |
|---|---|---|
| 炮线舰维持主要射角 | `M` | 已有多扇区射角校验，可将合法底座数量加入航向评分 |
| 鱼雷舰预先对准扇面 | `M` | 已有鱼雷 `fire_arcs`，需要 AI 主要武器窗口与攻击后航向 |
| 航母连续撤离 | `S` | 只需更高权重保持远离威胁与边界转出空间 |
| 潜艇结合氧气规划 | `Blocked` | 当前没有完整氧气/潜航运行时闭环 |
| 同时优化到达时间、射角和风险 | `L` | 容易演变成昂贵多目标优化；MVP 使用有限候选航向评分即可 |

建议不要做连续数学优化。每次从“保持、左偏、右偏、接近、远离”等 5-9 个候选方向中评分，已经足以产生可读且稳定的航行。

## 6. 列阵与编队可行性

| 设计项 | 简化版 | 完整版 | 当前难点 |
|---|---:|---:|---|
| 固定阵型槽位 | `M` | `M` | 需要锚点、局部坐标旋转和阵位容差 |
| 按职责分配阵位 | `M` | `L` | 简化版用角色标签排序；完整版涉及动态匹配和替补 |
| 舒适/修正/脱队三层 | `M` | `M` | 纯距离阈值即可，较适合当前架构 |
| 编组速度跟随 | `M` | `M` | 当前单位各自取最大速度，需要目标速度比例 |
| 前出—回收循环 | `M` | `L` | 需要组任务与单舰任务同时存在 |
| 单位沉没后的局部补位 | `M` | `L` | 首轮可保留空槽，不必立即重排 |
| 阵型整体旋转 | `M` | `L` | 需要平滑锚点航向，避免槽位突然换侧 |
| 动态阵型转换 | `L` | `XL` | 多舰路径交叉、顺序、拥堵和完成判定复杂 |
| 11v11 多编组协同 | `L` | `XL` | 算力不是主要问题，调试和战术状态组合才是主要成本 |

可行结论：固定阵型和弹性阵位可做；“战斗中自由切换六种阵型”不适合首轮。推荐第一版每个编组只使用一个阵型，允许单位临时脱队并归位，不做全队动态换阵。阵型转换可先由关卡阶段切换时重新生成一次槽位完成。

## 7. 碰撞、边界与拥堵可行性

| 设计项 | 可行性 | 说明 |
|---|---|---|
| 边界软警戒区 | `S` | 当前已有矩形 clamp，增加内缩矩形和路径惩罚即可 |
| 沿边界切向脱离 | `S` | 可从最近边法线计算两个切向候选 |
| 友军预测最近接近距离 | `M` | 位置与速度可算线性 CPA；适合 11v11 的单位规模 |
| 稳定让路权 | `S` | 使用任务优先级、机动性和稳定 ID 决胜 |
| 局部转向/减速避碰 | `M` | 候选航向评分即可，不必引入物理引擎避障 |
| 卡住检测与三段恢复 | `M` | 需要保存若干秒的位置进度和恢复次数 |
| 多舰狭窄航道拥堵 | `L` | 依赖航道占用、预约或队列；当前无岛地图无需实现 |

现有 `_resolve_unit_overlap()` 可保留为最后安全网，但不应承担 AI 避碰。前瞻避碰放在生成移动意图时，重叠分离继续由战斗模拟兜底。

## 8. 威胁规避可行性

| 设计项 | 可行性 | 前置条件 |
|---|---|---|
| 规避己方已发现鱼雷 | `L` | 必须先实现投射物阵营可见性/预警距离，不能直接读取全部鱼雷 |
| 单束鱼雷碰撞预测 | `M` | 鱼雷已有位置、航向、速度和半径 |
| 多束鱼雷低密度出口 | `L` | 需要短时轨迹采样和候选航向评分 |
| 危险区成本图 | `M` | 先限制为少量圆/扇形区域，不做连续栅格 |
| 炮弹规避 | `Blocked` | 当前火炮是延迟结算，玩家与 AI 都没有可规避的领域弹道 |
| 规避后恢复任务 | `M` | 依赖 AI Runtime State 和打断机制 |

可行结论：几何上能做，公平性前置尚缺。第一版可以只让 AI 响应已经进入公开预警距离的鱼雷，并加入 0.3-0.8 秒反应延迟；在投射物可见规则完成前，不应开发规避逻辑。

## 9. 接触、搜索与巡逻可行性

| 设计项 | 可行性 | 说明 |
|---|---|---|
| 失去接触后清除攻击锁定 | 已实现 | `_clear_invalid_targets()` 已处理 |
| 使用最后已知位置搜索 | `S` | contacts 已保存位置和剩余时间 |
| 扇形/弧线搜索 | `M` | 生成 2-3 个确定性航点即可 |
| 多舰搜索分区 | `M` | 按稳定 ID 分配左/中/右扇区 |
| 残影置信度衰减 | `S` | 可从 `ghost_remaining` 推导，不必新增复杂概率模型 |
| 搜索终止与归队 | `M` | 依赖模式/任务状态和编组锚点 |
| 无敌情巡逻 | `S` | 用关卡任务区与出生区生成固定巡逻弧线 |

这是低风险、高收益的模块，适合首轮实现。应避免模拟敌方可能位置的概率云；3 秒残影下，用时间衰减和有限搜索扇区已经足够。

## 10. 岛屿与环境规则可行性

### 10.1 岛屿前置能力

当前地图只有宽、高和海况。岛屿 AI 不是增加一个“靠岛坐标”规则即可完成，而是依赖以下公共战斗能力：

1. 岛屿碰撞多边形和舰船安全膨胀区。
2. 玩家与 AI 共用的可通行查询或导航图。
3. 水面侦查视线遮挡查询。
4. 直射火炮、鱼雷和航空分别配置的遮挡规则。
5. 地图数据、编辑/验证工具和调试显示。
6. 玩家移动命令也能绕开障碍，不能只给 AI 寻路。

### 10.2 各项评估

| 设计项 | 可行性 | 说明 |
|---|---|---|
| 岛屿碰撞与安全区 | `L` | 多边形碰撞不难，难点是与确定性 Domain 移动保持一致 |
| 绕岛寻路 | `XL` | 需要导航图、路径平滑、转弯半径和动态避碰共同工作 |
| 水面视线遮挡 | `L` | 线段—多边形查询可做，但需要重写侦查查询和测试 |
| 分武器遮挡 | `L` | 需修改武器授权、鱼雷碰撞、航空规则和表现反馈 |
| 掩体点评分 | `M` | 在上述几何能力完成后反而较简单 |
| 掩体槽位与占用 | `M` | 可在岛岸预生成少量候选点并做编组预约 |
| 等待装填后绕岛出击 | `L` | 依赖短航路、到达航向、武器就绪度和任务打断 |
| 岛端鱼雷伏击 | `L` | 依赖合法共享视野、预测发射和安全出口 |
| 岛后航空侦查反制 | `Blocked` | 依赖完整航空实体与空中视野规则 |

结论：岛屿相关 AI 本身可实现，但现在开发性价比很低。它应排在“玩家与 AI 共用的地形、寻路和遮挡”之后，不能作为 AI 项目内部功能先做。完整岛屿作战相当于独立阶段，不应计入首轮 AI 模式工期。

### 10.3 其他环境

| 环境 | 可行性 | 建议 |
|---|---|---|
| 矩形任务区/撤离区 | `M` | 最容易先做，可复用区域合法性查询 |
| 圆形雷区/危险区 | `M` | 使用少量解析形状，不做栅格成本图 |
| 低雾公开视野修正 | `S` | 作为正常 DetectionRange/Concealment 状态修正 |
| 海流 | `L` | 会影响所有移动、投射物和预测，暂缓 |
| 浅水/礁石 | `L` | 依赖舰船通行标签与地形查询，随岛屿阶段实现 |
| 狭窄海峡交通 | `XL` | 需要路径预约和拥堵管理，最后实现 |

## 11. 单舰行动模式可行性

| 模式 | 简化版 | 完整版 | 首轮建议 |
|---|---:|---:|---|
| `ReconAvoid` | `M` | `L` | 做：敌方侦查边缘未知，用已知敌舰位置、自身隐蔽和威胁距离近似；除非玩家也有“已被发现”提示，否则 AI 不能读取敌方视野表判断自己是否暴露 |
| `VanguardLine` | `S` | `M` | 做：以前锋阵位和驱逐/潜艇目标权重实现 |
| `TorpedoFlank` | `L` | `L` | 做简化版：固定左/右翼航点 + 合法鱼雷窗口 + 发射后脱离 |
| `FlagshipRaid` | `M` | `L` | 第二批：先基于已发现旗舰和护航数量，不做全局最优绕路 |
| `EscortScreen` | `M` | `L` | 做：相对保护对象与威胁方向生成弧形阵位 |
| `AntiAirEscort` | `Blocked` | `L` | 等可识别来袭航空实体；此前只做静态跟随不够成玩法 |
| `GunlineSupport` | `M` | `L` | 做：距离带 + 射角候选 + 不追轻舰 |
| `HoldDecisiveLine` | `S` | `M` | 做：固定任务区 + 威胁目标评分 |
| `CarrierStandoff` | `S` | `M` | 做：远离最近可见水面威胁并预留边界转出空间 |
| `SubmarineAmbush` | `Blocked` | `L` | 等潜航、氧气、反潜闭环 |
| `DisengageRegroup` | `S` | `M` | 优先做，它是其他高风险模式的公共回退 |

首轮推荐 6 个真正可用模式：`ReconAvoid`、`VanguardLine`、简化 `TorpedoFlank`、`GunlineSupport`、`CarrierStandoff`、`DisengageRegroup`。`HoldDecisiveLine` 可作为 `GunlineSupport` 的参数变体，先不独立增加状态数量。

## 12. 攻击与目标选择可行性

| 设计项 | 可行性 | 说明 |
|---|---|---|
| 可配置目标评分 | `S` | 现有 `_target_score()` 可直接参数化 |
| 区分机动任务目标/攻击目标 | `M` | 新增两个 ID，攻击目标继续走可见性与武器合法性 |
| 威胁、距离、旗舰、击沉收益 | `S` | 数据均已存在或可从事件短期累计 |
| 武器对甲适配 | `M` | 需要读取当前可用武器、目标厚度和弹药模式 |
| HE/AP 自动切换 | `M` | 已有切换命令与共享装填；需防止频繁切换 |
| 鱼雷简单提前量 | `M` | 可用可见目标速度估算解析拦截点 |
| 鱼雷封锁/概率预测 | `L` | 不建议首轮做概率模型 |
| 友军射线检查 | `M` | 当前无友伤，首轮只避免明显从友军圆形邻域穿过 |
| 集火目标 | `S` | 已有 `FocusTarget` 命令 |
| 重武器过量伤害预留 | `L` | 需估算在途炮弹、鱼雷和航空的期望伤害；首轮可只统计已发射轮次 |
| 航空防空风险评分 | `Blocked` | 航空/防空实体闭环不足 |

目标评分很适合早做；过量伤害和多武器协同应后做。首轮只需“同编组最多两艘重武器舰锁同一低血目标”之类的硬上限，就能避免最明显浪费。

## 13. 技能使用可行性

| 设计项 | 可行性 | 说明 |
|---|---|---|
| 技能用途标签 | `M` | 为技能数据补 `ai_tags` 和最低效用阈值 |
| Self/Enemy/Area 分类策略 | `S` | 当前施法接口已支持三类 |
| HP/敌人数/友军数阈值 | `S` | 现有状态可直接计算 |
| 与主要武器就绪协同 | `M` | 需要查询主要组装填和合法发射窗 |
| 保留技能与解除保留 | `M` | AI Runtime State 保存 reserve 原因和超时 |
| 同编组技能错峰 | `M` | 保存用途标签的最近释放时间即可 |
| 区域技能位置预测 | `M` | 简单线性预测可做，失去侦查后使用残影规则 |
| 精确效用评分 | `L` | 多效果技能很难统一量化；应为用途标签写小型策略函数 |

不建议建立一条“万能技能公式”。实际更稳妥的是 6-8 个用途处理器，例如 `Burst`、`Defense`、`Escort`、`Recon`，每个只读取少量统一字段。

## 14. 模式切换与舰队方案可行性

| 设计项 | 简化版 | 完整版 | 说明 |
|---|---:|---:|---|
| 条件式模式切换 | `M` | `L` | 首轮使用代码支持的条件枚举，不解析任意表达式 |
| 最短驻留与滞回 | `S` | `S` | 计时器即可 |
| 切换原因事件 | `S` | `S` | 对调试和批量模拟价值很高 |
| 标准推进 | `M` | `M` | 固定编组与角色模式即可 |
| 旗舰固守 | `M` | `L` | 需要保护对象和护卫阵位 |
| 单翼突击 | `M` | `L` | 关卡预先指定左右翼即可，不必动态选最优翼 |
| 双翼包围 | `L` | `XL` | 依赖两个编组的时序与攻击窗口协调 |
| 航空消耗 | `Blocked` | `L` | 依赖完整航空闭环 |
| 动态阶段切换 | `L` | `XL` | 首轮只支持少量事件，如旗舰暴露/己方减员 |

舰队方案适合先作为“关卡预设编组 + 单舰模式分配”，而不是实时战略 AI。动态重组、双翼同步和全局阶段规划属于后续增强。

## 15. 难度、数据与统计可行性

| 设计项 | 可行性 | 说明 |
|---|---|---|
| 决策间隔与反应延迟 | `S` | 最安全且可读的难度参数 |
| 评分项开关 | `S` | 基础难度少用若干评分项即可 |
| 技能阈值差异 | `S` | 不改变技能数值 |
| AI 数据结构 | `M` | Registry 新类别、引用和枚举校验 |
| 每舰模式覆盖 | `M` | 关卡成员数据增加可选 mode ID |
| 决策事件记录 | `M` | Recorder 增加模式驻留、切换原因、主要武器窗口 |
| 全部设计统计指标 | `L` | 应随功能逐项添加，避免先建空泛遥测框架 |
| 6 次批量模拟调参 | 已有但不足 | 适合冒烟；平衡结论至少需要更多种子和分位数 |

难度不应靠更高决策频率无限提升。0.4-1.0 秒已经足够；更高难度主要来自更合理的模式、目标和技能窗口。

## 16. 推荐裁剪版

### 16.1 第一阶段：AI 可配置闭环

目标：让不同舰船能真正执行不同模式，并会使用主要武器。

- AI Runtime State 和 0.5 秒低频调度。
- 单一 AI 配置类别与关卡/单位模式引用。
- 阵营可见 `AIObservation`。
- 机动任务目标与攻击目标分离。
- 可配置目标评分。
- AI 手动主要武器命令和简单线性提前量。
- 技能用途标签、简单阈值和保留超时。
- `VanguardLine`、`GunlineSupport`、`CarrierStandoff`、`DisengageRegroup`。
- 模式切换原因事件与基础统计。

预计：约 2-3 周，包括测试和首轮调参。

### 16.2 第二阶段：开阔海域战术

目标：让侦查、鱼雷、护航和编组站位形成可见差异。

- 两航点短航路、转弯前减速和边界软区。
- 简化 CPA 友军避碰与卡住恢复。
- 固定编组、弹性阵位，不做自由换阵。
- `ReconAvoid`、简化 `TorpedoFlank`、`EscortScreen`、`FlagshipRaid`。
- 最后已知位置搜索和终止规则。
- 简化目标预留与同用途技能错峰。

预计：约 2-4 周。

### 16.3 第三阶段：高级协同

目标：支撑第二、三章高难度舰队战。

- 关卡阶段触发的有限阵型转换。
- 单翼/双翼编组时序。
- 公平的鱼雷发现与规避。
- 更完整的过量伤害和攻击波预留。
- 11v11 调试工具与统计扩展。

预计：约 2-4 周。

### 16.4 独立后续阶段

以下功能不并入当前 AI 实现：

- 岛屿碰撞、寻路、视线和武器遮挡。
- 岛屿掩体与绕岛出击。
- 浅水、海峡和复杂地形交通。
- `AntiAirEscort` 的完整威胁响应。
- `SubmarineAmbush` 的氧气与潜航规划。

这些功能应分别在地形、航空和潜艇领域规则完成后接入 AI。岛屿完整阶段粗略为 4-8 周，且包含玩家移动、地图数据、表现和测试，不只是 AI 工时。

## 17. 最小可行实现建议

如果只安排一轮短开发，建议将首版压缩为：

1. 仅实现 4 个基础模式：前锋、炮线、航母后排、脱离。
2. 岛风增加一个脚本化程度较低的双航点侧翼雷击模式，用于验证模式框架。
3. 固定编组阵位，不做动态换阵。
4. 不做鱼雷规避、不做岛屿、不做全局成本图。
5. 技能只按用途标签和 2-3 个阈值释放。
6. 目标评分只加入模式权重、旗舰、距离、HP 和当前武器适配。
7. 每次模式切换、主要武器放弃/成功窗口都记录原因。

这版约 2-3 周可形成明显优于现状的可玩 AI，并能验证岛风侦查/侧翼/对线三种装配是否真的产生不同战斗体验。验证通过后，再决定阵型、规避或舰队协同中哪一项最值得继续投资。

## 18. 总结判断

- 原设计在技术上大多可实现，但不适合作为一次迭代整体开发。
- 开阔海域的模式、目标、技能、短航路和弹性阵位与现有架构兼容，属于可控增量。
- 动态换阵、鱼雷群规避、全局协同会显著增加状态组合和调试成本，应分阶段进入。
- 岛屿掩体不是单一 AI 功能，而是地图、移动、侦查、武器和表现共同依赖的新战斗子系统。
- 当前最重要的前置不是高级寻路，而是 AI Runtime State、合法可见视图、主要武器使用和可观测决策事件。
