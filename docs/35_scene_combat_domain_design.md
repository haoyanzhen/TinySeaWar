# 硬地形与场景空间 Domain 设计

> **功能与边界**：本文定义岛屿、岸线、浅水边界等硬地形进入战斗后的权威空间状态、几何查询和对移动、投射物、视线的约束。环境运行时见 `37_environment_runtime_domain_design.md`，设施见 `38_facility_combat_domain_design.md`，玩法效果见 `18_facility_weather_effect_design.md`，数据字段见 `22_scene_environment_data_schema.md`。

## 1. 设计目标

- 开阔海域与有岸地图共享核心战斗规则，只增加明确的空间查询。
- 作者输入、烘焙产物、运行时状态和表现网格彼此分离。
- 舰船、鱼雷、炮弹、视线和部署使用一致的地形语义，但可采用不同碰撞策略。
- 所有权威查询可在无图形模式运行，不依赖贴图像素或场景节点碰撞。
- 相同定义、种子、命令与 Tick 得到稳定的空间结果。

本文不维护天气、潮汐、设施数值、代码路径、关卡完成度或美术规格。

## 2. 空间定义与运行时状态

### 2.1 作者定义

作者输入描述可编辑的轮廓、区域、锚点和语义标记。它不是直接供战斗逐 Tick 查询的最终结构。字段、坐标系与校验要求见 `22_scene_environment_data_schema.md`。

### 2.2 烘焙定义

烘焙阶段把作者输入转换为运行时可加载的：

- 硬障碍轮廓与加速索引。
- 水深/浅水等空间区域。
- 导航门、走廊与连通信息。
- 部署、任务和设施锚点。
- 小地图和表现层可消费的派生几何。

烘焙产物必须带源版本与校验摘要。表现派生物不能反向成为权威碰撞源。

### 2.3 TerrainMapState

`TerrainMapState` 是单局只读或受控更新的场景空间聚合，至少提供：

- 地图边界和坐标转换。
- 障碍集合、区域集合与空间索引。
- 导航拓扑与部署锚点索引。
- 与环境/设施子域关联的稳定语义 ID。

静态地图通常不逐 Tick 改变。若未来允许可破坏地形，必须通过显式状态与版本化索引更新，不得直接删除场景节点来改变 Domain 查询。

## 3. 空间语义

### 3.1 硬障碍

硬障碍是舰船不可穿越的陆地或结构几何。每个障碍具有稳定 ID、闭合轮廓、包围盒和适用查询类别。轮廓必须无自交、方向一致并通过最小边长/面积校验。

### 3.2 区域

区域描述位置语义而非必然阻挡，例如浅水、航道、礁区或部署限制。区域效果本身由对应规则消费者解释：硬地形只回答“点或形状位于哪些区域”。天气、海况和局部环境组合由 `37` 负责。

### 3.3 锚点

锚点是稳定语义位置，包括出生、目标、设施槽位、任务目标和导航接入点。锚点必须位于合法地图范围，并按用途验证可部署性、净空和阵营约束。

### 3.4 导航拓扑

导航图是硬地形的派生加速结构，不是移动规则。路线规划可使用节点、边、门和净空信息生成走廊；烘焙边、直达段、最终接入段和被选中的稀疏门间段必须使用与运行时一致的带半径连续线段查询验证，最终舰船位移仍由 Domain 几何查询权威校验。语义目标可以落在当前不可占位区域，但执行目标必须位于动态可达分量并产生正向进展；投影执行目标不得修改任务原意，也不得绕过 Domain 合法性。导航性能和状态机见 `technical/t00`、`technical/t01`。

## 4. TerrainQueryService

查询服务是纯查询边界，输入显式地图状态和查询参数，返回稳定排序的结果。

### 4.1 点与区域查询

- 点是否在地图边界内。
- 点命中的障碍与区域语义集合。
- 最近合法水域点及其距离/法线。
- 给定用途的锚点或导航接入候选。

同点命中多个区域时按稳定优先级和 ID 排序，消费者不得依赖容器遍历顺序。

### 4.2 形状通行查询

舰艇使用随航向旋转的椭圆舰装碰撞。查询至少支持：

- 指定位置/航向的椭圆是否与硬障碍或边界重叠。
- 从旧姿态到新姿态的扫掠碰撞候选。
- 碰撞点、法线、穿透/安全距离和障碍 ID。

宽相位使用包围盒/空间索引，窄相位使用权威几何。不能只检查单位中心点，也不能以表现贴图边缘替代碰撞椭圆。

### 4.3 线段与射线查询

查询应返回按沿线距离排序的交点：

- 观察视线是否被遮挡。
- 鱼雷路径首次硬障碍接触。
- 炮弹轨迹或落点与地形的语义关系。
- 导航边、任务连接或部署净空验证。

不同消费者可选择是否把某类区域当作阻挡，但几何命中事实由同一服务提供。

舰船导航线段查询使用当前 Profile 的安全半径连续扫掠硬岸和地图边界，并按区域边界交点把线段分段；每段按最高优先级区域语义判定吃水或移动合法性。几何 epsilon 以世界坐标表达，转换为路径比例时必须除以当前线段长度，不能把比例常数直接当作世界距离。

## 5. 舰船运动集成

### 5.1 权威流程

1. 导航或控制器生成期望推力与转向。
2. MotionService 积分得到候选姿态。
3. TerrainQueryService 对候选姿态和扫掠路径做权威查询。
4. MotionService 按统一策略接受、截断、滑移、制动或拒绝位移。
5. 产生必要的受阻事实，提交最终姿态。

地形不能直接把单位瞬移到安全点；紧急恢复也必须经过显式状态与合法查询。

### 5.2 初始部署

创建战斗时应验证：

- 单位碰撞椭圆完整位于合法水域。
- 同阵营/异阵营出生满足关卡间距约束。
- 出生姿态不会与硬障碍或其他单位重叠。
- 必需锚点和接入走廊存在。

部署不合法时拒绝创建该运行，而不是在首 Tick 随机挪动单位。

### 5.3 浅水与软区域

硬地形服务只报告区域命中。浅水对舰种的通行或运动修正由核心运动规则消费 `TerrainContext` 决定，语义和数值来源见 `18` 与 `37`。若某区域对特定单位属于硬禁止，消费者必须用同一形状查询执行，不另建表现碰撞。

## 6. 投射物与攻击集成

### 6.1 鱼雷

鱼雷是实体投射物。每 Tick 推进时对前后位置做线段/扫掠查询，首次命中硬障碍即产生地形接触并失效；不能穿岛后继续命中舰艇。舰艇与地形候选的先后按沿路径距离统一排序。

### 6.2 炮弹

炮弹是否受地形阻挡以核心规则与攻击类别为准。硬地形服务提供发射点、轨迹/落点与地形的交点或覆盖事实，不自行决定伤害。表现层炮弹曲线不能成为地形命中依据。

### 6.3 航空、反潜与技能

这些攻击只在其规则明确要求时消费硬地形或区域查询。禁止因场景节点碰撞便利而给某类攻击增加未设计的阻挡规则。

## 7. 观察与视线

ObservationService 请求观察者到目标判定点的视线查询：

- 硬遮挡命中时，按 `10`、`12` 的观察规则处理。
- 视线结果包含遮挡物 ID 和交点，便于调试但不一定发布给玩家。
- 天气、时段、暴露和设施观测属于环境/核心/设施修正，不由几何服务重复计算。

对大型单位可使用规则规定的多个判定点，但采样集合必须稳定，不能随渲染分辨率变化。

## 8. 命令、事件与拒绝

硬地形通常不接收玩家直接命令，而是参与以下命令的合法性：移动、追加航点、攻击目标、设施任务和部署。典型稳定拒绝语义包括：目标点不可通行、路线接入失败、部署重叠、目标被硬遮挡或任务锚点不可达。

事实事件可包含：

- 舰船运动被硬地形限制。
- 投射物命中地形并失效。
- 路线因地形版本变化而失效。
- 部署或任务锚点校验失败。

事件只报告事实，不携带表现资源路径。

## 9. 确定性与性能

- 几何与空间索引在加载后使用稳定 ID 和排序。
- 边界点使用统一容差，避免不同服务各自判断内外。
- 同距离候选按类别、障碍 ID 与几何片段序号决胜。
- 运行时不从贴图、像素遮罩或不稳定物理回调重建权威结果。
- 高频查询复用共享索引；诊断模式统计查询次数、候选数和耗时。
- 战略路线请求预算与常规/紧急航迹预算以 `t00/t01` 为准。

## 10. 作者与运行时校验

加载前/烘焙时至少校验：

- 地图边界、障碍轮廓和区域几何有效。
- 导航拓扑与锚点引用存在、连通且净空满足用途。
- 表现派生物与权威几何使用同一源版本。
- 设施和环境区域引用的地形语义 ID 存在。

运行时测试至少覆盖：

- 椭圆舰体不能穿越岛屿、岸线或地图边界。
- 高速移动和鱼雷不会因离散 Tick 穿透薄障碍。
- 视线遮挡与交点排序可复现。
- 出生、航点和设施任务对非法空间输入给出稳定拒绝。
- 开阔海域没有硬地形时走同一接口且返回空命中。
- Headless 与带画面运行得到相同权威空间结果。

测试与工具位置见 `34_implementation_map.md`，当前通过情况见 `00_project_status.md`。
