# 平衡性测试设计

更新日期：2026-07-10

## 1. 文档定位

本文是 Tiny Sea War 平衡性测试的设计真源，定义测试问题、输入、输出、参数和结论边界。它不替代 `docs/13_balance_baseline.md` 的数值范围、`docs/14_character_balance_design.md` 的角色纸面设计、`docs/15_battle_level_design.md` 的关卡草案、`docs/16_enemy_ai_behavior_design.md` 的 AI 规则，以及 `docs/19_battle_simulator_design.md` 的模拟器通用实现。

平衡性测试独立于功能正确性和单项性能回归，用于判断改动是否在受控条件下改变战斗节奏、舰队生态、地图收益或策略收益。它不产生单一“角色强度真值”。

## 2. 测试原则与结论边界

- 单项功能或性能改动默认只运行 `1 -> 3` 个固定种子，确认可运行、可复现且无新增异常；这不是平衡结论。
- 20 局及以上的平衡统计、侧别交换、配对 A/B 和大矩阵，只能由任务、工单或用户指令明确指定为大版本验证。记录必须保存指定来源、问题和预期用途。
- 每个实验只回答预先声明的问题；固定阵容、单张地图或单个 AI Profile 的结果不能外推成整体舰种、角色或地图平衡。
- 基线和候选只允许改变声明的受测参数；其余参数必须锁定，或在报告中列为混杂因素。
- 一个异常种子只能提供复盘线索，不能单独触发正式数值修改；结论优先寻找跨种子、跨对手、跨地图或跨策略稳定存在的模式。

## 3. 统一实验契约

每个平衡实验必须具有可读实验说明或 manifest，并包含以下输入。

| 类别 | 必填字段 | 规范 |
| --- | --- | --- |
| 身份与授权 | `experiment_id`、标题、问题、人工指定记录 | ID 使用稳定英文；20+ 实验必须写明“大版本平衡验证”的指定来源。 |
| 版本 | 代码提交/工作树说明、Godot 版本、配置指纹 | 使结果可复跑；未提交工作树必须标记。 |
| 种子 | 显式固定种子列表、样本数、侧别交换规则 | 不使用隐式随机；配对比较使用同种子和侧别。 |
| 场景 | 关卡 ID、地图、天气/时段、局部环境、设施状态 | 未覆盖维度不得写成已验证。 |
| 阵容 | 双方舰船、旗舰、出生点、阵型、总 Cost | 是否等 Cost 必须记录；不等 Cost 不能用于对称性或 AI 平衡结论。 |
| 控制 | 双方策略、AI Profile、玩家辅助/自动开火、Tick、时间上限 | 策略和观察权限应对称，除非问题本身比较策略差异。 |
| 受测参数 | 基线、候选及唯一允许变化的字段 | 如伤害倍率、散布、编成、Cost、地图或 AI 权重。 |
| 产物 | 输出目录、明细粒度、图表和报告路径 | 必须可定位到逐局原始数据和汇总。 |

### 3.1 参数分层

| 参数层 | 含义 | 示例 |
| --- | --- | --- |
| 受测参数 | 本实验要判断影响的唯一变量或显式候选组 | `armor_coefficient`、舰炮散布、舰队 Cost、地图设施、AI 战术权重。 |
| 控制参数 | 保持不变以避免混杂 | 关卡、天气、种子、阵容、Profile、Tick、时间上限。 |
| 分层参数 | 不作为直接改动，但需展开结果 | 舰种、装甲、出生侧、地图、天气、设施、AI Profile。 |
| 禁止外推参数 | 当前实验未覆盖、不得据此下结论的维度 | 未入场角色、未运行地图、未测试 AI 策略、未实现环境组合。 |

同时改变多个受测参数时，实验必须标记为“组合候选”，不能把结果归因给其中任一单项；需要单项归因时，后续建立配对 A/B 或因子实验。

## 4. 输出与数据规范

每个实验输出位于 `artifacts/simulations/{experiment_id}/`，生成物默认不是运行时数据源：

```text
metadata.json       实验身份、授权、版本、输入与环境
runs.jsonl          一行一局的原始结果
summary.csv         一行一局的可读数据表
aggregate.json      聚合数值、分层与区间
report.md           问题、结果、结论边界与下一步
*.png               回答核心问题的图表（如适用）
```

`metadata.json` 必须包含实验 ID、问题、人工指定记录、配置/代码版本、种子、场景、阵容、策略、受测参数和控制参数。`runs.jsonl` 与 `summary.csv` 必须共享稳定的 `run_id` 或 `seed + side_variant` 键。比例指标必须保存事件数和分母，连续指标至少保存样本数、均值、中位数、P10/P90、最小值和最大值。

`report.md` 按“实验问题、输入与控制、结果表、图表、异常种子、可以下的结论、不能下的结论、后续动作”组织。图表用于比较形状或分布，CSV 用于精确查值；图表必须标明单位、样本数和筛选条件。

## 5. 平衡性测试族

### 5.1 伤害倍率与舰炮散布

目的：验证伤害量纲与舰炮逐发椭圆高斯散布对命中链路、有效伤害和战斗时长的共同影响。

核心链路：`几何相交 -> 命中判定 -> 有效伤害 -> TTK`。

输入额外要求：声明局内伤害倍率、武器/公式版本、散布设置、舰炮可用舰种和目标装甲；地图、AI Profile 与阵容作为控制参数。

输出额外要求：舰炮结算数、几何相交数/率、几何未相交数/率、命中数/率、有效伤害事件与总量、按主炮/副炮分组伤害、每局 TTK、TTK P10/P90，以及命中链路柱状图和逐种子 TTK 图。

当前已实现人工指定的 `sim.balance.damage_ttk_20`：3v3、双方 `LatestRuntimeAI`、标准 Profile、20 个固定种子、局内伤害倍率 `0.25`。运行脚本为 `tools/simulation/run_damage_ttk_balance.gd`，统计与图表脚本为 `tools/simulation/analyze_damage_ttk_balance.py`。它只覆盖本子项，不验证后续三类平衡测试。

### 5.2 舰队安排与舰队 Cost（待实施）

目的：验证合法编成、舰种职责、总 Cost、同预算替换与舰队边际贡献，避免把阵容差异误判为 AI 或地图差异。

未来实验必须声明阵容生成或人工名单、双方 Cost、旗舰、出生侧、镜像规则和替换关系；输出应包含阵容胜率、同 Cost 胜率差、逐舰有效伤害/承伤、单位 Cost 效率、舰种覆盖和不可替代性信号。当前不定义具体阈值、不生成脚本、不形成结论。

### 5.3 地图与环境（待实施）

目的：验证地图、出生侧、天气、时段、地形、设施和局部环境是否系统性偏向某类阵容或策略。

未来实验必须使用相同阵容、策略和种子对进行地图/环境配对，并分开报告原始阵容胜率、出生侧胜率、时长、地形/环境停留时间、设施使用与路径异常。当前不执行跨地图或环境统计。

### 5.4 AI 策略倾向（待实施）

目的：验证模式、战术、目标、技能、设施任务、接敌压力和策略 Profile 是否产生非预期收益偏差，而不是把 AI 漏洞误当作角色强度。

未来实验必须锁定属性、观察权限和阵容，只改变声明的 AI 策略参数；输出需结合胜率、目标/战术驻留、技能收益、非法命令、路线异常、消极行为和设施响应。当前不把单局 AI 胜率或行为异常解释为整体平衡结论。

### 5.5 关卡目标与进度（首个运行时子集已实施）

目的：验证教学关、挑战关和后续章节的目标胜率、时长、失败原因与可复现正确解法，不把关卡门槛误判为角色或 AI 强度。

单项关卡、功能或性能改动默认仍只运行 `1 -> 3` 个固定种子。自 2026-07-16 起，所有标记为 `LevelWinRateEvaluation` 的正式胜率实验统一固定为 **20 场、20 个互不重复种子**；加载器必须拒绝其他样本数、重复种子或会复用同一批种子的 `side_swap=true`。教学关可使用对应教学要求的确定性合法指令脚本，敌我 AI 等级仍相同。挑战关目标容差为 `±5` 个百分点，10% 目标关容差为 `±3` 个百分点。关卡语义的侧别限制必须在报告中明示；侧别公平性需另建非胜率结算实验验证。

输出必须同时生成战斗统计与伤害统计，至少包含胜率、时长分布、旗舰死亡时间、首次接触时间、逐舰分类伤害、路线选择、环境停留时间、任务失败原因和人工可读性复核。自动结算只读取聚合战斗统计报告中的有效对局数与胜率；逐局日志和伤害报告用于解释与复核，不得挑选单局改变结算。`T-01`、`S-01` 已建立正式关卡数据与 20 场实验清单，其余关卡仍待实施。

## 6. 统计与验收记录

平衡结论至少同时检查 Cost 效率、舰队边际贡献、对局与地图覆盖面、明确优势与可利用弱点、角色职责是否改变行为、是否挤压同职责选择，以及是否依赖 AI 缺陷或单一关卡结构。

结果接近阈值、方差过高或稀有事件重要时，不得自行扩大样本；先由人工明确指定新的大版本平衡验证。历史 20/40 局及更大批次保留为历史证据，但不构成未覆盖维度的验收结果。

任何正式数值修改都必须记录“修改前、修改后、受测参数、控制参数、预期变化、实际变化和未解决风险”，并同步 `docs/00_project_status.md`。

## 7. 实施状态

- 已实施：伤害倍率与舰炮散布子项的逐局事件统计、CSV、Markdown 和 PNG 图表。
- 待实施：舰队安排与 Cost、地图与环境、AI 策略倾向的实验契约、脚本、数据与验收。
- 待人工验收：1080p/4K 下瞄准椭圆、弹着、水柱与命中反馈的可读性；它属于表现验证，不由无图形平衡统计替代。
