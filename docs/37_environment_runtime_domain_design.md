# 环境运行时 Domain 设计

> **功能与边界**：本文定义天气、时段、海况、水流、潮汐和局部环境区如何形成单局权威环境上下文，并被移动、观察、武器与设施服务消费。玩法效果与数值见 `18_facility_weather_effect_design.md`，数据字段见 `22_scene_environment_data_schema.md`，硬地形见 `35`，设施见 `38`。

## 1. 设计目标

- 全局环境与局部区域使用一个确定的组合入口。
- 环境只提供上下文和修正来源，不直接绕过核心结算改状态。
- 同一位置、Tick、实体和定义得到可复现结果。
- Domain 环境状态可在 Headless 模拟中运行，不依赖海面 Shader 或天气粒子。
- 环境数值只维护在玩法真源与配置中，本文不复制当前倍率。

## 2. 状态所有权

### 2.1 GlobalEnvironmentState

单局全局环境状态至少关联：

- 天气定义 ID、时段定义 ID 与海况/风况来源。
- 当前环境 Tick 或阶段。
- 全局水流向量、能见度语义和允许的动态转换状态。
- 确定性随机源或预定时间线引用。

Definition 是只读配置；State 只保存本局阶段与必要的动态事实。

### 2.2 EnvironmentZoneState

局部环境区保存稳定区域 ID、定义引用、启用状态、持续阶段和必要的动态参数。区域几何由 `TerrainMapState` 提供，环境子域不复制多边形作为第二套空间真源。

多个区域可重叠。组合顺序和互斥组必须由配置语义和稳定优先级决定，不依赖加载顺序。

### 2.3 TerrainContext

`TerrainContext` 是给定查询点/形状、实体类别和 Tick 的派生结果，可包含：

- 全局天气、时段与海况语义。
- 命中的硬地形区域语义。
- 命中的局部环境区及其来源 ID。
- 合成后的水流、能见度、航行、武器和设施查询输入。

它是只读查询结果，不保存为单位的第二份权威状态；消费者需要时按稳定缓存策略复用。

## 3. 固定 Tick 更新

环境状态在核心 Tick 的命令处理后、单位观察与运动前更新：

1. 推进预定天气/时段阶段。
2. 更新全局风、海况、水流或潮汐相位。
3. 推进局部环境区的启用、持续和结束状态。
4. 生成环境变化事实并使相关上下文缓存失效。
5. 后续观察、运动、武器与设施服务读取同一 Tick 的环境版本。

表现层可以插值天空、海面和粒子，但规则只在固定 Tick 边界切换环境状态。

## 4. 上下文组合

### 4.1 组合顺序

环境查询按以下概念顺序组合：

1. 关卡全局天气与时段基线。
2. 当前海况、风和潮汐阶段。
3. 查询位置命中的局部环境区。
4. 硬地形/浅水等空间语义。
5. 实体类别、武器类别或设施类别的适用性过滤。
6. 状态效果和技能等核心修正由对应服务在环境上下文之后叠加。

具体加法、乘法、上下限与舍入见 `12`、`18`。环境服务不复制公式。

### 4.2 重叠区域

- 互斥区域按显式优先级选择。
- 可叠加区域按稳定 ID 顺序生成修正来源列表。
- 同一来源不能因多次空间命中重复计入。
- 区域边界使用 `35` 的统一几何容差。

### 4.3 潮汐与水流

潮汐和水流是环境上下文，不直接改写单位坐标。MotionService 将其作为外部运动输入；设施可用性或水雷语义在 `38` 中消费同一环境状态。若潮汐改变可通行区域，应通过明确的区域状态版本参与 `35` 查询，不能只改表现贴图。

## 5. 消费者契约

- **MotionService**：读取水流、海况、浅水和航行修正输入，再执行权威运动。
- **ObservationService**：读取天气、时段、区域能见度和环境遮蔽来源。
- **Weapon/DamageService**：读取武器类别适用的环境上下文，不由环境服务决定命中或伤害。
- **ProjectileService**：读取鱼雷稳定性、水流或区域影响，再按实体规则推进。
- **FacilityService**：读取设施任务、航空、水雷或观测所需的环境条件。
- **AI/Application**：只读取所属阵营可合法知晓的环境事实；隐藏局部区域不能借查询泄露敌方信息。
- **Presentation**：读取发布后的环境快照选择海面、天气与 UI 表现。

## 6. 命令与事件

正式战斗通常由关卡时间线推进环境。调试或脚本若需要改变环境，必须通过 Application 授权的环境命令进入固定 Tick，并记录来源；表现层不能直接切换权威天气。

可发布的事实类别包括：

- 全局天气、时段或海况阶段改变。
- 局部环境区启用、更新或结束。
- 潮汐/水流跨越具有规则意义的阶段。
- 环境定义或区域引用无效导致运行拒绝。

事件携带语义 ID，不携带 Shader 参数或物理资源路径。

## 7. 快照与隐藏信息

环境快照分为：

- 所有阵营可知的全局环境事实。
- 需要进入、发现或由设施揭示的局部环境事实。
- 仅供调试/复盘的完整环境状态。

局内 HUD、AI 和表现层使用阵营过滤后的版本。视觉上明显的天气可以公开，但不能由视觉资源反推未授权的设施或敌方状态。

## 8. 确定性与缓存

- 动态环境时间线按 Tick 而非墙钟时间推进。
- 概率性转变使用会话随机源，并记录种子和抽取阶段。
- 区域候选、优先级与修正来源稳定排序。
- 上下文缓存键至少包含地图/环境版本、Tick 阶段、空间单元和消费者类别；环境变化时显式失效。
- 缓存只能优化派生查询，不能改变边界判定或组合顺序。

## 9. 校验与测试

加载时至少校验环境、区域、地形语义与关卡引用完整，动态阶段可达且无非法循环。

运行时测试至少覆盖：

- 同位置、Tick 和输入得到相同上下文与修正来源顺序。
- 全局、局部、浅水和实体类别按规定顺序组合。
- 区域重叠、边界点、启停和缓存失效正确。
- 水流由 MotionService 消费而不是直接瞬移单位。
- 环境改变后观察、武器、鱼雷与设施在同一 Tick 读取一致版本。
- Headless 规则结果不依赖海面、天气和光照节点是否存在。

当前实现入口见 `34_implementation_map.md`，完成与验收状态见 `00_project_status.md`。
