# 场景美术设计文档

> 当前文档只定义纯场景美术：海面、波纹、云影、独立天气层、海域配色、大地图连续性、地图边缘、镜头移动、分辨率适配，以及后续陆地/岛屿层。投射物、命中、潜艇、航空、防空和战斗特效归 `docs/42_combat_art_design.md`；HUD、战术叠层、选中、路径、范围、画外提示和结算界面归 `docs/44_ui_art_design.md`。

## 1. 文档目标

本文档定义 Tiny Sea War MVP 阶段的场景美术方向、战场视觉结构、环境资产、天气层、镜头和交付规范。

MVP 场景美术目标：

- 以 1920 x 1080 为设计基准，完整支持 3840 x 2160（4K）显示
- 海面具有二次元插画感和运动感，但不抢夺舰娘、投射物和技能区域的视觉优先级。
- 场景层主动为角色、舰装、战斗特效和 UI 留出可读空间，不使用会伪装成功能信息的环境形状。
- 通过模块化海面、光照、云影和天气叠层形成关卡差异，不为每关制作一张不可复用的大背景。
- MVP 开阔海域不引入会误导碰撞和遮挡判断的岛屿、陆地或大型障碍物；后续陆地层作为独立场景模块设计。

## 2. 场景定位

### 2.1 核心视觉概念

MVP 战场采用“航海战术图上的二次元海战”作为核心概念：

- 海面保留水体深度、波纹、浪花和天气变化。
- 战术信息由 UI/战术叠层负责，场景只提供承载底面。
- 舰娘与舰装保持插画化，场景纹理比角色低一档对比度和细节密度。
- 战斗爆发时，场景层允许短暂降噪或减弱天气透明度，避免争夺局部对比度。
- 非战斗区域保持安静，避免全屏持续流动的高亮波纹造成视觉疲劳。

### 2.2 画面视角

MVP 使用固定正俯视 2D 视角。海面、场景边界、天气和陆地均位于统一的正交平面，不使用斜俯视透视或可旋转镜头。

推荐规则：

- 海面、天气层、陆地层和地图边界按正俯视平面处理。
- 角色本体不跟随海面透视压扁，不按航向 360 度旋转。
- 舰装底座、航迹、方向箭头和武器节点由战斗/UI 层承担，不由场景层绘制。
- 场景层不制作需要透视高度判断的地平线、远景山体或天空背景。
- 不制作地平线、透视汇聚线或固定画面朝向的环境装饰。
- 镜头不旋转，屏幕下方始终代表玩家阵营方向，屏幕上方始终代表敌对阵营方向。

### 2.3 阵营构图方向

- 玩家舰队的初始部署区位于地图下部，主要进攻方向朝向屏幕上方。
- 敌方舰队的初始部署区位于地图上部，主要进攻方向朝向屏幕下方。
- 左右方向用于侧翼机动，不改变上下阵营的基础认知。
- 关卡中的出生点、初始编队中心和镜头默认中心均遵循该方向规则。
- 环境纹理不得出现强烈的固定上下流向，以免与双方进攻方向混淆。

### 2.4 视觉关键词

```text
清澈深海 / 二次元海战 / 低噪声海面 / 舰娘高可读性
冷色基底 / 局部高亮 / 模块化天气 / 连续大地图 / 固定正俯视
```

### 2.5 海面场景统一风格基准

本节根据当前角色成品、战场单位、舰装拆件和公共战斗特效归纳海面场景的统一风格。后续海面概念图、AI 生成母版、可平铺纹理、波纹遮罩、云影、Shader 调色和天气变体均以本节为上位限定；外部参考图或生成结果与本节冲突时，以本节为准。

#### 2.5.1 当前美术语言归纳

当前美术存在三种细节层级，海面需要在三者之间起到视觉衔接作用：

| 层级 | 当前美术特征 | 对海面的要求 |
| --- | --- | --- |
| 角色立绘与头像 | 精细二次元插画，轮廓干净，赛璐璐明暗结合柔和渐变；发色、服装和阵营点缀鲜明 | 海面不能使用同等级人物插画细节，不与脸部、发型和服装主色争夺注意力 |
| 战场角色与舰装 | Q 版比例和清楚外轮廓；角色使用大色块，舰装以海军灰、黑铁、深蓝和少量金属高光为主 | 海面需要提供稳定的中低明度底色，使浅色角色和深色舰装都能保留外轮廓 |
| 公共战斗特效 | 图形化、短促、边缘清楚；青白表现水与支援，金黄和橙色表现发射与命中，红橙表现危险，紫色表现特殊技能 | 海面必须降低饱和度和线性高光密度，为这些功能色、光圈、拖尾和预警形状保留空间 |

统一后的海面定位为：

```text
低饱和清冷插画海面 + 柔和大色块水体 + 稀疏利落波纹
作为精细舰娘与图形化战斗特效之间的安静舞台
```

不是写实海洋照片，也不是纯色战术棋盘。画面应保留二次元插画的色彩组织和手绘节奏，同时具备支持长时间战斗阅读的克制与稳定。

#### 2.5.2 四项风格支柱

1. **插画化而非照片化**：水体以概括色块、柔和层次和经过设计的波纹表达，不追求真实摄影噪点、复杂反射或物理海浪细节。
2. **清冷基底、冷暖分工**：环境主体使用低饱和蓝、青蓝、蓝灰和深海军蓝；暖色只用于暮色的大面积低饱和反光，不形成类似炮焰、命中或警告的孤立亮点。
3. **软体积、硬识别**：大尺度水体和云影使用软边过渡；中小波纹使用清楚但断续、渐细的边缘。海面不能比舰装轮廓更硬，也不能软到像无材质的纯色渐变。
4. **低噪声、留舞台**：海面先提供空间和情绪，再提供动态。任何单层纹理关闭后都不应破坏整体；任何局部高光移除后都不应影响地图或战斗信息理解。

#### 2.5.3 形状与纹理语言

- 大尺度水体使用不规则、无明确边框的深浅色团，形状偏宽、缓、连续，避免规则圆斑、云朵轮廓和明显程序噪声颗粒。
- 中尺度波纹使用短弧、折弧和轻微交错的梭形水纹，边缘允许有少量手绘抖动，但整体必须利落。
- 小尺度高光使用渐细短线、碎点和极短白沫，成簇出现后迅速留空，不平均撒满全屏。
- 建议单个 1080p 画面保持约 70% 安静水面、25% 可感知但低对比的水体变化、最多 5% 小波纹和闪光高光。
- 白沫、碎浪和风纹必须独立于基础底色，使用透明遮罩或程序分布；不得将大量白沫永久烘焙进基础平铺纹理。
- 不允许出现贯穿全屏的规则斜线、等距平行波纹、鱼鳞阵列、同尺寸光点阵列或能够一眼识别的重复图章。
- 海面纹理不得形成类似舰装炮管、鱼雷航迹、航空路径、瞄准线或范围圈的长直线和完整几何图形。

#### 2.5.4 色彩与明度限定

- 海面主体优先使用低饱和蓝青色系，允许少量蓝绿偏移，但不得大面积进入高饱和荧光青。
- 高亮以冷白、灰青和低饱和浅蓝为主。纯白只用于极少量浪尖，不形成连续亮带。
- 环境不使用高饱和红、橙、黄、紫作为小面积亮点，避免与危险、炮火、航空和技能功能色混淆。
- 深色角色和黑铁舰装需要在海面上保持轮廓，因此常规可战斗区域不得长期接近纯黑；暮色海域也应保留蓝灰色阶。
- 白发、浅色服装和金色装饰需要保持细节，因此海面不得出现大面积接近白色或高亮青白的反光区。
- 晴昼、多云、暮色使用同一材质家族和波纹形状语言，只调整明度、色温、云影比例和局部反光，不改变为三套互不相关的画风。
- 角色阵营色和功能色始终高于环境饱和度。海面截图单独观看可以有情绪，叠加角色和特效后必须主动退到视觉层级后方。

#### 2.5.5 材质与光照限定

- 采用“赛璐璐色块 + 柔和插画渐变”的混合方式：色阶组织清楚，但过渡不做硬切割的卡通水块。
- 水体允许有轻微半透明和深度感，不表现清晰海底、真实折射、镜面天空倒影或写实焦散。
- 不使用高强度法线、金属反射、塑料高光或 3D PBR 海洋质感。固定正俯视下，水面不能出现暗示地平线方向的长反射带。
- 云影是低对比乘色层，不改变角色本体和舰装的阵营色，也不在单位经过时制造突兀明暗闪烁。
- 暮色暖反光使用宽、软、断续的低饱和色带，不能表现成橙色炮火、技能光柱或危险落区。
- 地图边缘压暗继续使用海水本身的深色和雾化过渡，不添加实体墙、发光边框或写实岸线材质。

#### 2.5.6 动态节奏限定

- 大尺度明暗变化最慢，中尺度波纹次之，小尺度闪光最快；三层不得同向、同速、同周期平移。
- 波纹运动以缓慢漂移、局部显隐和轻微形变为主，不让整张底图像一张贴纸持续滑动。
- 小波纹和闪光应有明显空窗期，避免持续闪烁造成角色边缘和炮弹轨迹难以追踪。
- 环境动画不使用脉冲圆环、快速收缩、突然爆亮或强烈方向加速，这些节奏保留给战斗反馈。
- 镜头静止时海面保持生命力但不主动吸引视线；镜头移动时纹理必须稳定存在于世界坐标中，不跟随屏幕漂浮。

#### 2.5.7 AI 生成与纹理制作提示基线

生成海面风格锚点或纹理母版时，提示词至少包含以下正向约束：

```text
fixed orthographic top-down 2D anime naval battle ocean,
stylized illustrated water surface, broad low-frequency teal and navy color masses,
sparse tapered curved wave strokes, restrained cool-white glints,
clean cel-shaded color organization with soft painted transitions,
low contrast, low visual noise, calm negative space, seamless-texture-friendly
```

同时包含以下负向约束：

```text
no horizon, no perspective convergence, no ships, no characters, no islands,
no coastline, no UI, no text, no tactical circles, no projectile trails,
no photorealistic water, no PBR reflections, no dense foam,
no repeating fish-scale pattern, no full-screen diagonal bands,
no saturated red, orange, yellow or neon cyan accents
```

生成图只作为风格锚点或纹理母版，不直接视为可平铺成品。进入运行时前必须完成无缝化、降噪、重复图案检查、灰度层级检查和与当前角色/特效的叠加验收。

#### 2.5.8 风格验收样本与判定

海面定稿至少使用以下当前资产类型作为叠加样本：

- 浅色高明度角色：厌战等金白、蓝白配色角色。
- 深色低明度角色：大和、兴登堡等深蓝、黑铁、深红配色角色。
- 轻量高动态角色：雪风、岛风等驱逐战场单位。
- 横向宽轮廓单位：企业、百眼巨人等航母和飞行甲板舰装。
- 公共战斗色：青白水体特效、金黄炮焰、红橙预警、黄色航空区域和紫色技能提示。

验收标准：

- 在 1080p 战场尺寸下，角色发型、脸部主色块、舰装外轮廓和炮口方向不被海面吞没。
- 将画面缩小到 50% 观察时，第一眼先看到角色和功能信息，第二眼才感知海况和波纹。
- 将同一海面连续铺设到至少两倍屏幕宽高后，不出现明显接缝、重复亮斑、规则条带或固定图章。
- 晴昼、多云、暮色在不显示文字标签时可以通过明度、云影和色温区分，但仍能被识别为同一游戏、同一套海面材质。
- 青白波纹不被误认为航迹、声呐或防空圈；暖色反光不被误认为炮火、命中或危险警告。
- 在 1080p、1440p 和 4K 下保持相同视觉密度，不因分辨率提高而增加小波纹数量或扩大高光覆盖率。

## 3. 战场构图与安全区

### 3.1 基准分辨率

画面设计以 1920 x 1080 为逻辑基准，最高目标分辨率为 3840 x 2160。两者均为 16:9，4K 模式原则上保持与 1080p 相同的世界取景范围和 UI 构图，仅提高渲染精度、纹理清晰度和文字质量，不因分辨率提高而显示两倍战场范围。

分辨率规则：

- 1920 x 1080 是布局、字号、线宽和特效尺寸的基准。
- 2560 x 1440 和 3840 x 2160 按统一 UI 缩放规则适配。
- UI 图标、战术图形和文字优先使用 SVG、SDF、程序绘制或高分辨率源文件。
- 海面纹理、云影和环境遮罩使用可平铺资产，不制作单张 4K 全地图背景。
- 像素线宽、描边和警告图形设置最小屏幕尺寸，避免 4K 下显得过细。
- 非 16:9 窗口优先保持安全区和可读性，多余区域显示更多海面，不拉伸资产。

基准布局建议：

| 区域 | 建议范围 | 用途 |
| --- | --- | --- |
| 顶部信息区 | 高 84-108 px | 关卡名、计时、暂停和战斗状态 |
| 主战场区 | 约 1792 x 840 px | 海面、天气、单位和战斗表现的主要承载区 |
| 左右边缘安全区 | 各 48-64 px | 防止单位、标记和特效贴边 |
| 底部操作区 | 高 120-156 px | 舰娘头像、技能、编队和消息反馈 |

主战场不应被厚重装饰边框包围。边界使用低亮度战术线、雾化渐隐或轻微深色压边表达，不能像实体墙一样误导玩家。

### 3.2 地图与可见区域

- 地图宽度和高度原则上均不低于当前可见战场区域的 2 倍，地图面积明显大于单屏画面。
- 进入战斗时，镜头中心对准玩家阵营初始编队中心。
- 初始镜头保持静止，不自动追随旗舰、战斗焦点、投射物或敌方单位。
- 开局时玩家阵营初始编队中心与画面中心对齐；“玩家在下、敌方在上”指地图部署方向，不通过额外镜头偏移改变。
- 敌方初始编队位于地图上部，通常不会在开局时与玩家舰队同时完整出现在同一屏幕内。
- 海面底图、波纹、云影和装饰必须支持跨越多屏连续移动，不得暴露拼接边界。
- 地图实际边界与屏幕边缘分离；只有镜头移动至地图边缘时，才显示对应的战场边界反馈。

### 3.3 场景可读性约束

场景层始终低于角色、战斗表现和 UI 的视觉优先级。海面、天气、边界和陆地可以提供氛围与空间，但不能抢占玩家对单位轮廓、操作提示、危险预警和 HUD 的识别。

场景侧约束：

- 环境层不得使用高饱和红色、橙色、黄色和紫色作为小面积亮点。
- 海面和天气不得形成长直线、完整圆环、扇面、锁定框、箭头或规则网格。
- 云影、雨线、雪雾、岸线白沫和浅水边缘的对比度必须低于主要角色轮廓。
- 复杂天气或 11v11 高负载时，天气层优先降透明度或降密度，而不是压低角色/UI。

## 4. 场景分层结构

推荐 Godot 场景层级：

```text
BattleScene
  OceanBase
  OceanDepthPattern
  LargeWaveLayer
  SmallWaveLayer
  FoamAndCurrentLayer
  WeatherShadowLayer
  WeatherParticleLayer
  WeatherFlashLayer
  LandAndIslandLayer
  ShorelineFoamLayer
  SceneBoundaryLayer
  BattleUnits
  ProjectileLayer
  SurfaceImpactLayer
  AirUnitLayer
  TacticalOverlayLayer
  ScreenVFXLayer
  BattleUILayer
```

### 4.1 海面底色层

- 使用低频渐变表达海水深浅，避免写实海底地形。
- 使用屏幕空间的轻微中心提亮和边缘压暗，为当前镜头区域提供自然聚焦；该效果随镜头移动，不烘焙在地图固定位置。
- 基础色相保持蓝青范围，关卡变体通过 LUT、叠色和天气层调整。
- 不在基础底图中画固定浪花、船影或明显方向性物体，以便重复铺设和镜头移动。

### 4.2 海浪纹理层

海浪分为三种尺度：

- 大尺度：缓慢移动的深浅色块，表达海水体积和整体流向。
- 中尺度：稀疏弧形波纹，提供方向感和速度参照。
- 小尺度：短线高光与碎波，只在局部出现，控制画面噪声。

建议使用可平铺纹理、Shader UV 流动和少量粒子组合，不使用长序列帧铺满全屏。

### 4.3 天气层

天气层独立于海面 Shader 和战斗 VFX，位于海面纹理之上、单位与战术叠层之下。它只负责云影、雨幕、雪幕、雾化、风暴暗云和闪电环境光，不承载命中、侦查、伤害、潜航或警告信息。

天气层拆为三类节点：

| 子层 | 内容 | 层级约束 |
| --- | --- | --- |
| `WeatherShadowLayer` | 云影、厚云、风暴暗云、雪云压暗 | 世界坐标铺设，随镜头移动保持连续 |
| `WeatherParticleLayer` | 雨线、雨点涟漪、雪粒、雪雾、风纹 | 屏幕空间或世界空间均可，但必须低于 UI 和战术叠层 |
| `WeatherFlashLayer` | 雷雨闪电冷白环境光、短时云层亮边 | 只做短促环境照亮，不改变角色贴图本体颜色 |

### 4.4 陆地与岸线层

陆地层是海面之上的独立场景模块，MVP 开阔海域默认关闭。后续关卡启用时，应由 `LandAndIslandLayer`、`ShorelineFoamLayer` 和必要的碰撞/遮挡数据共同组成。

- 陆地不直接烘焙进海面底图，必须可按关卡单独开关、替换和移动。
- 岸线泡沫、浅水过渡和礁石高光属于场景层；岸防炮、港口目标、占点图标和敌方设施属于后续玩法/战斗/UI 文档。
- 陆地轮廓必须清楚表达不可通行区域，不用纯装饰岛屿误导玩家。
- 正俯视下不制作高透视山体、地平线或远景岸线。
- 岛屿阴影和岸线高光不得遮挡角色底环、路径、范围提示和小地图信息。

### 4.5 场景边界层

战场边界属于场景承载，不等同于 UI 画外提示：

- 默认使用低亮青灰虚线、暗化水纹或雾化渐隐。
- 靠近边界时增加轻微压暗和水纹密度变化，不使用持续闪烁红框。
- 边界不是实体设施，不绘制浮标墙、铁链、港口结构或真实国旗。
- 单位触边、危险画外提示和小地图边框由 UI/战术叠层表达，见 `docs/44_ui_art_design.md`。

## 5. MVP 海域方案

MVP 使用同一套海面模块制作三种场景变体。三种场景不改变碰撞、遮挡或战斗规则，只改变情绪、明度和局部环境动效。

### 5.1 晴昼训练海域

用途：1v1 教学、首次操作、基础战斗验证。

视觉方向：

- 明亮青蓝海面，中心区域通透。
- 稀疏白色碎波，风浪较小。
- 云影少，整体对比稳定。
- 战场边界清楚但柔和。
- 友方蓝、敌方红和黄色警告均能直接辨认。

色彩建议：

| 用途 | 色值建议 |
| --- | --- |
| 深水底色 | `#123E59` |
| 主海面 | `#1E6982` |
| 浅层反光 | `#4DA8B5` |
| 浪尖高光 | `#B7E4E5` |
| 边缘压暗 | `#0D2B40` |

环境动态：慢速波纹、少量闪光、短而清晰的航迹。

### 5.2 多云标准海域

用途：3v3 标准关、主要平衡测试场景。

视觉方向：

- 海面比训练海域更深，加入大块缓慢云影。
- 中等风浪，波纹方向更明显。
- 局部明暗变化增加战斗氛围，但角色始终保持稳定可读。
- 炮烟、水柱和航空路径在深色背景上更突出。

色彩建议：

| 用途 | 色值建议 |
| --- | --- |
| 深水底色 | `#102F45` |
| 主海面 | `#24566B` |
| 云影区 | `#183D50` |
| 波纹高光 | `#75B8C2` |
| 边缘压暗 | `#0A2436` |

环境动态：中速波纹、云影、少量风纹和远处白沫。

### 5.3 暮色压力测试海域

用途：5v5 至 11v11、大规模战斗和旗舰决战验证。

视觉方向：

- 蓝灰暮色海面，加入低饱和暖色天光反射。
- 环境整体更暗，但单位脚下保留轻微局部提亮。
- 火炮、鱼雷、航空和技能特效具有更强舞台感。
- 不使用纯黑夜战，避免 11v11 时信息丢失。

色彩建议：

| 用途 | 色值建议 |
| --- | --- |
| 深水底色 | `#17283B` |
| 主海面 | `#29485C` |
| 暮色反光 | `#936B68` |
| 波纹高光 | `#7795A3` |
| 边缘压暗 | `#0B1726` |

环境动态：较宽波纹、低速云影、间歇暖色反光。大规模战斗时自动降低环境粒子密度。

### 5.4 气候与时间效果设计方案

完整海面变体采用“时间色板 + 气候渲染剖面”的组合方式制作。时间决定海面基底色、整体明度、色温和反光方向；气候不能只改变色调，必须改变环境渲染结构，包括云团尺度、云影硬度、风浪频率、白沫覆盖、雨线角度、雨线密度、雨点涟漪、雾化和雷雨暗云。二者组合后形成 5 种气候 x 4 个时间段的效果矩阵，但运行时仍应复用同一套海面 Shader、波纹遮罩、云影遮罩和天气粒子，不制作 20 张独立大背景。

本方案只作为场景视觉表现，不改变命中、侦查、移动、射程或任何战斗规则。雨、雷雨和夜间会降低环境明度，但必须通过局部补光、降噪和天气层透明度控制保证角色、舰装、路径和 UI 可读。

#### 5.4.1 时间参数

| 时间 | 海面基调 | 明度与色温 | 反光与高光 | 可读性约束 |
| --- | --- | --- | --- | --- |
| 白天 | 清澈蓝青、浅青反光 | 明度最高，色温偏冷，水体通透 | 冷白短高光较清楚，小浪尖可见 | 不出现大面积接近纯白的反光，避免吞掉白发和浅色服装 |
| 凌晨 | 较浅青蓝、晨雾青、少量浅金 | 明度中高，色温清新，表现新一天开始的欣欣向荣感 | 高光柔和但更明亮，海面有轻薄晨光和舒展感 | 不做阴冷黎明；雾感必须轻，不能把凌晨做成低亮阴天 |
| 黄昏 | 暗蓝紫底、黄红橙反光、沉暖灰 | 明度中低，色温偏暖且昏沉，强调日落后的压迫感 | 暖色反光更宽、更浑浊，局部偏黄红，但不形成炮火亮点 | 暖色可作为大面积氛围反射，避免小面积高饱和橙红被误认为警告 |
| 夜间 | 深海军蓝、墨青、少量月光灰蓝 | 明度最低，色温偏冷，保留蓝灰层次 | 高光极少，使用细月光波纹和局部冷白浪尖 | 不使用纯黑海面；角色脚下与地图中心需有轻微环境补光 |

| 气候 | 云影与天空感 | 风浪与纹理 | 天气粒子 | 设计边界 |
| --- | --- | --- | --- | --- |

| 多云 | 大块软云影缓慢移动，云团比晴朗更密 | 中等风浪，水体明暗变化更明显 | 无雨，可有少量风纹 | 当前标准海域的主要扩展基准 |
| 阴云 | 云影覆盖高，边缘更硬，局部暗云压低画面 | 风浪偏大，波纹更宽，白沫略增 | 无雨或极少预雨粒子 | 情绪压迫但不遮挡单位，避免全屏灰黑 |

| --- | --- | --- | --- | --- |
| 晴朗 | 训练海域基准：明亮青蓝、短白浪尖、低云影，最适合新手关和资产验收。 | 晴朗晨光海：较浅青蓝底、浅金晨光、轻薄雾感，氛围清新、有恢复感。 | 晴朗昏沉海：暗蓝紫底配黄红橙反光，保留清爽海面但带明显日落压暗。 | 晴朗月夜海：深蓝底、少量月光碎线、中心轻微补光，用于夜间可读性验证。 |

#### 5.4.4 参数化制作规则

- 时间参数至少包含：`base_deep_color`、`base_shallow_color`、`highlight_color`、`ambient_tint`、`center_light_strength`、`edge_vignette_strength`、`reflection_color`、`reflection_strength`。凌晨色板应偏浅、偏亮、偏清新；黄昏色板应偏黄红、偏浑浊、偏昏沉。
- 气候剖面参数至少包含：`cloud_shadow_strength`、`cloud_scale`、`cloud_cutoff`、`cloud_softness`、`wave_scale`、`foam_density`、`foam_coverage`、`rain_angle`、`rain_density`、`rain_line_strength`、`rain_ripple_strength`、`mist_strength`、`squall_strength`、`lightning_enabled`、`lightning_interval`。
- 组合时先应用时间色板，再叠加气候强度。夜间、雨和雷雨需要额外启用可读性保护：降低小波纹密度、减弱雨线不透明度、提高单位附近的环境分离度。
- 晴朗、多云、阴云三类必须在云影尺度、风浪尺度和白沫覆盖上产生差异；雨和雷雨再追加斜向雨线、落点涟漪、轻雾、风暴暗云和闪电层。
- 正式天气层必须使用独立母版资源：晴朗波光、多云云影、阴云厚云、白沫风纹、雨线、雨点涟漪、风暴暗云和闪电冷光遮罩，不再只依赖程序噪声占位。
- 闪电只影响海面和云影层的短时亮度，不改变角色资产本体颜色，不产生持续残留。
- 所有时间与气候变体都必须沿用 2.5 节的海面形状语言：低噪声、低饱和、短弧波纹、稀疏高光、正俯视无地平线。

#### 5.4.5 推荐落地优先级

第一阶段保留当前已实现的晴朗白天、多云白天和黄昏多云/暮色基准。第二阶段优先补齐阴云白天、白昼雨海、夜间晴朗和夜间雷雨四个代表性差异样本，用于验证最亮、最暗、雨幕和闪电四类边界。第三阶段再将全部 20 个组合补齐为参数资源，并通过同一截图模板做 1080p、1440p 和 4K 对比验收。

## 6. 独立天气层设计

天气层不是海面 Shader 的附属噪声，也不是战斗特效。它是位于海面之上、单位和战术叠层之下的独立环境模块，用来表达云、雨、雷、雪、雾和风浪情绪。天气层可以随关卡配置切换，也可以在运行时被暂停、减弱或关闭，但不得改变命中、侦查、移动、射程或 AI 行为。

### 6.1 天气层资产母版

所有天气母版必须由 `gpt-image-2` 生成或由已生成母版后处理得到，进入运行时前统一裁切、降噪、透明化、灰度检查和 1024 x 1024 标准化。禁止使用临时占位线条或纯程序噪声伪装成最终天气资源。

| 天气类型 | 必需母版 | 用途 |
| --- | --- | --- |
| 晴朗 | 晴朗波光、少量冷白闪光遮罩 | 表达明亮、干净、低云影海况 |
| 多云 | 软云影遮罩、大块云团明暗遮罩 | 表达云团经过和局部明暗 |
| 阴云 | 厚云遮罩、低云压暗遮罩 | 表达沉稳、压迫和低亮天空感 |
| 雨 | 斜向雨线、雨点涟漪、薄雾雨幕 | 表达明确降雨和海面落点 |
| 雷雨 | 风暴暗云、强风白沫、闪电冷光遮罩 | 表达短时闪光、强风浪和高压暗云 |
| 雪 | 雪粒飘落、雪雾/风雪遮罩、冷白积云 | 用于寒冷海域和后续雪天关卡 |

当前已接入的正式母版位于 `assets/environment/weather/`，包含晴朗波光、多云云影、阴云厚云、白沫风纹、雨线、雨点涟漪、风暴暗云、闪电冷光遮罩、雪粒和雪雾遮罩。

### 6.2 云层

- 云影使用大面积、低对比、软边遮罩缓慢移动。
- 晴朗云影极少，只用于轻微层次；多云云影更宽、更软；阴云和雷雨可使用更高覆盖率和更低明度。
- 云影通过乘色或低透明叠色影响海面，不改变角色、舰装和 UI 本体色。
- 云团边缘避免形成完整圆圈、箭头、范围圈或锁定框形状。
- 云层移动速度应慢于海面小波纹，单次横穿 1080p 画面不少于 20 秒。

### 6.3 雨层

- 雨线使用独立透明母版，按天气配置控制角度、密度、长度和透明度。
- 白昼雨线可以更细更浅；夜雨雨线更明显但透明度更低，防止遮挡单位轮廓。
- 雨点涟漪只出现在海面，不能覆盖 HUD、头像、血条和战术标记。
- 雨幕可轻微增加雾化，但不做持续遮挡单位的大雾。
- 雨层在玩家瞄准、危险预警、结算面板出现时允许临时降透明度。

### 6.4 雷雨层

- 雷雨由厚云、强风浪、密雨、风暴暗云和闪电短时照亮组成，不使用红橙危险色表达。
- 闪电使用冷白或淡蓝白，只影响环境层短时亮度和云层边缘。
- 闪电频率必须低，避免高频闪烁造成疲劳；单次闪光应在 80-180 ms 内完成主峰并快速衰减。
- 雷雨夜间是最暗组合，但仍必须保留中心补光、角色脚下分离度和海面蓝灰层次。
- 任何闪电形状不得像技能光柱、炮击落区或目标锁定线。

### 6.5 雪层

雪层用于后续寒冷海域，不纳入当前 5 气候 x 4 时间的 20 个基础组合，但运行时天气模块需要预留资源位和参数。

- 雪粒使用稀疏、大小不一、轻微拖尾的冷白透明母版，避免像 UI 星点或命中火花。
- 雪雾使用低对比蓝白软遮罩，只改变环境氛围，不遮挡角色脸部、舰装炮口和单位底环。
- 海面可追加极少量冷白碎纹和风雪扫过的短线，但不制作大片积雪海面，避免误导为陆地。
- 雪天不使用纯白全屏雾，也不让浅色角色失去轮廓。
- 若后续加入冰缘、浮冰或冻结水面，应归入陆地/障碍场景模块，不能仅作为天气层贴图处理。

### 6.6 天气参数接口

天气层参数应与海面时间色板分离：

| 参数 | 含义 |
| --- | --- |
| `weather_cloud_texture` | 云影、厚云或风暴暗云母版 |
| `weather_rain_line_texture` | 雨线母版 |
| `weather_rain_ripple_texture` | 雨点涟漪母版 |
| `weather_foam_texture` | 风纹、白沫和强风浪遮罩 |
| `weather_lightning_texture` | 闪电冷光遮罩 |
| `snow_flake_texture` | 雪粒母版 |
| `snow_haze_texture` | 雪雾/风雪遮罩 |
| `cloud_shadow_strength` | 云影压暗强度 |
| `rain_line_strength` | 雨线可见强度 |
| `rain_ripple_strength` | 雨点涟漪强度 |
| `storm_strength` | 风暴暗云和强风压暗强度 |
| `lightning_strength` | 当前闪电强度，由运行时脉冲控制 |
| `snow_strength` | 雪粒强度 |
| `snow_haze_strength` | 雪雾强度 |

海面 Shader 可以读取部分天气纹理参与反光和涟漪，但正式视觉输出应由独立天气层完成，避免所有气候差异只停留在海水调色上。

## 7. 陆地与岛屿层设计

陆地层是海面基础上的独立场景扩展，用于后续非开阔海域关卡。它不属于当前 MVP 开阔海域默认交付，但从设计上必须先明确资产样式、分层方式和十类可复用构图，避免以后把岛屿直接画死在海面背景里。

### 7.1 陆地层通用规则

- 陆地资产使用正俯视 2D 插画风格，轮廓清楚，色彩饱和度低于角色、高于海面。
- 每个陆地块至少拆为陆地底色、岸线泡沫、浅水过渡、礁石/沙洲细节和阴影遮罩。
- 陆地成品必须为透明 PNG，背景剔除后保留岛体、浅水边缘、白沫和必要阴影，不保留整张海面背景。
- 碰撞、遮挡、寻路、射线阻挡等玩法数据独立配置；可以从 alpha 边缘生成初始候选多边形，但正式关卡启用前必须人工审查和调校。
- 岛屿边缘必须有浅水青绿过渡和少量白沫，帮助玩家理解不可通行边界。
- 岛屿内部不绘制大量高对比建筑、炮塔或旗帜，避免与角色和目标点抢焦点。
- 大面积陆地不得覆盖玩家初始中心画面；开局镜头仍应以己方阵营中心和可航行海域为主。

### 7.2 十类陆地样式

| 样式 | 构图描述 | 场景用途 |
| --- | --- | --- |
| 双岛长海峡 | 左右两块长岛夹出中间纵向海峡，上下保持通航 | 验证中线遭遇、侧翼绕行和海峡宽度可读性 |
| 散岛群 | 多个小岛分散在中部和两翼，彼此间留出多条航道 | 验证复杂机动和局部遮挡 |
| 环岛泻湖 | 环形岛链包围中央水域，留 2-3 个开口 | 验证围绕中心目标的交战空间 |
| 新月岛 | 单侧弧形大岛包住一片浅水湾 | 制造单侧安全边与绕后路线 |
| 中央沙洲 | 中央低矮沙洲和浅水带，岛体高度低、遮挡少 | 适合轻量障碍和视觉变化 |
| 双航道礁线 | 两条斜向礁石/浅滩分割地图，形成平行航道 | 验证队形通过和远程火力视线 |
| 港湾入口 | 下方或上方有半包围港湾陆地，但不出现港口建筑玩法 | 用于后续防守/突围氛围 |
| 破碎环礁 | 多块礁石围出不完整圆形，边缘有浅水和白沫 | 比环岛更轻、更自然的障碍 |
| 大岛偏置 | 一块大岛偏左或偏右，另一侧是开阔海 | 让地图形成明显强弱侧 |
| 细长群岛 | 多条纵向或横向细长岛链，像天然航道标尺 | 适合高速舰队穿插和镜头移动验证 |

### 7.3 陆地资产母版

第一批陆地母版建议不直接生成完整关卡背景，而生成可组合模块：

- 深色岩岸块。
- 浅色沙岸块。
- 青绿浅水过渡带。
- 岸线白沫透明遮罩。
- 暗礁和礁石点缀。
- 小型植被或低饱和地表纹理。
- 岛体投影/压暗遮罩。
- 可无缝拼接的沙洲边缘。

陆地母版可以使用 AI 生成后进行透明切图和模块化处理；正式关卡组合应由程序或编辑器摆放，避免单张大图限制地图尺寸、镜头移动和 4K 清晰度。

### 7.4 陆地资产后处理与碰撞边缘

当前陆地母版位于 `assets/environment/land/`，使用 imagegen 生成纯色背景源图，再通过 chroma-key 去背景得到透明 PNG。源图保存在 `assets/environment/land/source/`，正式运行资产保存在 `assets/environment/land/land_*.png`。

碰撞边缘判定规则：

- 以透明 PNG 的 alpha 通道作为初始边缘来源，默认 `alpha >= 24` 视为陆地/浅滩组件。
- 连通区域面积小于阈值的碎点不进入碰撞候选，避免小泡沫点造成不可通行噪声。
- 每个连通组件生成一个候选碰撞多边形，默认最多保留 72 个顶点。
- 碰撞多边形记录在 `assets/environment/land/land_collision_manifest.json`，只作为关卡编辑初始数据。
- 真正启用碰撞、寻路或视线遮挡前，必须按玩法需求将候选边缘拆分为 `blocking_polygon`、`shallow_water_cost_polygon`、`visual_only_foam` 等语义层，不能直接把所有白沫和浅水 halo 当成硬障碍。

## 8. 场景色彩与功能避让

场景环境色与功能色必须分离。完整 UI 色板与功能色见 `docs/44_ui_art_design.md`；战斗特效色见 `docs/42_combat_art_design.md`。场景侧只遵守避让规则：

- 环境不使用高饱和红、橙、黄、紫作为小面积亮点。
- 暮色和雷雨允许大面积低饱和暖色或冷白环境光，但不能形成技能、炮火或危险警告形状。
- 云、雨、雪、白沫和岸线高光不画成长直线、完整圆圈、扇面或锁定框。
- 场景最高对比度应低于角色轮廓、危险预警和主要操作提示。
- 天气层在 UI 密集、预警密集或 11v11 高负载时允许自动降透明度。

## 9. 材质、纹理与动画规范

### 9.1 海面纹理

- 可平铺纹理建议为 512 x 512 或 1024 x 1024。
- 同一纹理四边必须无明显接缝。
- 避免大面积高频噪点、规则重复的鱼鳞纹和明显摄影水印感。
- 高光纹理使用独立 alpha，便于调整海况和性能档位。
- 波纹方向不应强到让玩家误判单位航向。

### 9.2 动画节奏

- 海面大纹理循环：12-24 秒。
- 小波纹和闪光循环：4-8 秒，并使用随机相位避免同步。
- 云影通过缓慢平移完成，单次横穿画面不少于 20 秒。
- 环境动画在暂停时减速到 0-20%，并与战斗/UI 暂停状态保持同步。

### 9.3 透明与混合

- 云影、雨线、雪雾、白沫和岸线高光使用透明 PNG、灰度遮罩或程序材质。
- 场景雾化避免纯黑；使用深蓝灰、低饱和暖灰或冷白蓝适配海面。
- 发光素材保留透明边缘，禁止白底、黑底和明显矩形边界。
- Add 混合只用于短暂闪电、波光和极少量浪尖；云影、雨幕和雪雾使用 Alpha 或乘色混合。

## 10. 镜头移动规则

MVP 使用固定正俯视角度和统一世界显示比例。镜头只在地图平面内平移，不旋转；MVP 默认不依赖自由缩放来完成战术观察。

### 10.1 初始镜头

- 战斗开始时以玩家阵营初始编队中心作为镜头中心。
- 镜头加载完成后保持静止，不因己方单位自动移动而自行漂移。
- 初始构图让己方初始编队中心与画面中心对齐。
- 若玩家阵型宽度超过安全区，保持编队中心对齐，不通过自动缩放或持续镜头移动改变构图。
- 场景层不因天气、波纹或陆地动效擅自切换镜头目标。

### 10.2 手动移动模式

- 玩家使用 `WASD` 在地图平面移动镜头。
- `W` 向地图上方移动，`S` 向地图下方移动，`A` 和 `D` 分别向左、右移动。
- 镜头移动不改变上下阵营方向，也不旋转海面、天气或陆地。
- 启动手动移动时退出舰船跟随模式，镜头停在玩家最后移动到的位置。
- 镜头接近地图边界时平滑减速并停止，禁止露出地图外空白区域。
- 手动移动期间，屏幕空间 UI 保持固定；场景层只负责世界坐标连续性。

### 10.3 己方舰船跟随模式

- 玩家可以选择任意存活的己方舰船作为镜头跟随目标。
- 跟随时以目标舰船为镜头中心，保持固定正俯视角度和固定显示比例。
- 镜头使用平滑插值跟随，避免航向微调和受击位移造成连续抖动。
- 目标舰船接近地图边界时允许舰船偏离画面中心，以防镜头越出地图范围。
- 跟随目标沉没、失效或离开战场时，镜头停在最后有效位置并退出跟随模式。
- 切换另一艘己方舰船时使用短距离平滑过渡；距离过大时可快速淡出再定位，避免高速横穿整张地图。
- 跟随模式不由场景事件自动切换目标。

### 10.4 画外信息承载

地图大于单屏范围，因此画外单位、危险和目标提示由 `docs/44_ui_art_design.md` 定义。场景层只需要保证地图边缘、天气层和陆地层不会遮挡屏幕边缘安全区，也不会通过环境图案伪装成画外方向提示。

### 10.5 高分辨率与性能降级

- 1080p、1440p 和 4K 保持相同镜头逻辑与世界取景范围。
- 4K 提高海面、天气和陆地纹理采样质量，不增加环境粒子数量。
- 大规模战斗中优先简化远离镜头中心的碎波、云影细节、雨线密度、雪粒密度和次要白沫。
- 画外区域不继续绘制高密度天气粒子，只保留必要的海面连续性。
- 场景降级不能影响 UI 与战斗层的可读性。

## 13. 场景制作与验收流程

### 13.1 制作顺序

1. 制作晴昼训练海域色稿，验证角色、功能色和海面承载可读性。
2. 完成海面基础纹理、大中小波纹和边缘压暗。
3. 接入独立天气层，验证云影、雨线、雷雨闪光和雪层预留参数。
4. 扩展多云、阴云、雨、雷雨和四个时间色板，复用基础海面资产。
5. 生成 20 种时间 x 气候总览图，检查差异度、可读性和 4K 适配。
6. 在 11v11 场景验证天气透明度、海面粒子密度和性能降级。
7. 后续制作陆地层模块和 10 种岛屿/陆地构图样张。

### 13.2 验收检查

- 3v3 固定正俯视镜头下，角色发型、主色块和舰种轮廓仍可辨认。
- 11v11 战斗中，天气层、云影和海面高光不会遮挡主要角色轮廓和战术叠层。
- 开局镜头正确定位在己方阵营中心，且在未输入操作时保持静止。
- `WASD` 手动移动与己方舰船跟随模式切换明确，镜头不会越过地图边界。
- 玩家阵营始终位于地图下方方向，敌方阵营始终位于地图上方方向。
- 海面纹理无明显平铺接缝和重复图案。
- 云影、雨线和波纹不会被误认为移动路径、射程或攻击预警。
- 晴朗、多云、阴云、雨和雷雨在云团、波浪、白沫、雨点、风暴和闪电上具有结构差异，而不只是色调差异。
- 凌晨组合较浅、较亮、清新；黄昏组合黄红、昏沉、低饱和，不与炮火和危险警告混淆。
- 雪层资源关闭时不影响 20 个基础组合；启用时不把海面误读为陆地。
- 透明素材无白底、黑边、矩形残留或过紧裁切。
- 1920 x 1080 至 3840 x 2160 下，天气密度、海面纹理密度和边界反馈保持一致。

## 14. MVP 明确不做

- 岛屿、礁石、陆地、港口和海岸炮台。
- 会影响碰撞、侦查或弹道的天气系统。
- 写实昼夜循环、实时反射和高成本全屏流体模拟。
- 随航向变化的完整角色环境光重绘。
- 为每个关卡制作独立不可复用的大幅场景插画。
- 持续遮挡单位的大雨、浓雾、巨浪和全屏烟尘。
- 需要玩家辨认真实国旗、政治符号或历史敏感标识的场景装饰。

## 15. 后续扩展方向

MVP 验证完成后，可按玩法系统逐步扩展：

- 岛屿海域：新增浅水、礁石、岸线、遮挡阴影和碰撞反馈。
- 突围模式：新增撤离边界、航道、封锁线和目标方向标识。
- 占点模式：新增浮标、控制区域、占领进度和阵营染色。
- 非对称海战：新增大型敌方单位、岸防设施和阶段性环境破坏。
- Roguelike 海图：新增路线节点、事件海域、天气预览和关卡缩略图。
- 港口与基地：在养成、剧情和角色交互需求明确后单独制定场景规范。

扩展场景必须继续遵循同一原则：环境负责情绪与空间，角色负责记忆点，战术叠层负责规则信息，三者不能互相替代。
