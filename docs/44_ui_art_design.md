# UI 美术设计文档

## 1. 文档目标

本文档定义 Tiny Sea War MVP 阶段的 UI 美术方向、信息层级、通用组件、战斗 HUD、战场叠层、弹窗、动效、适配和资产交付规范。

UI 的首要目标不是填满屏幕，而是在 1v1、3v3 直至 11v11 的开阔海域战斗中，让玩家快速读取舰队状态、自动控制状态、已知敌情和关键战果，同时尽量保留中央战场观察面积。

角色头像、半身立绘、技能图标和舰种图标遵循 `docs/40_art_direction_design.md`；战术范围、武器预警和命中特效遵循 `docs/42_combat_art_design.md`；海面、镜头和场景安全区遵循 `docs/43_scene_art_design.md`。

## 2. MVP 范围与边界

### 2.1 MVP 必需界面

- 战斗 HUD。
- 开场主菜单。
- 模式选择 UI。
- 操作说明 UI。
- 游戏介绍 UI。
- 战场单位血条、选中、锁定、旗舰、侦查和潜航标记。
- 顶部战斗状态与自动控制栏。
- 双方舰队头像栏。
- 战术小地图。
- 战况滚动栏。
- 选中舰娘信息栏。
- 暂停面板。
- 胜利与失败结算面板。
- 通用按钮、标签、进度条、提示框和状态图标。

### 2.2 MVP 暂不制作

- 主城、宿舍和基地经营界面。MVP 开场 UI 只承担模式选择、说明和进入战斗，不承担主城功能。
- 抽卡、商店、付费和活动运营界面。
- 完整养成、装备仓库和图鉴界面。
- 复杂战前编队编辑器。
- 可自由拖拽并保存位置的桌面式 HUD 编辑器。

非 MVP 界面后续应继续复用本文定义的颜色、边框、图标和动效语言，避免形成第二套视觉体系。

## 3. 设计原则

### 3.1 战场优先

- 中央战场不放常驻大面板。
- UI 主要停靠在屏幕边缘和四角。
- 面板使用半透明浅色磨砂底和柔和蓝灰投影，保持明亮感，同时避免海面纹理穿透后干扰文字。
- 重要危险信息可覆盖战场，装饰信息不得覆盖投射物和预警区。
- 11v11 时优先保留旗舰、低血量、技能可用、已发现敌人和击沉信息。

### 3.2 信息不能只靠颜色

所有关键状态至少同时使用两种表达方式：

- 颜色加图标。
- 颜色加轮廓。
- 明暗加动画节奏。
- 图标加文字或数字。

敌我、可用/不可用、潜航/上浮、存活/阵亡和自动开关不得只通过色相区别。

### 3.3 模块化与可收缩

- 顶部栏、头像栏、小地图、战况栏和选中信息栏均为独立部件。
- 部件可使用统一的边缘锚点、展开箭头和缓动规则。
- 收缩状态必须保留必要摘要，不允许关键状态完全消失。
- 展开和收缩不能改变战场坐标、镜头中心或其他面板的固定边界。

## 4. 视觉语言

### 4.1 风格关键词

- 清爽明亮的海上指挥界面。
- 二次元角色识别。
- 海盐白、晴空蓝和浅青色磨砂面板。
- 圆角卡片、轻量细线、柔和高光和清楚的功能色。
- 轻松但不幼稚，不使用厚重大框包围整屏。

UI 装饰可以使用水波、浮标、航线、罗盘、测距线和抽象海军仪表元素。装饰线条使用圆润端点和较大的留白，不把界面做成严肃的军用终端，也不能复制真实政治或军事徽记。

### 4.2 功能色

| 用途 | 建议颜色 | 规则 |
| --- | --- | --- |
| 主面板底 | `#F7FCFF` | 海盐白磨砂底，透明度建议 88% 到 94% |
| 次级面板底 | `#E8F7FB` | 卡片、悬停区、小地图水域和分组底色 |
| 面板边框 | `#8DD9E8` | 细边框、分隔线和轻量高光 |
| 主文字 | `#244B5A` | 标题、数值和关键说明，避免使用纯黑 |
| 次文字 | `#5A7883` | 标签、帮助和非关键状态 |
| 我方识别 | `#2FBAE6` | 我方轮廓、头像边框、路径和地图图标 |
| 敌方识别 | `#FF7180` | 已发现敌舰、敌方头像和普通锁定提示 |
| 危险警告 | `#E83F5B` | 鱼雷逼近、致命攻击和旗舰危急，不用于普通敌方标记 |
| 选中/聚焦 | `#FFC857` | 当前操作单位、重要提示和选中高光 |
| 目标/集火 | `#FF9F43` | 当前攻击目标和集中火力指令 |
| 自动开启/正向 | `#35C99A` | 自动控制开启、成功反馈和可执行状态 |
| 技能/特殊状态 | `#8A78F0` | 技能就绪、强化状态和特殊指令 |
| 正常生命 | `#45C983` | 高生命值区间 |
| 警戒生命 | `#FFB84D` | 中低生命值区间 |
| 危急生命 | `#F2555A` | 低生命值与濒危状态 |
| 潜航/声呐 | `#5A8EDB` | 氧气、潜航、声呐和水下信息 |
| 未知 | `#9AAEB6` | 未发现身份、最后接触和未知目标 |
| 禁用 | `#C5D2D7` | 不可用按钮、空槽和暂不可执行状态 |

功能色遵循以下关系：

- 我方使用晴空蓝，体现清爽与可靠；在蓝色海面上必须配白色内描边或深青外阴影。
- 敌方使用珊瑚粉，保持对抗感但不让常态战斗持续处于警报氛围。
- 危险警告单独使用更深的警报红，只给需要立即反应的信息。
- 选中使用日光黄，目标使用橙色，避免把“我正在操作”和“我正在攻击”混为一谈。
- 自动开启和成功状态使用薄荷绿；技能与特殊强化使用紫罗兰，避免所有正向状态都挤在蓝绿色区域。
- 阵营色只作为角色卡角标和技能演出点缀，不替代统一的敌我功能色。
- 大面积面板只使用低饱和浅色，高饱和颜色仅用于图标、细边框、进度和短时反馈。
- 功能色按钮优先使用“浅色染底 + 高饱和图标 + 深青文字”，不把白字直接放在晴空蓝、薄荷绿或日光黄底上。
- 普通正文与背景的对比度目标不低于 4.5:1；大号标题和非文字图形不低于 3:1。

### 4.3 字体与数字

- 中文正文优先使用清晰的无衬线字体。
- 战斗计时、冷却和生命数值使用等宽数字或稳定字宽，避免刷新时跳动。
- 伤害跳动数字使用运行时字体和描边生成，不使用预烘焙数字贴图；不同武器类别通过字号、颜色、描边和动效区分。
- 1920 x 1080 下正文建议 18 到 22 px，次级标签 16 到 18 px，重要计时 28 到 36 px。
- 浅色面板上的文字使用深青色；直接覆盖海面的文字增加白色内描边与深青外阴影，保证在晴昼、多云和暮色海面上都可读。
- 功能色主要承担状态，不替代正文颜色；危险按钮如需反白文字，应使用经过加深的危险底色并单独检查对比度。
- 不把长段文字放入战斗 HUD；战况使用短句和图标组合。

### 4.4 边框与材质

- 面板外框使用 1 到 2 px 浅青细线、圆角和少量软切角，不使用大面积金属浮雕。
- 面板可加入顶部偏白高光和底部浅蓝投影，形成轻薄的漂浮卡片感。
- 选中状态增加日光黄色外描边和轻微呼吸光，不改变卡片尺寸。
- 面板内部以分隔线组织信息，减少独立小框数量。
- 可拉伸面板使用九宫格或程序绘制，保证不同分辨率下边角不变形。
- 面板阴影使用透明蓝灰，不使用纯黑硬阴影。

## 5. 分辨率、缩放与安全区

### 5.1 基准设置

- 逻辑基准：1920 x 1080，16:9 横屏。
- 窗口尺寸变化只改变物理输出尺寸；根窗口始终使用 1920 x 1080 逻辑画布，以 `Canvas Items` 模式等比缩放并保持宽高比，禁止按物理像素裁切界面。
- 目标输出：1920 x 1080、2560 x 1440、3840 x 2160。
- 开始界面提供窗口尺寸设置，当前候选为 1280 x 720、1600 x 900、1920 x 1080、2560 x 1440、3840 x 2160；候选值由表现设置配置提供。
- 4K 模式保持相同 UI 构图和世界取景，提升清晰度，不把面板物理尺寸缩小一半。
- UI 图标和战术图形优先使用 SVG、SDF、程序绘制或至少 2 倍分辨率源文件。

### 5.2 安全区

- 屏幕四周保留 48 到 64 px 基础安全边距。
- 顶部收缩栏、左下小地图和右下选中栏使用固定边缘锚点。
- 重要战场单位、技能落区和画外警告不得长期停留在 HUD 遮挡区。
- 面板展开时允许覆盖边缘战场，但中央约 60% 的主要观察区域应保持无遮挡。

### 5.3 小屏与窄屏降级

- 优先缩小面板间距，其次缩小头像和图标，最后才减少次级文字。
- 不隐藏战斗计时、暂停入口、旗舰危急和自动控制状态。
- 战况栏可减少同时显示条数，小地图可切换紧凑尺寸。
- 双方头像阵列可缩小单格，但仍保留全部 11 个单位槽位。

## 6. 通用组件

### 6.1 按钮

所有按钮至少包含：

- 默认。
- 悬停。
- 按下。
- 选中/开启。
- 禁用。
- 警告。
- 键盘或手柄焦点。

图标按钮建议尺寸为 64 到 80 px；顶部紧凑按钮可使用 40 到 52 px。按钮按下使用 2 到 4 px 内缩或明暗变化，不做夸张弹跳。

### 6.2 操作状态栏

选中角色后显示四个固定操作槽：

| 操作 | 图标语义 | 必须显示 |
| --- | --- | --- |
| `F` 技能 | 技能图标 | 名称、冷却、目标类型、可用状态 |
| `Q` 弹药 | HE/AP 炮弹 | 当前弹种；不可切换时禁用 |
| `E` 主要武器 | 主炮、鱼雷或飞机 | 武器名称、装填、目标方式、可用状态 |
| `V` 跟踪 | 镜头/锚点 | 跟踪开启或关闭 |

按键字母保持固定位置，图标和内容随角色变化。禁用状态必须保留按键轮廓并显示原因，不能直接隐藏导致布局跳动。三项自动控制属于顶部战斗状态栏，不与这四个角色操作槽混排。

按下 `E` 后，战场显示以鼠标世界坐标为中心的主要武器准心。准心必须逐帧贴合鼠标，不使用缓动；左键确认攻击，右键取消攻击。主炮显示落点海域与散布，鱼雷显示从角色到准心方向的扇面，空袭显示以准心为中心的范围轮廓。

### 6.3 头像卡

头像卡需要支持：

- 头像。
- 舰种图标。
- 生命值条或生命环。
- 旗舰角标。
- 当前选中描边。
- 技能就绪提示点。
- 低血量闪烁。
- 阵亡使用低饱和雾蓝处理和划除标记，避免整块变成沉重黑灰。
- 敌方未发现或失去视野状态。

头像裁切以脸部、发型和主色块为中心。缩小后不得依赖服装细节辨认角色。

### 6.4 进度条

- 生命条：薄荷绿、阳光橙、珊瑚红分段变化，并保留浅蓝灰空槽。
- 技能冷却：使用扇形遮罩或线性进度，不只显示数字。
- 潜艇氧气：独立使用蓝白气泡/氧气图标，不与生命条共用颜色。
- 条形刷新使用 100 到 180 ms 追随动画；受击损失可保留短暂延迟残影。

### 6.5 标签、提示和事件条目

- 标签使用短词和单行结构。
- 临时提示不遮挡计时和舰队头像。
- 战况条目由事件图标、角色短名、结果和时间组成。
- 同类连续事件允许合并数量，减少 11v11 时的信息刷屏。

## 7. 开场、模式选择与说明 UI

### 7.1 当前程序入口

MVP 当前存在独立主菜单场景 `scenes/menu/main_menu.tscn`，脚本为 `scripts/presentation/menu/main_menu.gd`。开场 UI 必须覆盖程序中已经存在的入口和说明内容：

- `开始 1v1`：进入 `level.prototype_1v1`。
- `开始 3v3`：进入 `level.prototype_3v3`。
- `开始 5v5`：进入 `level.prototype_5v5`。
- `开始 11v11`：进入 `level.prototype_11v11`，作为大规模压力战与 11 个操作槽验证入口。
- `操作说明`：说明当前键鼠操作和 HUD 区域。
- `游戏介绍`：说明核心玩法、胜利条件和当前战斗目标。
- `设置`：选择并立即应用游戏窗口尺寸。

主菜单不是主城。它是一个轻量出击入口，应让玩家在 30 秒内理解“选模式、读操作、进入战斗”三件事。

### 7.2 开场主菜单布局

开场 UI 使用左右分栏：

```text
左上：标题卡
左中：模式/说明内容卡
左中下：模式与说明按钮区，设置按钮单独位于下一行
左下：提示卡
右侧：随机角色技能横幅立绘或半身封面
```

推荐 1920 x 1080 布局：

- 左侧安全边距 56 px，左列宽 620 到 680 px。
- 标题卡位于左上，约 620 x 190 px。
- 信息卡位于左中，约 650 x 420 px。
- 底部提示卡位于左下，约 650 x 88 px。
- 右侧封面区域从 x=43% 起铺到右边安全区，高度保留 36 到 72 px 上下边距。
- 四个模式按钮、两个说明按钮分两行放在信息卡下方；设置按钮位于第三行左侧，避免遮挡长说明文字。

开场背景使用明亮海面或程序化海面，不使用实景港口、复杂舰队或主城建筑，避免给 MVP 增加未实现系统的期待。

### 7.3 标题卡

标题卡必须显示：

- 游戏名：`小小海战`。
- 副标题：`开阔海域舰队战术原型`。
- 一句短说明：选择模式、阅读操作、进入海战。

运行画面文字统一使用中文。E/Q/F/V、W/A/S/D、1v1 等实际按键与模式符号可以保留；内部英文枚举、实体 ID、技能 ID 和拒绝码不得直接显示给玩家。

标题卡风格：

- 海盐白磨砂底，浅青描边。
- 标题使用深青大字，字号约 44 px。
- 副标题使用次文字色，字号约 20 px。
- 标题卡内可以使用罗盘、水波和星形高光，但不能堆满装饰。

### 7.4 模式选择面板

模式选择状态的说明文本需要覆盖：

| 模式 | 当前状态 | UI 表达 |
| --- | --- | --- |
| 1v1 | 可游玩 | 主按钮，高亮为“熟悉基础操作” |
| 3v3 | 可游玩 | 主按钮，高亮为“练习多角色切换” |
| 5v5 | 可游玩 | 主按钮，高亮为“完整小舰队交战” |
| 11v11 | 可游玩/压力模式 | 主按钮，文案明确“大规模压力战” |

模式说明应包含：

- 1v1：单舰对决，用于熟悉镜头、选择、主要武器瞄准和旗舰胜负。
- 3v3：小队战，用于练习角色槽位切换、集火目标、技能和小地图阅读。
- 5v5：完整小舰队交战，用于验证潜艇、驱逐、巡洋、战列的混合威胁。
- 11v11：大规模压力战，用于验证 11 个操作槽、侦查密度、HUD 可读性和表现层性能。

按钮状态：

- 可游玩模式使用默认/悬停/按下三态。
- 当前选择或当前说明页按钮使用日光黄描边。

### 7.5 操作说明 UI

操作说明页使用同一个信息卡，不切换场景。内容按玩家实际操作分组：

**基础 UI：**

- 顶部左右为敌我舰队头像栏，头像下方显示生命状态。
- 左下角是战术小地图。
- 右侧是战斗日志和选中单位信息。
- 底部操作槽显示 `E / Q / F / V` 的当前可用状态。

**键鼠操作：**

- `1-9 / 0 / -`：切换己方角色槽位。
- 鼠标左键：选择单位、设置集火目标、确认瞄准。
- 鼠标右键：普通状态下移动，瞄准状态下取消。
- 鼠标滚轮：以鼠标所指海域为中心缩放战场视角。
- `E`：主要武器瞄准。
- `Q`：切换 HE/AP。
- `F`：释放技能。
- `V`：跟踪镜头。
- `WASD`：移动镜头。
- `Space`：暂停。
- `Esc`：取消当前操作。

说明 UI 不使用长篇段落墙。每个按键使用小胶囊或图标卡展示，文字行距保持宽松。若空间不足，优先保留当前程序已实现按键，不展示未来操作。

### 7.7 设置 UI

设置使用主界面内的居中浮层，不切换场景。当前只提供游戏窗口尺寸选择、应用和关闭操作；应用成功后立即更新窗口，并在下次启动时恢复。浮层使用海盐白卡片、浅青描边和半透明深青遮罩，与主界面信息卡保持一致。

### 7.6 游戏介绍 UI

游戏介绍页说明当前 MVP 的核心规则：

- Tiny Sea War 是开阔海域中的轻量 2D 舰队战。
- 角色会自动航行、索敌并使用副武器。
- 玩家负责关键角色轮换、主要武器瞄准、弹种切换、技能释放和集火目标选择。
- 目标是保持己方旗舰存活，并击沉敌方旗舰。
- 时间耗尽时按双方剩余总 HP 比例判定胜负。
- 双方旗舰同一结算周期沉没时，当前规则判定玩家胜利。

视觉上可以用三张小图标卡概括：

```text
守住旗舰 -> 抓住主要武器窗口 -> 击沉敌方旗舰
```

介绍页应保持轻松语气，不把教学写成严肃规则书。

### 7.7 右侧封面角色

开场右侧封面从已有角色 `processed/ui/{id}_illust_skill_cutin_alpha.png` 中随机选择。设计要求：

- 使用角色技能横幅或半身立绘，不额外生成菜单专属角色图。
- 角色透明度约 90% 到 96%，避免压过左侧信息。
- 右下可显示 `Today's Cover: {character}` 或中文等价短标签。
- 标签区域使用半透明深青底或浅色描边，保证文字在立绘上可读。
- 若角色图加载失败，保留背景和左侧 UI，不阻塞模式选择。

### 7.8 开场动效

- 主菜单进入时，标题卡、信息卡、提示卡按 60 到 90 ms 间隔轻微上浮淡入。
- 右侧角色封面使用 260 到 420 ms 淡入，不做大幅滑动。
- 切换“选择模式 / 操作说明 / 游戏介绍”时，只替换信息卡标题和正文，按钮位置不跳动。
- 按钮按下反馈使用 80 到 140 ms 缩放或亮度变化。

### 7.9 开场验收

- 1v1、3v3、5v5 和 11v11 按钮能直接进入对应关卡。
- 11v11 入口会明确作为大规模压力模式使用。
- 操作说明中所有按键均与当前程序一致。
- 游戏介绍中的胜负条件与战斗结算逻辑一致。
- 右侧随机封面不会遮挡左侧按钮或说明文字。
- 1920 x 1080 与 4K 下按钮位置、信息卡行距和角色封面裁切稳定。

## 8. 战斗 HUD

### 8.1 总体布局

战斗 HUD 采用边缘停靠式布局：

```text
顶部：可展开战斗状态与自动控制栏
左上：我方 2 x 6 舰队头像阵列
右上：敌方 2 x 6 舰队头像阵列
左下：战术小地图
右侧：战况滚动栏
右下：选中舰娘信息栏
中央：战场、技能演出和必要预警
```

双方各使用一个 2 x 6 阵列，每个阵列提供 12 个固定槽位，可容纳最多 11 名舰娘并保留 1 个空槽。空槽弱化显示，不因参战人数变化而改变整个 HUD 尺寸。

### 8.2 顶部收缩状态

收缩状态只保留：

- 战斗计时。
- 展开按钮。

建议高度为 48 到 56 px。计时固定在屏幕水平中心，展开按钮放在计时右侧或顶部栏右端。展开和收缩过程中计时位置保持不变，避免玩家视线跳动。

即使顶部栏收缩，暂停、旗舰危急和自动控制变化也可以通过短暂图标提示反馈，但不常驻展开完整控制组。

### 8.3 顶部展开状态

展开状态建议高度为 88 到 104 px，包含：

- 战斗计时。
- 暂停按钮。
- 战斗阶段或期间状态。
- 自动移动开关。
- 自动主要攻击武器开关。
- 自动技能释放开关。
- 当前角色编号与名称。
- `F/Q/E/V` 紧凑操作提示。
- 收缩按钮。

期间状态使用短标签，例如准备、交战、暂停、旗舰危急和战斗结束。三项自动控制分别对应角色是否自发移动、是否自发使用主要攻击武器、是否自动释放技能；按钮只表达控制意图，具体可执行性仍由战斗规则和冷却状态决定。

### 8.4 顶部展开动效

- 展开时长：220 到 280 ms。
- 收缩时长：180 到 240 ms。
- 展开使用 `Ease Out`，收缩使用 `Ease In`。
- 面板从顶部向下裁切展开，透明度由 0 到 1，位移控制在 6 到 12 px。
- 图标在面板展开约 40% 后开始显现，避免内容先于容器出现。
- 动画过程中仍可读取计时，但展开按钮避免重复触发。

### 8.5 双方舰队头像栏

每方阵列采用 2 行 6 列：

- 我方阵列停靠左上。
- 敌方阵列停靠右上。
- 单格建议 64 到 76 px，格间距 4 到 8 px。
- 头像栏默认展开，确保 11v11 参战单位都可见。
- 头像按关卡编队顺序排列，旗舰优先放在第一格并使用明确角标。
- 点击我方头像可选中对应舰娘；点击已发现敌方头像可设置关注目标。

我方头像显示实时生命和技能就绪。敌方头像只显示玩家已知信息；未发现敌舰使用未知轮廓，失去视野后可保留最长 1 分钟残影和最后已知状态，目标重新被发现时立即恢复真实显示，不泄露隐藏期间的实时生命、位置和潜航变化。

头像栏可以提供紧凑收缩能力，但收缩后至少保留 11 个小型状态点、旗舰状态和展开按钮。MVP 默认状态为展开。

### 8.6 左下战术小地图

小地图建议尺寸：

- 标准：320 x 200 px 左右。
- 紧凑：260 x 160 px 左右。

小地图显示：

- 海域边界和主要海况分区。
- 我方全部存活舰娘。
- 当前已发现的敌舰。
- 失去视野敌舰的最后已知残影。
- 双方旗舰标记。
- 潜艇上浮/已知潜航状态。
- 舰载机或重要航空编队。
- 当前镜头可视范围框。
- 重要技能区域和危险海域的简化图形。

小地图图标使用轮廓和朝向区别舰种，不绘制完整头像。点击或拖动小地图可移动镜头；未知敌人、未发现潜艇和不应公开的攻击来源不得显示。

### 8.7 右侧战况栏

战况栏位于右下选中舰娘栏上方，其下边界固定。新信息从底部进入，旧信息向上滚动，保证玩家始终在同一位置读取最新战况。

战况栏规则：

- 宽度建议 300 到 360 px。
- 同时显示 4 到 6 条重要信息。
- 新条目进入时使用 120 到 180 ms 上移和淡入。
- 旧条目接近顶部时逐渐降低透明度。
- 默认记录击沉、旗舰受击、技能释放、重要航空波次和潜艇发现。
- 普通小口径命中不逐条记录，避免刷屏。
- 击沉条目使用攻击方头像/图标、目标头像/图标和结果符号。
- 战况栏可收缩为标题标签和最近一条重大事件。

滚动动画以下边界为不变量，不允许整个面板因新增信息上下跳动。

### 8.8 右下选中舰娘栏

选中信息栏保持小型化，建议约 320 x 120 px，只展示：

- 小头像或舰种图标。
- 舰名。
- 当前生命值与生命条。
- 当前状态。
- 技能名称。
- 技能可用或冷却状态。

当前状态使用一个主状态加必要的警告图标，例如移动、交战、待机、潜航、被锁定、撤离或阵亡。不要在此面板堆叠完整属性、武器列表和长技能说明。

未选中舰娘时，面板收缩为小型“未选择”标签或完全隐藏，只保留再次展开所需的边缘锚点。

### 8.9 暂停与期间状态

- 暂停后顶部状态明确显示“暂停”。
- 战场可轻微降低饱和度并覆盖很淡的云白蓝遮罩，但不压成暗场，也不使用完全遮挡海面的不透明层。
- 当前程序暂停面板居中，仅提供暂停图标、`Paused` 标题和按 `Space` 继续的提示。
- 后续如果在暂停中加入重新开始或退出按钮，必须使用确认弹窗，并与战斗结算按钮在位置和文案上明确区分。
- 自动控制按钮在暂停时保持当前开关状态，但显示暂不执行。
- 恢复战斗时使用短促淡出，不播放长过场。

### 8.10 HUD 遮挡优先级

发生空间冲突时按以下顺序保留：

1. 战斗计时、暂停和旗舰危急。
2. 鱼雷、空袭和技能危险预警。
3. 双方舰队存活与已知状态。
4. 小地图和镜头范围。
5. 选中舰娘信息。
6. 战况历史和装饰信息。

## 9. 战场单位 UI 与战术叠层

### 9.1 单位头顶信息

单位头顶最小集合：

- 生命条。
- 舰名或短名。
- 旗舰标记。
- 选中或目标状态。
- 潜航、失去视野、技能强化等关键状态图标。

战场血条建议宽 72 到 96 px、高 8 到 12 px。远距离或高密度情况下隐藏普通舰名，保留生命、旗舰和危险状态。

### 9.2 选中与目标

- 我方选中：暖黄色完整环和航向指示。
- 敌方目标：橙红色锁定框或断续环。
- 移动目标：青蓝色落点和路径线。
- 当前目标与范围技能落点必须使用不同轮廓。
- 选中、锁定和技能范围不能只依靠不同颜色区分。

### 9.3 战术范围

| 类型 | 建议轮廓 | 动态节奏 |
| --- | --- | --- |
| 主炮射程 | 圆弧/刻度线 | 稳定低频呼吸 |
| 主要武器准心 | 中心十字、合法性外环 | 完全跟随鼠标，不使用缓动 |
| 鱼雷扇面 | 扇形边界和方向线 | 向外推进的短线 |
| 空袭区域 | 斜纹区域和到达路径 | 倒计时扫描 |
| 防空圈 | 点划圆环 | 环形脉冲 |
| 侦查范围 | 稀疏雷达刻度 | 扫描线 |
| 支援技能 | 柔和实线和连接线 | 向内汇聚 |
| 敌方危险区 | 尖角、斜纹或警告齿 | 快速脉冲 |

范围图形应复用程序绘制或可拉伸素材，不为每个角色烘焙固定尺寸图片。

#### 9.3.1 主炮海事瞄准镜

玩家使用 `E` 控制主炮时，准心采用低干扰的海事测距刻度，不使用狙击镜式黑色圆框、暗角或高亮全屏扫描。准心由程序绘制，以保证轴线严格贯通、刻度等距并在镜头缩放下保持稳定屏幕尺寸；不依赖预烘焙位图。

- 瞄准镜分为屏幕空间精密刻度与世界空间散布椭圆两层。横纵轴和中心点保持稳定屏幕尺寸；散布椭圆由武器实际 `impact_radius` 与 `spread` 推导，并随镜头缩放正确变化。
- 1920 x 1080 下横轴总宽 440 px、纵轴总高 220 px。横纵轴连续贯穿中心，不设置方形空区；中心只保留一个 2 到 3 px 的精确落点。
- 轴线使用 1 px 海盐白或浅冰青，透明度约 42%；可增加 1 px 深青弱阴影，但不使用外发光。散布椭圆使用分段虚线，透明度约 26%，视觉权重低于横纵刻度。
- 次刻度长 5 px、中刻度长 9 px、主刻度长 14 px，间隔 16 px；每 4 个次刻度设置一个中刻度，每 8 个设置一个主刻度。刻度一直延伸至中心附近，最近一组距中心 16 px。
- 中心点使用低饱和日光黄；合法瞄准保持中性色，非法时只将中心点和轴线端部改为珊瑚红，不把整套瞄准镜染红。
- 舰体到准心的指向线使用细点线，透明度低于刻度；射界红、绿、深绿仍由现有主炮射界层表达，不与瞄准镜重复争夺颜色。
- 瞄准镜逐帧贴合鼠标，不平滑、不呼吸。确认开火时整套刻度在 100 ms 内轻微向中心收束并淡出；取消时直接消失，不播放旋转、扫描或长尾动画。

### 9.4 伤害跳动数字

伤害跳动数字用于补充命中反馈，不替代爆炸、水柱、装甲火花和音效。跳字只在玩家可见或已确认命中的目标上出现，不得泄露未发现单位、潜航单位或超出视野目标的实时位置。

基础规则：

- 数字由运行时字体绘制，不为每个数字烘焙位图。
- 字体使用粗体无衬线或项目统一战斗数字字体，外描边必须比填充色更深或更浅，保证海面、爆炸和角色立绘上都可读。
- 同一单位 0.25 秒内受到多段小伤害时允许合并为一组数字，避免 11v11 时刷屏。
- 每个目标同时最多显示 3 组跳字；后续低优先级伤害可合并或延迟 0.05 到 0.12 秒排队。
- 数字锚点位于受击单位上方或命中特效中心上方 16 到 36 px，不遮挡单位生命条、旗舰标记和主要预警区。
- 伤害为 0、未命中、格挡、跳弹或免疫时可以显示短标签，但必须使用比真实伤害更小的字号和更低动效优先级。

不同武器命中时使用不同颜色、字号和运动节奏：

| 命中类型 | 颜色与描边 | 1920 x 1080 建议字号 | 跳动动效 |
| --- | --- | ---: | --- |
| 小口径炮、副炮、机枪 | 灰色填充 | 10 到 14 px | 持续 420 到 520 ms |
| 中口径炮、重巡主炮 | 晴空蓝填充，白色内描边，深青外阴影 | 20 到 26 px | 持续 520 到 640 ms |
| 大口径主炮、战列舰重炮 | 日光黄到橙色填充，深青描边 | 42 到 58 px | 上浮 42 到 56 px，持续 680 到 820 ms |
| 穿甲有效命中/核心区命中 | 日光黄填充，白色高光，黑色秒边 | 44 到 62 px | 数字短暂停顿 80 ms 后弹起 |
| 鱼雷命中 | 珊瑚红填充，白色内描边，深蓝水影 | 20 到 26 px | 从命中侧向外弹出后上浮，持续 720 到 900 ms |
| 航空炸弹/空袭命中 | 紫罗兰或橙黄填充，浅白描边 | 20 到 26 px | 从落点垂直弹出，持续 620 到 780 ms |
| 防空命中飞机 | 浅蓝白 | 10 到 14 px | 向被击落方向漂移，持续 420 到 560 ms |
| 反潜与水下爆炸 | 潜航蓝填充，白色气泡描边 | 34 到 48 px | 带气泡感缓慢上浮，持续 700 到 900 ms |
| 灼烧、进水、中毒等持续伤害 | 对应状态色填充，低饱和描边 | 10 到 14 px | 小幅上浮或原地淡出，持续 480 到 600 ms |
| 治疗、护盾恢复或修复 | 薄荷绿填充，白色描边，前缀 `+` | 24 到 34 px | 稳定上浮，节奏比伤害更柔和 |

尺寸只表达“反馈权重”，不直接等同于伤害数值大小。实际数值差异主要通过数字本身体现；字号差异用于帮助玩家快速分辨武器类别、命中重要性和危险程度。

格式规则：

- 普通伤害显示整数，例如 `128`。
- 治疗和修复显示 `+128`。
- 跳弹、格挡、免疫和未命中使用短标签，例如 `跳弹`、`格挡`、`免疫`、`未命中`，字号比同类伤害低 20% 到 30%。
- 暴击、穿透、核心区命中不使用长文字覆盖战场，可用小型图标、角标、描边闪光或一次短促放大表达。
- 多段命中可以显示 `128 x3`，但只在合并显示时使用，避免每个弹片都单独跳字。

动效曲线：

- 入场 80 到 140 ms：缩放从 90% 到 108% 或 112%，重型命中可短暂停顿。
- 主运动 300 到 620 ms：向上或侧上方移动，速度逐渐减慢。
- 退场 120 到 220 ms：透明度淡出，缩放回到 96% 到 100%。
- 小口径数字可以更快消失；鱼雷、重炮和空袭数字保留更久，但总时长不超过 900 ms。
- 若开启减少动效，取消弹跳和横向抖动，只保留轻微上浮与淡出。

层级和遮挡：

- 伤害数字位于单位头顶信息和普通命中特效之间，低于鱼雷、空袭、旗舰危急和技能预警。
- 选中环、主要武器准心、技能落区和小地图永远不被伤害数字遮挡。
- 同屏数字过多时，优先保留玩家选中目标、旗舰、主要武器命中、鱼雷命中和空袭命中；普通副炮和持续伤害可降级为合并数字。

### 9.5 画外提示

- 旗舰危急、鱼雷接近和空袭到达可使用屏幕边缘方向标。
- 方向标只指向玩家已知威胁。
- 多个同方向提示允许聚合数量。
- 提示不得覆盖顶部计时、双方头像栏和小地图。

## 10. 暂停、确认与战斗结算 UI

### 10.1 暂停面板

- 标题、暂停图标和短说明。
- 当前程序中按 `Space` 继续，因此面板必须显示“按 Space 继续”或等价提示。
- 暂停状态不显示返回主界面或再玩一次按钮，避免和战斗结束状态混淆。
- 可附带当前战斗时间、当前模式和选中角色摘要，但不在暂停面板重复提供复杂设置。
- 背景使用局部降饱和、云白蓝遮罩和轻微模糊，保留明亮的战场上下文。

### 10.2 战斗结算信息结构

当前程序中战斗结束后显示独立结算面板，并提供 `返回主界面` 与 `再玩一次` 两个按钮。结算面板必须显示：

- 胜利或失败标题。
- 胜负副标题。
- 随机己方角色立绘。
- 战斗模式。
- 战斗时长。
- 结算原因。
- 胜利阵营。
- 复盘提示。
- `再玩一次`。
- `返回主界面`。

当前程序已使用的字段：

| 字段 | UI 文案用途 |
| --- | --- |
| `winner_faction` | 判断胜利/失败标题，并显示胜利阵营 |
| `reason` | 显示结算原因 |
| `elapsed_time` | 显示战斗时长 |
| `level_id` | 显示战斗模式 |
| `result_character_id` | 选择左侧角色立绘 |

### 10.3 胜利结算

胜利面板语气应轻快、鼓励玩家复盘：

- 标题：`胜利`。
- 常规副标题：敌方旗舰已经失去作战能力。
- 若 `reason == TIME_LIMIT`：显示“时间耗尽，按双方剩余总 HP 比例判定。”
- 色彩：晴空蓝、薄荷绿、日光黄。
- 左侧角色立绘使用明亮正常饱和度。
- 胜利装饰可以使用罗盘、浪花、星光和柔和飘带。

### 10.4 失败结算

失败面板保持温和，不做压迫式失败演出：

- 标题：`失败`。
- 常规副标题：己方旗舰失去作战能力。
- 若 `reason == TIME_LIMIT`：显示时间耗尽判定文案。
- 色彩：雾蓝、淡紫灰、少量珊瑚红。
- 背景降低饱和度，但不压成黑场。
- 复盘提示优先提示主要武器窗口、集火目标和旗舰位置。

MVP 不需要复杂奖励动画、星级评分和多页统计。结算是“复盘入口”，不是养成奖励页。

### 10.5 结算按钮

结算按钮固定在右下信息区：

- `再玩一次`：重新开始当前 `level_id`。
- `返回主界面`：返回 `scenes/menu/main_menu.tscn`。

两个按钮尺寸保持一致。`再玩一次`使用主按钮样式，`返回主界面`使用次按钮样式。按钮位置不能随胜负文案长度变化。

### 10.6 确认弹窗

重新开始、退出或手动结束战斗如果后续增加二次确认，需要确认弹窗。主操作与取消操作在颜色、位置和文字上明确区分，危险操作使用红色边框和清楚动词。当前程序的战斗结束按钮可直接执行，不强制弹确认。

## 11. 展开、收缩与过渡动效

### 11.1 统一时长

| 类型 | 建议时长 |
| --- | --- |
| 小按钮反馈 | 80 到 140 ms |
| 标签/提示出现 | 120 到 180 ms |
| 普通面板展开 | 180 到 240 ms |
| 大面板或顶部完整展开 | 220 到 320 ms |
| 战况滚动 | 120 到 180 ms |
| 结算面板进入 | 280 到 420 ms |

### 11.2 动效规则

- 展开使用 `Ease Out`，收缩使用 `Ease In`。
- 位移、裁切和透明度配合使用，不做大角度旋转。
- 同一时间最多突出一个主要面板动效。
- 面板固定边界不因内容刷新跳动。
- 用户连续操作时允许动画快速完成或反向，不排队播放多次。
- 提供减少动效选项时，保留状态切换但缩短位移和闪烁。

## 16. 验收标准

- 开场主菜单的 `开始 1v1`、`开始 3v3`、`开始 5v5`、`开始 11v11` 能进入对应关卡。
- `开始 11v11` 明确是大规模压力模式，不误导玩家以为突围、占点等其他模式已经可玩。
- `操作说明` 中的按键与当前程序一致，包括 `1-9 / 0 / -`、鼠标左右键、`E/Q/F/V`、`WASD`、`Space` 和 `Esc`。
- `游戏介绍` 中的旗舰胜负、时间耗尽判定和同周期沉没判定与当前结算规则一致。
- 顶部栏收缩后只常驻计时和展开按钮，计时位置不跳动。
- 顶部展开后可清楚查看暂停、三项自动控制以及当前角色的 `F/Q/E/V` 状态。
- 双方最多各 11 名舰娘均有固定头像槽位，阵亡、旗舰、选中和未知状态清楚。
- 我方头像槽位与 `1` 到 `9`、`0`、`-` 一一对应，第 10、11 位不得显示为两位数字键组合。
- 小地图只显示玩家已知信息，不泄露未发现敌舰和潜艇。
- 战况栏以下边界为不变量，新信息从底部进入并向上滚动。
- 选中舰娘栏只显示生命、当前状态和技能名称等必要信息。
- 11v11 时中央战场仍有足够观察面积，鱼雷、空袭和旗舰危险不被 UI 遮挡。
- `E` 瞄准准心在镜头移动、缩放和跟踪状态下仍准确对应鼠标下的世界坐标。
- 不同武器命中的伤害跳动数字在颜色、字号和运动节奏上能区分小口径炮、重炮、鱼雷、航空、防空、反潜、持续伤害和治疗。
- 11v11 密集命中时伤害数字会合并、限流或降级，不遮挡生命条、旗舰标记、主要武器准心、技能落区和危险预警。
- 所有关键状态不只依靠颜色表达。
- 1920 x 1080、2560 x 1440 和 3840 x 2160 下无拉伸、重叠、裁切和过小文字。
- 晴昼、多云和暮色海况下文字、图标和战术范围均可读。
- 面板展开、收缩和战况刷新无明显跳动、延迟堆积或输入阻塞。
- 暂停面板只表达暂停和继续方式，不出现会被误认为结算页的返回或重开按钮。
- 战斗结束后结算面板显示胜负、模式、时长、原因、胜利阵营、复盘提示，并提供 `再玩一次` 与 `返回主界面`。

## 18. 从场景文档迁入的战术叠层与承载 UI

以下内容原先混在场景美术文档中，现统一归入 UI 美术。场景层只负责让海面、天气和陆地为这些信息留出可读空间。

### 18.1 选中、移动与阵型

- 选中单位：金白色细环，带一个清楚的前向缺口或箭头。
- 目标单位：橙色锁定环，动画节奏比选中环更快。
- 移动路径：半透明青白曲线，节点间距随速度变化。
- 当前航向：单位下方短实线箭头。
- 目标航向：较长虚线箭头。
- 阵型槽位：低亮圆点或短弧，仅在调整阵型时显示。

### 18.2 侦查、隐蔽与最后接触

- 已发现敌人正常显示角色、舰装和敌方标记。
- 即将丢失目标时逐步降低外轮廓清晰度，不直接整体变透明到不可读。
- 丢失目标后只保留最后位置残影、最长 1 分钟时间衰减环和模糊航迹；目标重新被发现时残影立即消失。
- 最后接触标记使用暗红或紫红虚影，不能被误认为当前可攻击目标。
- 侦查范围只在选中单位、部署侦查机或相关技能时显示，避免常驻圆圈淹没战场。

### 18.3 功能色迁入规则

功能色采用晴空蓝、珊瑚粉、日光黄、薄荷绿和紫罗兰组成的明亮体系。高饱和色只用于标记、路径、进度和短时反馈，不铺满大面积环境。功能色需要同时配合形状、线型、白色内描边和动画区分，不能只依赖颜色，以兼顾色觉差异和复杂海况。

| 功能 | 主色建议 | 使用规则 |
| --- | --- | --- |
| 友方识别 | `#2FBAE6` | 头像边框、单位底环、友方路径；海面上配白色内描边或深青阴影 |
| 敌方识别 | `#FF7180` | 已发现敌舰、敌方底环和普通锁定提示 |
| 选中状态 | `#FFC857` | 当前操作单位，不用于环境高光 |
| 目标锁定 | `#FF9F43` | 单体目标和集中火力 |
| 危险警告 | `#E83F5B` | 鱼雷、致命攻击、旗舰危急，不用于普通敌方识别 |
| 防空/正向 | `#35C99A` | 防空圈、拦截反馈和正向状态 |
| 航空 | `#FFD166` | 飞行路径、起飞和空袭边界 |
| 技能/强化 | `#8A78F0` | 技能范围、强化和特殊状态 |
| 潜航/声呐 | `#5A8EDB` | 水下阴影、气泡、声呐波纹 |
| 无效/未知 | `#9AAEB6` | 残影、不可选状态和失效提示 |

### 18.4 暂停、胜负与旗舰危急承载

- 暂停时可降低环境流速和饱和度，但战术叠层必须保持清晰。
- 旗舰低生命时在旗舰标记上增加节奏缓慢的红色脉冲，不做持续全屏红闪。
- 胜利时海面可恢复较高亮度，保留战场结果，不立刻用遮罩完全盖住场景。
- 失败时可降低环境亮度和饱和度，旗舰沉没位置保留扩散水纹。
- 结算面板与战场分层，背景使用半透明深色，不要求额外制作独立结算场景插画。
