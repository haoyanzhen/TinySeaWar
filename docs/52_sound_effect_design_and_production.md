# 音效设计与素材交付规范

> **功能与边界**：本文负责舰娘海战声音语言、素材分类、制作与采用包规范。触发、观察权限、去重、11v11混音及实施关闭条件由[音效工单](../workorder/20260929-sound-effects-inventory-and-integration.md)负责；运行时字段归25，音乐归50，当前完成度归[00](00_project_status.md)。[历轮记录](history/52_sound_effect_production_iterations.md)仅供追溯，不作为当前需求。

## 1. 声音语言与玩家反馈

海军机械的体量、真实水感与简洁操作提示建立二次元舰娘海战身份。舰娘在海面敏捷滑行，不为每个角色铺巨舰引擎声；近场炮雷有尺寸与介质差异，不用连续电影爆炸覆盖指令。海战主题应转译成具体可听声源、动作和时间包络，不能只在提示词末尾加背景标签。

物理声只表达公开且实际发生的动作：开火不等于命中，航空装饰减员不等于真实击落。UI与任务提示可采用短音乐音型，不要求全部伪装成舰桥开关。无角色台词、喊招或额外背景配乐；钢琴完成提示、辅助开关音型属于短音效，允许保留。

每种声音承担一种清楚的语义。高频动作控制尾音、尖锐高频和重复疲劳；不同结果不用同一模板仅改响度。提示不能泄露隐藏单位、雷点或命中事实，也不能成为唯一信息载体。

## 2. 有效范围与分类

当前制作决策真源为[逐项评审清单](../tools/sfx/reviews/current_disposition.json)；正式整理包的采用文件与需求快照见[素材索引](../assets/audio/sfx/source/selected_20261001_v1/inventory.md)。工单105项是需求索引，独立素材可拆分或复用，不能以需求数推导WAV数。

| 分类 | 声音设计与复用原则 |
| --- | --- |
| weapon | 轻/中/重/超重炮、鱼雷发射、防空和反潜按体量及器材区分；超重炮是完整素材，不再叠重炮 |
| impact | 舰装冲击、空气/水下爆炸与沉没分开；重受击以冲击和爆炸为主，不叠无关机械 |
| water | 炮弹落水水柱按尺寸区分；共享只复用声源，不推断隐藏命中 |
| aviation | 公共螺旋桨与编队尺度；投弹使用舱门及初期破空；不逐架重复分配声源 |
| submarine | 下潜气泡、上浮出水与非空间完成提示分离；不加入虚构声呐定位 |
| alert | 接触、低氧、旗舰危急、任务与时间提示以可辨音型承载；目标完成采用钢琴三音 |
| ambience | 海面、风、雨、雷与近岸独立分层；五天气复用，四时段不无据新增鸟声/虫鸣 |
| facility | 靠泊锚锁盘、补给开始、布雷开始与完成有明确阶段；布雷完成采用舰桥报告铃 |
| ui | 选择、移动、拒绝、弹种切换与面板反馈保持短而清楚；辅助开关采用成对升降音型 |

K01–K09技能独立音效已取消，不再制作通用技能成功声，也不以复用其他提示声恢复该触发。实际技能产生的炮雷、飞机和水面事实仍按有效武器/航空需求选播；技能视觉和文字反馈不取消。K10专属语音仍属静默/暂缓。

N04鱼雷危险警报、S05强制上浮独立警报、就绪提示U08/U09及其他取消项均不恢复。F07岸炮触发整体取消，即使共享炮声存在也不播放。U14专用试听音效取消，音量试听使用主界面音乐。局部父需求只保留有效子项；取消不是等待素材的缺口。

## 3. 设计、生成与评审

先确定玩家要理解的事实，再写声源、动作、节奏、体量和收束方式。物理声写明器材与介质，抽象提示写明具体乐器或声响；避免整类套用“电子提示加金属点缀”。

每个待制作独立条目默认三候选，保存完整英文提示、种子、时长及模型参数。三候选是人工选择，不自动成为三个运行时随机take。实验可使用同种子比较提示词标签，编辑或派生必须明确来源，不能伪称独立生成。取消项禁止进入历史批次重新排产。

当前制作工具使用Stable Audio 3 Small SFX独立离线CLI；版本、采样器与权重来源保存在各批回执。官方指南与社区证据及适用边界见[提示词调研](../tools/sfx/revision3_design_20261001_v6.md)。类别短词可作对照，不假定越短或越长越好；标签和音符文本不保证具体听感、次数或音高。TangoFlux曾因用途限制撤回，未用于交付声音。

评审导出必须绑定batch和试听SHA256。无意见偏好采用；有修改意见继续返工；明确取消退出生成与接入。文字说明优先于空选择或矛盾选择，历史记录不覆盖。选材通过只代表听感方向采用，不替代循环和实机混音验收。

## 4. 正式采用源包

采用源包放在 `assets/audio/sfx/source/selected_20261001_v1/`，以分类和小写工单ID组织。该目录由 `.gdignore` 隔离，避免源版与采用版被Godot重复导入；不是运行时manifest。

- `{category}/{id}/selected.wav`：人工选中的试听版本，48kHz PCM24，逐字节复制，不重新剪辑或归一化。
- `raw.wav`：对应完整生成源，保留原采样率/浮点格式；源峰值超出0dBFS单独记录，不把浮点超范围直接等同听感削波。
- `provenance.json`：候选、批次、提示/种子、后期、测量、人工选择及原路径；W03沿用旧小样C的真正生成来源。
- `manifest.json`：素材、相对路径、SHA256、循环标记与105项需求快照；用途明确为制作归档，禁止当成已接入API。
- `disposition_snapshot.json`、`reviews/`、`production/`：评审快照、原反馈和生成回执。
- `inventory.md`、`listen.html`、`validation.json`：可读索引、只读试听和交付核验。

正式路径与工具入口见[34](34_implementation_map.md)。历史未采用、取消候选保留在原批次 `reports/audio/`，不删除、不混入采用包、不再生产。提示词和评审仍在 `tools/sfx/` 追溯。归档中历史路径只是来源记录，使用采用包无需临时试听服务或GPU在线。

## 5. 后期与交付验收

整理不改变已采用波形。原后期记录包含静音裁剪、淡入淡出、重采样、声道转换、增益、循环交叉淡化及测量；应按每条记录重建，不能用最新统一参数覆盖旧母版。空间点声一般单声道，环境与非空间提示一般双声道，最终接入策略另验。

循环标记表示用途，不代表无缝已验收。循环点、首尾衔接至少连续试听三轮；必要时从源版派生新文件并保留采用版。超过原目标时长是节奏复查提示，不自动裁掉用户选中的尾音。浮点源峰值、样本峰值、过采样峰值和响度分别记录，降低增益不能消除已有失真。

整理验收须核对所有采用文件及源版哈希、格式、文件存在性、ID唯一性、需求引用完整、取消项不被引用，以及复跑不覆盖不同内容。模型与组件使用条件保留上游来源与版本记录，项目代码许可不替代其条款。

游戏接入前再确定总线、编码/导入、音量设置、空间衰减、事件所有者、并发与生命周期，正式字段同步25/33及必要的资产接口。运行时不能引用reports或本源包；需独立交付运行时派生资源并通过工单AUD-01/02/03/05/07验收。9项循环、长尾、源峰值及11v11混音的实际剩余检查见源包validation与00，不因文件整理完成而关闭。
