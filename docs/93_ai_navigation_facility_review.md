# AI、设施交互与港湾编成设计修改清单

更新日期：2026-07-03

## 1. 文档定位

本文记录本轮已经确认方向、但尚未完成实现和验收的设计修改。每个设计修改均包含简要描述、修改原因和待完成事项；只有“待完成事项”使用复选框。

本文不是当前运行时真源。实施时需要把结论同步到玩法、AI、设施、数据契约、Domain、关卡和项目状态文档。只有代码、数据、玩家入口、AI 接入、表现、自动测试和动态验证全部完成后，才能勾选相应事项。

## 2. 设计修改内容

### 2.1 水流规则

**简要描述**

普通区域控制、舰船移动不应改变舰船既有运动规则。除了撞到岸边外，舰船始终受到速度、转向惯性、水流、海况、碰撞和外力影响；被水流推离交互区会中断控制或尚未建立靠泊的服务。

**原因**

设施交互本身不是物理稳定装置。无条件将航速归零或抵消水流，会绕过海面规则，也会消除玩家在接近、控速、维持位置和承担停留风险方面的决策。

**待完成事项**

- [x] 撤销普通设施交互自动航速归零、保持定点和抵消水流的规则。

### 2.3 设施操作拆分为五类模式

**简要描述**

设施操作拆分为区域控制、靠泊服务、远程指挥、自动运行和战斗处置。一个设施可以组合多种模式，但每种模式拥有独立前置条件和状态，不再让所有设施共用一个近距离交互流程。

区域控制用于取得设施所有权；靠泊服务用于补给和维修；远程指挥用于机场任务和布雷；自动运行用于岸防炮、传感器、通信和已部署水雷；战斗处置用于压制及可摧毁设施的摧毁。

**原因**

占领、维修、机场空袭和炮击设施的输入方式、风险、持续时间及结果完全不同。统一命令会迫使规则互相迁就，也无法自然表达机场无需靠近、维修需要进坞、岸防炮自动开火等差异。

**待完成事项**

- [x] 为五类模式建立独立数据字段、Domain 状态和命令契约。
- [x] 区域控制采用先声明意图、进入水域后自动累计进度的流程。
- [x] MVP 同一阵营只指定一艘控制执行舰，其他友舰不叠加占领速度。
- [x] 敌舰进入争夺范围时暂停控制进度并进入 `Contested`。
- [x] 靠泊服务检查设施阵营、泊位、位置、低速、占用和必要朝向。
- [x] 远程指挥检查设施状态、阵营、依赖、次数、冷却、航程和环境条件。
- [x] 自动运行能力不要求玩家或 AI 重复提交使用命令。
- [x] 战斗处置与近距离交互分离，继续使用公共攻击、命中、伤害和压制规则。
- [x] 将普通玩家语义统一为“控制/占领”；`Activate` 仅用于关卡初始化、脚本事件或特殊待激活设施。

### 2.4 玩家与 AI 使用同一规则、不同意图入口

**简要描述**

玩家和 AI 共用同一套设施合法性、进度、中断、完成和效果结算。玩家通过世界设施、小地图和设施面板主动选择操作；完整 AI 从阵营已知设施中量化选择任务。玩家受限辅助可以帮助接近玩家指定设施，但不能替玩家决定设施战略价值。

**原因**

规则对称能够避免 AI 绕过位置、所有权或服务条件。玩家和 AI 的差异应来自决策来源，而不是两个互不一致的设施系统。

- [x] HUD 显示前置条件、控制/服务进度、争夺状态、泊位状态和中断原因。
- [x] 玩家受限移动辅助只执行接近，不计算设施价值或自动改换设施目标。

### 2.5 沉没单位终止决策，但保留已发射实体

**简要描述**

舰船沉没后立即终止该舰的 AI、任务、航行、设施交互、技能和待执行操作。尚未实际发射或生效的行为取消；沉没前已经发射的炮弹、鱼雷、航空攻击和其他独立战场实体继续按自身规则结算。已经生效的持续效果按各自失效条件处理。

**原因**

沉没单位不能继续产生新的意图或动作，但已经脱离舰船存在的弹药不应凭空消失。区分“待执行操作”和“已生成战场实体”可以保持时序一致，也符合玩家预期。

**待完成事项**

- [x] 删除沉没舰尚未发射或尚未生效的攻击、服务与支援请求。
- [x] 保留沉没前已经发射的炮弹、鱼雷、航空攻击和其他独立实体。
- [x] 持续效果按持续时间、来源依赖和自身失效条件处理。
- [x] 增加“沉没后无新命令”和“已发射弹药继续命中”的自动测试。

### 2.6 港湾均衡验证要求双方 Cost 相同

**简要描述**

用于 AI、出生侧和设施平衡验证的港湾编队必须具有相同总 Cost。旧有玩家侧 `12 Cost`、敌方侧 `9 Cost` 的结果只作为历史记录，不再作为均衡结论。

**原因**

不等 Cost 编成会把阵容差异混入 AI 和地图结果。即使侧别交换能证明出生侧公平，也不能证明不同预算舰队的战斗强度合理。

**待完成事项**

- [x] 调整港湾双方编队，使总 Cost 完全相同。
- [x] 为港湾均衡验证模式增加双方 Cost 一致性校验。
- [x] 将旧不等 Cost 报告明确标为历史证据。
- [x] 调整后按 `1 -> 3 -> 20` 阶梯执行固定种子和侧别交换。
- [x] 报告同时输出阵容胜率、出生侧胜率、设施使用率、超时率和行为异常。

### 2.7 长时间回避产生主动接敌压力

**简要描述**

量化 AI 增加连续回避、无有效位移、无接敌和无有效攻击的时间记录。消极状态持续越久，回避、防守和原地等待收益越低，主动接敌、逼近、侧翼、争夺关键区域和形成射击窗口的收益越高。真实高威胁或明确任务可以降低或暂停惩罚。

**原因**

单次回避可能合理，但无限回避会产生原地不动、长期拉扯和超时。时间惩罚需要进入评分并保持可解释，不能用固定时刻强制冲锋替代。

**待完成事项**

- [x] 记录连续回避、无有效位移、无接敌和无有效攻击时长。
- [x] 随时间降低回避、防守、保持距离和原地等待评分。
- [x] 随时间提高主动接敌、逼近、侧翼、区域争夺和射击窗口评分。
- [x] 在真实高威胁、低耐久、武器装填、护航或撤离任务下降低或暂停惩罚。
- [x] 在有效开火、形成窗口、完成任务、显著位移或脱离威胁后重置或衰减惩罚。
- [x] 将惩罚实现为可解释量化项，禁止只使用硬编码超时冲锋。
- [x] 报告累计消极时长、触发次数、触发后接敌时间和长期原地不动次数。

### 2.8 设施状态、所有权与依赖分离

**简要描述**

设施分别保存生命、所有权、运行和交互状态。建议生命状态至少包含 `Alive | Destroyed`；运行状态包含 `Dormant | Active | Suppressed | Silent | Disabled`；交互状态包含 `Idle | Controlling | Contested | Moored | Docked | Servicing | Interrupted`。`Approaching` 属于单位任务，不属于设施占用状态。

依赖同时检查状态和阵营。敌方通信站不能为己方设施提供通信。压制不改变所有权；恢复时重新计算所有权和依赖是否合法。

**原因**

单一 `operation_state` 无法同时准确表达设施是否被摧毁、属于谁、能否运行以及是否正在被控制。状态拆分可以避免压制恢复到错误阵营、跨阵营共享通信等问题。

**待完成事项**

- [x] 拆分设施生命、所有权、运行和交互状态。
- [x] 将设施是否可占领、可压制、可摧毁、可静默和依赖列表数据化。
- [x] 依赖检查同时验证设施状态和所属阵营。
- [x] 压制恢复时重新检查所有权、依赖和允许的运行状态。
- [x] 为不可摧毁设施增加伤害下限、压制累计和表现反馈契约。
- [x] 补充状态组合负例校验与生命周期测试。

### 2.9 海岸观察站采用光学区域控制

**简要描述**

海岸观察站采用区域控制、自动运行和战斗处置。港湾默认中立、休眠，允许占领、压制和摧毁。占领后向所属阵营提供固定光学观察，继续受到天气、昼夜、海雾、视距和岛岸遮挡影响。

**原因**

观察站的价值是取得岸上视点，而不是提供无条件全知。保留光学限制可以让天气、岛岸和压制继续具有反制价值。

### 2.10 岸防炮采用条件激活、不可摧毁与通信静默

**简要描述**

岸防炮具有“敌方已激活”和“己方待激活”两种关卡默认状态。敌方已激活炮台直接运行；己方待激活炮台允许己方通过占领完成激活。岸防炮不可摧毁，只能被压制；所有可用通信站均被摧毁后进入 `Silent` 并停止索敌、开火。

岸防炮的耐久和防护采用“经典战列舰”语义基线。武器采用“经典高级战列舰一座联装主炮塔”语义基线，单发伤害、散布、穿深、装填和弹药类型与该模型一致。

**原因**

大型岸防炮工事不应在短时舰队战中被完全摧毁，但需要能够通过火力压制和切断通信反制。使用舰船与武器语义基线可以避免设施复制一套逐渐漂移的平行数值。

**待完成事项**

- [x] 己方待激活炮台可通过区域控制完成激活。
- [x] 敌方已激活炮台不通过普通水面交互直接夺取。
- [x] 禁止岸防炮进入 `Destroyed`，伤害只用于受击、压制和反馈。
- [x] 所有可用通信站均被摧毁后进入 `Silent`。
- [x] 通信暂时受压制时暂停能力，通信恢复后重新计算运行状态。
- [x] 建立经典战列舰耐久、防护的稳定语义引用。
- [x] 建立经典高级战列舰联装主炮塔的稳定语义引用。
- [x] 复用联装炮塔的伤害、散布、穿深、装填和弹药模型。

### 2.11 前沿补给点采用占领后靠泊补给

**简要描述**

前沿补给点采用区域控制、靠泊服务和战斗处置。港湾默认中立、休眠，允许占领、压制和摧毁。占领后只为同阵营舰船提供补给泊位；完成服务后恢复武器装填并缩短技能冷却。

**原因**

补给具有显著战斗收益，应要求舰船取得设施、接近泊位并承担停留风险，而不是驶过区域立即获得资源。

- [x] 保持补给点不直接影响其他设施。

### 2.12 近岸机场采用远程任务、不可摧毁与通信静默

**简要描述**

机场采用远程指挥、自动运行和战斗处置。港湾默认敌方、激活，不由水面舰在岸外直接占领。机场不可摧毁，只能被压制；所有可用通信站均被摧毁后进入 `Silent`，不再接受或生成新任务。已经出动的任务按自身阶段继续或取消。

### 2.13 雷达站使用独立雷达探测

**简要描述**

雷达站采用自动运行和战斗处置。港湾暂定敌方、休眠，不由水面舰直接占领，允许压制和摧毁。激活后自动发现范围内未处于雷达隐身状态的舰船；探测距离不受天气、昼夜、海雾和光学能见度影响。雷达接触与光学接触分别记录，但遵守相同阵营情报隔离。

**原因**

雷达与观察站的核心差异是主动电磁探测，不应复用光学能见度倍率。独立接触类型也为雷达隐身、电子对抗和接触精度留下扩展空间。

### 2.14 通信站控制设施通信依赖

**简要描述**

通信站采用区域控制、自动运行和战斗处置。港湾默认敌方、激活，允许占领、压制和摧毁。它只向同阵营岸防炮、机场和未来声明依赖的设施提供通信。占领通信站不会自动转移依赖设施的所有权。

### 2.15 水雷控制站支持远程随机布雷

**简要描述**

水雷控制站采用区域控制、远程布雷和战斗处置。港湾默认中立、休眠，允许占领、压制和摧毁。占领后可在控制半径内选择一个不包含现有敌方单位的正方形海域；布雷持续 `10s`，完成时在该区域内一次性随机生成一批水雷。

随机落在陆地或海岛范围的水雷立即失效，不重新抽取，也不影响同批其他水雷。水雷不区分敌我，接触任意舰船都会爆炸。其发现流程与鱼雷相同，默认发现距离为经典战列舰长度的一半，增强鱼雷发现距离的技能同样生效；纸面伤害采用经典鱼雷伤害基线。

**原因**

### 2.16 港口维修泊位采用占领后进坞维修

**简要描述**

维修泊位采用区域控制、靠泊服务和战斗处置。港湾默认中立、休眠，允许占领、压制和摧毁。占领后只为同阵营舰船提供维修；舰船满足低速、位置和进坞方向后进入 `Docked`，再开始维修计时。

**原因**

维修收益高于普通补给，需要更严格的进坞条件和更明显的战术风险。把进坞与普通区域停留分开，也能合理解释维修期间的定点保持。
