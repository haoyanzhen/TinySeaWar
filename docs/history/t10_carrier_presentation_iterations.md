## 1. 实施前检查结论与证据（历史基线）

以下仅记录 2026-09-29 接入前的系统，用于解释方案动机，不描述当前实现。当时系统有航空延迟伤害、一些起飞/命中特效与航空伤害数字，但没有把一次航空任务作为可持续观察的作战过程展示出来。当前 A/B 接入情况见第 12 节与 [00](../00_project_status.md)。

| 环节 | 实施前确认的状态 | 当时的缺口与影响 |
|---|---|---|
| 普通航空攻击 | `BattleSession._fire_weapon/_fire_weapon_at_position` 将 `Aviation` 放入 `delayed_attacks`，按距离、武器速度与天气延迟结算 | 没有对应的持续飞行编队状态投影；玩家只能看到零散首尾反馈 |
| 飞行节点 | `BattleEffectDirector.sync_snapshot` 只同步单位和 `projectiles`；`_spawn_shell_flights` 只接受 `Gun` | `aircraft.*` 配置存在不等于有飞机节点；普通航空没有进入鱼雷实体分支 |
| 起飞/命中 | `WeaponFired` 触发角色开火姿态、挂点 VFX；`AttackResolved` 触发命中特效和按航空类型区分的数字 | 缺编队航行、投弹、任务收尾；未命中落水目前只对大口径炮有专门分支；部分效果还依赖角色 role 存在 |
| 防空 | `_aviation_survival_ratio` 到达时按目标点附近防空估算折损，使用基础航空 HP 及修正；没有沿飞行路线逐轮射击事实 | 无法诚实画出“某门防空炮此时命中这架飞机”；不能用装饰弹幕冒充真实拦截 |
| 侦察 | 技能创建 `Reconnaissance` 区域，保存 HP/剩余时间；`_anti_air_dps_at_position` 按每 Tick DPS 扣血 | 快照有 `skill_effects`，当前战斗协调器未把它接入持续侦察视图；不是已有移动侦察机实体 |
| 航空鱼雷 | `weapon.shokaku_torpedo_bomber` 为 `Aviation`，引用 `projectile.surface_torpedo`；仍走航空延迟区域攻击 | 没有“飞机投雷→入水→鱼雷航行→碰撞”的闭环；不能展示假的可规避鱼雷 |
| 岸基航空 | 机场有任务与效果；`TerrainView` 绘制支援区域，空袭完成播放通用水柱 | 缺任务飞行；战斗机巡逻主要影响航空命中修正，不是逐机空战 |
| HUD/小地图 | 已有航空图标文件；当前小地图主要绘制舰艇、接触、设施、环境和水雷 | 无持续编队标记、己方任务阶段、合法可见的空袭威胁读数 |
| 隐藏信息 | 舰艇/投射物快照有过滤；场景把原始事件及 session 传给导演，导演多处读取 `session.state` | 新航空链必须先建立过滤后的表现事实；不能把敌航母起点、隐藏防空舰或落点全量交给视图 |
| 资产 | 审计时公共飞机为带光晕符号，角色飞机存在视角混杂与残片 | 改为共享五类正俯视机体，独立于角色包；旧专属飞机仅保留历史兼容，新资产与映射交付见 `00` |
| 文档 | 审计发现 `42` 的返航降落要求与 `10/12` 冲突，本轮已同步修订设计 | 从角色位置生成飞机、攻击后脱离淡出；设计修订不代表运行时已接入 |

## 12. 2026-09-29 实施记录

- P0/P1/P2：接入 Application 逐波关联/事件过滤、公共编队与独立炸弹、侦察/设施适配、任务摘要和小地图。默认 `Abstract` 保持旧结算，只显示己方持续飞行。旧航空起飞/命中和机场通用完成水柱已移交唯一消费者，隐藏结果只给中性到达反馈。
- P3：`Physical` 模式已有权威波次HP、独立观察、真实周期全圈防空、侦察摧毁和冷却惩罚、机场空袭HP、翔鹤实体鱼雷及独立统计。每波共享HP，投放时冻结折损，全灭停止载荷；航空雷使用公共发现、角误差、连续碰撞和伤害统计。该模式显式选择，尚不替代默认A；未以调数值追平旧胜率。
- 自动证据：388条排程事实对照一致；七舰×晴昼/雨夜14个完整Tick指纹及关闭快照的同组对照一致，排除新增航空事件、事件序号和非确定性计时诊断，保留攻击ID/事实顺序/随机源/单位与装填状态。专项规则72、表现40、资产51、场景236、技能417、机场20、模拟器52、伤害统计27、AI观察19、核心含五模式烟测1903项通过。
- P4：七舰出击关键帧、企业飞行与翔鹤实体投雷短片、1080p/1440p和雨夜/雷雨停飞样例已生成；暂停、重建、重复事件、隐藏/脱离、缺图及十次重开清理自动覆盖。32编队（96架装饰）11v11背景的两轮CPU增量 mean/P95 约0.92/1.16ms，活动视图32、空闲池上限32，关闭后活动视图0；GPU计时不可用，不能宣布完整GPU/整场性能验收。领域压力单列mean/P95/P99约0.884/1.029/1.125ms。
