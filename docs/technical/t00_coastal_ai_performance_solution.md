# 有岸地图 AI 决策性能解决方案

> 状态：方案定稿；稀疏拓扑走廊、统一请求入口、请求数预算、空间索引与分阶段性能统计已实施，严格可抢占微秒预算和全部绝对性能门槛尚未完成
> 适用范围：港湾、岛屿、浅水、航道、潮汐、设施和雷区共存的战斗地图
> 关联设计：`docs/16_enemy_ai_behavior_design.md`、`docs/35_scene_combat_domain_design.md`
> 配套航迹方案：`docs/technical/t01_inertial_navigation_and_emergency_avoidance.md`

## 0. 定稿结论

当前正式基线是“低频稀疏拓扑走廊 + `1s` 常规动力学航迹 + `0.1s` 白名单高威胁避险 + Domain 每 Tick权威碰撞”。**路线系统的目标是让角色顺利、持续且高效地完成移动意图；性能预算、请求节流和失败抑制都服务于这个目标，不能以永久停车、反复撞岸、无效绕行或大编队堵塞换取漂亮指标。** 战略路线只保障目标拓扑可达和剩余进度下降，不生成全程精确航线，不逐边积分水流收益，也不对所有候选重复完整扫掠或执行精确折线平滑；烘焙边、直达段、最终接入段和被选中的稀疏门间段仍须通过一次与运行时同口径的带半径连续合法性查询。

- `RoutePlanner` 复用三档审核导航图，以门间距 `180`、起终接入候选上限 `4` 输出有半径的走廊门；廉价中心线用于候选预筛，最终采用的线段由 `is_navigation_segment_clear` 校验。
- `NavigationRequestBroker` 是玩家与 AI 的统一战略路线入口；玩家优先，同级按提交序号，每 Tick最多完成 `1` 条。请求不合并、结果不缓存。
- 无安全旧走廊时进入 `StrategicRouteWaiting` 并停车；有旧走廊时继续执行；不可直接接入的目标在动态可达分量中解析为有正向进展的阶段门，同时保留语义目标；沉没单位取消排队请求。
- 紧急避险不进入战略请求队列，也不读取战略收益。常规航迹和 Domain 权威移动负责门间操舰、避岸、水流与碰撞。
- 当前预算对“每 Tick完整请求数”是硬上限；单条 A* 仍不可抢占，`2000us` 额度只能阻止继续开始下一条请求。后续若需要严格微秒上限，再将潮汐边检查和节点展开改为可暂停工作单元。

第 `13-14` 节保存实施审计和性能演进数据；若其历史描述与本节冲突，以本节及第 `14.6-14.9` 节的最终参数和结论为准。

## 1. 问题与基线

当前港湾 3v3 与普通海域 3v3 使用相同单位规模，但无图形固定 Tick 对照显示：普通海域在约 `2.34s` 内完成 `580` Tick；港湾运行 `600` Tick 已消耗约 `77.8s` 且尚未结束。按已执行 Tick 计算，港湾规则侧单 Tick 至少慢约 `32x`。因此主要瓶颈位于 AI、导航和地形查询，而不是海面 Shader 或岛屿贴图。

已确认的放大链路：

1. 港湾按吃水档包含三套约 `500` 节点的导航图；一次路径请求会重建查找表、扫描起终点邻近节点，并以重复排序数组执行 A*。
2. 路径候选、路径平滑、岸线风险、卡住恢复、鱼雷规避和设施任务会重复触发整段通行查询。
3. 潮汐通行当前按每 `4` 世界单位采样整段路线；水深合法性也沿线采样，并在采样点继续执行多边形区域判断。
4. 即时生存每 Tick 运行，战略、任务和设施决策虽有周期与局部缓存，但空间查询没有统一预算、共享结果或地图 revision 契约。
5. AI 计算超过单帧预算后，固定 Tick 在一帧中积压，表现为战斗速度下降、输入延迟和连续卡顿。

表现层逐帧重建环境区、设施和雷区节点是另一项独立性能问题，应另行治理；它不是本方案用来掩盖 AI 规则侧成本的理由，也不计入本方案的无图形验收结果。

## 2. 目标与非目标

### 2.1 目标

- 角色能够顺利、持续且高效地向语义目标移动；不得用降低请求/失败计数掩盖永久等待、重复失败、无效绕行、岸线振荡或大编队拥堵。
- 保持 AI 可见信息、评分公式、优先级、命令接口和 Domain 权威规则不变。
- 港湾 3v3 的无图形平均单 Tick 成本不高于普通 3v3 的 `3x`，P99 不高于 `5x`。
- 目标机器实时战斗中，规则更新 P95 不超过 `4ms/Tick`，P99 不超过 `8ms/Tick`；单帧不得因 AI 补算连续执行超过 `2` 个昂贵路径任务。
- 同地图、配置、命令和固定种子保持确定性；性能调度不得依赖真实帧率改变战斗结果。
- 11v11 有岸地图能够通过预算降级保持响应，不出现全舰同 Tick 重规划或永久无路可达。

### 2.2 非目标

- 不改变伤害、侦查、碰撞、吃水、潮汐或设施规则。
- 不允许 AI 绕过阵营观察隔离或使用隐藏真值。
- 不以降低固定 Tick 频率、减少舰船数量或关闭港湾机制作为正式优化。
- 不在本方案内处理 TerrainView 的逐帧节点重建、GPU 填充率或美术资源体积。

## 3. 核心原则

1. **静态答案预计算**：岸线、导航节点、边连接、空间索引和吃水兼容性在地图加载或制作管线中准备，不在每次决策时重建。
2. **动态通行按 revision 失效**：潮汐、设施控制和已知雷区分别维护单调 revision；revision 用于使旧走廊或排队请求失效，不要求引入路线缓存。
3. **高频安全只筛选迫近攻击**：每 `0.1s` 只对阵营已知鱼雷，以及白名单内的大口径主炮、高等级航空编队、伤害类技能做廉价风险扫描；岸线、边界、普通避碰和航迹进展由 `1.0s` 常规动力学航迹预防并由 Domain 每 Tick 兜底。任何高频路径都不执行完整 A*、设施全量评分或长距离逐点采样。
4. **低频规划统一排队**：舰队、编组和单舰通过统一路径代理请求路线；请求保持独立，不合并、不缓存。
5. **预算影响延迟，不影响规则**：超出预算的非紧急请求延后到确定的未来 Tick；硬碰撞和 Domain 合法性仍每 Tick 权威执行。
6. **先量测再替换**：每一阶段都保留旧实现作为对照，并用固定种子比较命令序列、结果和性能。

## 4. 目标架构

```text
AIObservation / BattleState
        |
        v
AI Decision Scheduler ---------> High-threat Emergency Scan
        |                         已知攻击、局部空间索引、每 0.1s
        v
Navigation Request Broker
        |
        v
Compiled Coastal Navigation
  审核 Profile -> 稀疏拓扑 A* -> 有半径走廊门
        |
        v

  岸线 BVH/网格 | 水域区域索引 | 潮汐边状态 | 雷区索引
        |
        v

```

建议新增职责：

| 组件 | 层级 | 职责 |
|---|---|---|
| `RoutePlanner` | Application | 加载审核导航 Profile，执行拓扑可达搜索并输出稀疏走廊门，不拥有战斗规则 |
| `NavigationRequestBroker` | Application | 预算、稳定排序、取消和异步式分 Tick交付；不去重、不缓存 |
| `AIDecisionScheduler` | Application | 按固定 Tick 时间轮调度任务/模式/路线重评 |
| `TerrainSpatialIndex` | Domain/Service 数据结构 | 为岸线、水域、环境区和雷区提供候选集合，不改变最终判定 |
| `AITraceProfiler` | Infrastructure | 记录各阶段耗时、调用次数、请求积压和等待时间，不参与决策 |

以上为当前正式职责边界；具体实现仍保持 `scripts/domain`、`scripts/application`、`scripts/infrastructure` 的现有分层。

## 5. 地图预编译与空间查询

### 5.1 编译导航图

地形生产管线应为每个导航 Profile 输出稳定的运行时结构：

- `nodes_by_id`：加载时构建一次，后续只读。
- `adjacency`：邻接节点索引和基础距离数组，避免运行时字符串字典反复查找。
- `regions` 与 `portals`：把约 `500` 个局部节点归入较少的连通分区；长路径先搜索分区/门户，再限定局部节点集合。
- `edge_clearance`：边对不同碰撞半径档和吃水标签的静态通行位。
- `edge_bounds`：用于环境区、潮汐和雷区的快速相交候选。
- `stable_order`：所有节点、边和门户保存确定性序号，同分不依赖字典遍历顺序。

A* 开放集改为二叉堆或等价优先队列。路径查询不得重新构造整张 `by_id`，不得每次弹出节点前对完整开放集排序。

### 5.2 分离静态与动态通行

一条边的通行结果拆为：

```text
static_passable(profile, edge)
and tide_passable(tide_revision, edge)
and hazard_passable(faction_knowledge_revision, edge)
```

- 岸线、固定浅水和航道属于静态位。
- 潮汐只重算与受潮汐控制区域相交的边，不扫描全部边。
- 雷区不改写物理通行位；它按阵营已知信息生成风险成本或禁行策略，并以阵营知识 revision 失效。
- 设施状态只在确实改变通道或任务目标时使相关旧走廊失效；普通设施 HP 变化不应使全图请求重建。

### 5.3 水域与环境空间索引

现有岸线障碍已有空间网格；水域区域、环境区和雷区需要同等候选索引。`regions_at`、`context_at` 和潮汐区域查询先取得所在网格候选，再执行精确多边形判断。

长线段不再每 `4` 单位全程采样：

1. 用线段包围盒查询可能相交的区域/边界。
2. 对候选边界做精确线段或扫掠相交。
3. 仅在曲线近似、碰撞半径膨胀或数值边界处做有限自适应采样。
4. Domain 最终移动继续使用连续扫掠与精确合法性校验，不能把导航近似当作权威碰撞结果。

## 6. AI 调度与查询预算

### 6.1 固定 Tick 时间轮

为单位分配由稳定实体 ID 推导的槽位，使昂贵决策均匀分布：

| 工作 | 推荐周期 | 每 Tick 行为 |
|---|---:|---|
| 战略走廊 | `3-5s` | 按单位稳定槽位错峰评估；仅 dirty 时搜索，紧急状态延后收益型重算 |
| 常规动力学航迹 | `1.0s` | 处理岸线、边界、普通避碰、编组与航迹进展 |
| 已知攻击风险扫描 | `0.1s` | 只筛选已知鱼雷、大口径主炮、高等级航空编队和伤害类技能，再精算少量候选 |
| 紧急避险轨迹 | `0.1s` | 仅紧急状态执行 `0.8-1.5s` 短候选，承诺前 `0.1-0.3s` |
| 目标与战术 | `0.5s` | 按单位槽位错峰 |
| 设施与关卡任务 | `2.0s` | 按编组或阵营统一评估，再分配给单位 |
| 编组与阵列 | `1.0s` | 事件可提前标记 dirty，但仍进入确定性槽位 |
| 完整路径规划 | 事件驱动 | 统一 Broker，每 Tick 有硬预算 |

扫描满足 `docs/technical/t01_inertial_navigation_and_emergency_avoidance.md` 的完整进入条件后，才切换紧急状态并生成极短避险轨迹。紧急状态不读取战略走廊收益；退出后再由常规航迹接回战略目标。这样避免普通岸线、边界或交通问题触发 `0.1s` 轨迹规划。

### 6.2 路径请求身份与独立交付

请求身份至少包含：

```text
profile_id
start_region_or_quantized_cell
goal_region_or_quantized_cell
movement_tags_hash
collision_radius_bucket
tide_revision
known_hazard_revision
navigation_revision
```

- 起终点先量化到导航单元；最终首尾段仍从真实位置做局部连接。
- 每条请求独立保留并按提交序号交付，不因起终点相似而合并。
- 成功和失败结果均不进入路线缓存；重复失败通过战略决策节流、等待状态和请求过期控制。

### 6.3 每 Tick预算与积压

当前正式预算：

- 所有规模每 Tick最多完成 `1` 条完整战略路线请求。
- 单次请求起点和终点各最多保留 `4` 个接入候选。
- `2000us` 是开始下一请求前检查的时间额度，不可抢占已开始的单条 A*，不得表述为严格微秒硬上限。

请求优先级固定为：致命路径恢复、当前路径失效、关键任务、编组移动、普通战术调整。同优先级按请求 Tick、阵营稳定顺序、单位 ID 排序。积压只延迟新意图，不停止旧路径执行；若旧路径已非法，则单位保持或执行局部安全脱离。

## 7. 高威胁攻击快速路径

高频路径不能共享完整战略或常规航迹的成本模型。每 `0.1s` 只执行：

- 从阵营已知攻击空间索引取得反应窗内的鱼雷、固定落区或公开预警区。
- 按正式语义白名单过滤；普通小口径攻击、副炮、低等级航空和非伤害技能不进入高频候选。
- 鱼雷先按距离与接近方向筛选，再解析计算 CPA；白名单攻击的固定落区只与当前常规轨迹包络做相交。
- 未满足高威胁进入条件时仅输出风险结果，不生成紧急轨迹候选。
- 进入紧急状态后只比较固定数量的 `0.8-1.5s` 控制候选，并只承诺前 `0.1-0.3s`。

岸线、边界、普通舰船避让、编组和航迹进展不进入高频扫描。它们由 `1.0s` 常规动力学航迹治理；地形与碰撞仍在紧急候选硬过滤和 Domain 每 Tick 权威移动中保持生效。

首轮硬预算：常规候选 `<=12`；紧急基础候选 `<=5`、扩展后总候选 `<=7`；常规/紧急控制段分别 `<=3/2`；单紧急候选积分样本 `<=16`；单舰精算攻击 `<=8`。多舰同 Tick 紧急时优先复用仍降低风险的旧控制，只运行基础候选集，并裁剪全部战略与软收益评分。

## 8. Revision 失效与确定性

需要显式 revision：

| Revision | 变化来源 | 失效范围 |
|---|---|---|
| `navigation_revision` | 地图/导航数据加载 | 全部路线 |
| `tide_revision` | 潮汐通行阶段改变 | 与潮汐边相交的路线 |
| `facility_objective_revision` | 所有权、存活或任务能力改变 | 设施任务目标与相关终点 |
| `known_hazard_revision[faction]` | 雷区首次获知、失效或安全航道改变 | 该阵营风险路线 |
| `observation_revision[faction]` | 目标/残影集合变化 | 战术目标，不默认清空静态路径 |

所有请求、延后和结果交付都绑定战斗 Tick。禁止用 `Time.get_ticks_*`、线程完成先后或真实帧率决定结果顺序。未来若把搜索放入 WorkerThread，线程只能计算不可变请求；主线程按预定 Tick和请求序号接纳结果，超时则走确定性降级。

## 9. 降级、诊断与安全网

当路径预算持续积压时：

1. 复用未失效旧路径。
2. 编组成员复用组长走廊，只计算局部接入。
3. 暂缓掩体、侧翼等收益型路线，不暂缓已知高威胁攻击扫描；岸线与边界仍由 Domain 硬规则兜底。
4. 连续无进展不再生成 `PathRecovery` 临时航点；改为标记战略走廊失效并进入 `SafetyHold`，允许短时停车或倒车，等待预算化的走廊请求选择局部安全目标。
5. Domain 的移动、碰撞、吃水、潮汐和命令合法性始终是最后安全网。

## 10. 实施阶段

### 阶段 A：量测与回归基线

- 在 `BattleSession.advance_tick` 的移动、侦查、AI、导航、设施和快照阶段加入可关闭的微秒统计。
- 固定普通 3v3、港湾 3v3、港湾 5v5/11v11 压测种子与最大 Tick。
- 记录命令序列摘要、胜负、时长、碰撞、卡住、路径失败和设施响应，作为语义回归基线。

### 阶段 B：无行为变化的查询优化

- 导航图只读编译、节点索引、邻接数组、优先队列。
- 为水域、环境区和雷区建立空间索引。
- 用边界相交替代固定 `4` 单位全段采样，并以旧实现做随机线段差分测试。

阶段 B 必须优先落地，因为它不改变 AI 调度语义，最适合隔离正确性风险。

### 阶段 C：统一路径代理

- 引入统一 Broker、revision、请求取消和独立交付，不合并、不缓存。
- 所有 AI 完整路径入口迁移到 Broker；玩家路径仍可同步优先处理，但复用同一编译图。
- 删除绕过 Broker 的 AI `plan_path` 调用前，使用断言和调用统计确认迁移完整。

### 阶段 D：预算化决策调度

- 目标、战术、设施和编组按稳定槽位错峰。
- 即时生存按 `t01` 拆为 `1.0s` 常规动力学航迹与只针对已知高威胁攻击的 `0.1s` 快速路径。
- 启用每 Tick路径预算、稳定优先队列和确定性降级。

### 阶段 E：关卡规模验收

- 单项导航或性能改动默认只执行 `1 -> 3` 个固定种子基准，检查正确性、性能采样和异常记录可复现。
- 港湾 3v3 的 30 种子侧别交换、代表性岛屿 5v5/11v11 的规模验证及带画面 P95/P99 验收，只能在人工明确指定为大版本性能改动时执行。
- 大版本性能验证在目标机器做带画面实机验证；AI 规则合格与表现层合格分别记录，不能互相替代。

## 11. 测试与验收

### 11.1 正确性

- 地形线段、扫掠、水深、潮汐和雷区查询以旧实现为 oracle 做随机差分；边界误差使用统一 epsilon。
- 路径必须逐段通过 Domain 权威合法性检查。
- 同固定种子重复运行的命令序列摘要、结果和统计完全一致。
- 关闭调度优化时，新导航实现不得改变可达/不可达结论；开启错峰后允许命令 Tick 延后，但不得改变观察权限和硬约束。
- 隐藏敌舰、未知雷区和未发现设施不能进入缓存键或路径成本。

### 11.2 性能门槛

| 场景 | 必须达到 |
|---|---|
| 普通 3v3 | 不比优化前回退超过 `10%` |
| 港湾 3v3 无图形 | 平均单 Tick不高于普通 3v3 `3x`，P99 不高于 `5x` |
| 港湾 3v3 实时 | 规则 P95 `<=4ms/Tick`，P99 `<=8ms/Tick` |
| 港湾 11v11 压测 | 路径队列有界，无持续增长；无全舰同 Tick重规划 |
| 请求队列 | 队列长度和最老等待时间有界；无重复请求导致的持续增长 |

若目标机器差异较大，应在报告中同时保存 CPU、Godot 版本、渲染模式、构建类型和是否 headless；不得只报告总墙钟时间。

### 11.3 行为门槛

- 岸线碰撞、卡住、无路可达和边界钳制次数不高于优化前基线。
- 设施首次响应 P95 不超过设计周期加一个调度周期。
- 致命鱼雷和白名单高威胁伤害攻击的扫描/避险不允许因路径预算延迟；未来触岸由常规航迹预防并由 Domain 每 Tick 阻止非法位移。
- 人工指定的大版本性能批次中，不出现因队列积压导致的永久保持、重复同终点失败或任务永不分配。

## 12. 完成定义

### 14.3 门槛判断与风险

- **架构搭配成立，最终性能不合格。** 开阔 3v3 航迹 P95 为 `2.77ms`，表明短时动力学候选本身可控；但港湾平均 Tick 为开阔 3v3 的 `3.70x`，高于 `3x`，港湾 P99 为其 `21.6x`，远高于 `5x`。
- **最大风险已定位到同步战略路线。** 多张近岸图出现 `135 -> 242ms` 的 P99，个别 Tick 最大值更高；这些尖峰与低频完整走廊请求同 Tick执行相符。现有 `3/5s` 节流降低了频率，却没有限制一次 Tick 内的 A* 工作量，因此低频不等于预算有界。
- **大编队还有既有 AI 决策峰值。** 11v11 的 AI 决策 P95 为 `44.24ms`，高于航迹 P95 `8.68ms`；初始错峰只能削峰，目标/战术/编组及战略走廊仍需要统一预算队列和跨 Tick续算。
- **0.1s 扫描当前不是统治热点。** 每艘存活舰每 Tick只做轻量高威胁扫描，只有确认鱼雷或白名单高伤害攻击才进入紧急候选；本轮数据不支持为常规触岸风险启用紧急规划。
- 下一步继续完善 `NavigationRequestBroker`：紧急避险不入队，AI 战略走廊按稳定优先级实施可暂停的节点/微秒预算与过期取消，之后再进行有岸 11v11 合成压测与带画面验收。按当前决策不做请求合并和路线缓存。当前仓库没有有岸 5v5/11v11 关卡，因此本次全量测试只能覆盖现有十张有岸 3v3，不能据此宣称“有岸 11v11 已通过”。

### 14.4 首阶段统一请求入口

运行时已加入统一 `NavigationRequestBroker`，玩家和 AI 的战略走廊均先排队；每 Tick最多完成 `1` 条请求，玩家请求优先，同优先级保持提交顺序。请求不合并，也不使用成功或失败路线缓存。单位没有安全旧走廊时进入 `StrategicRouteWaiting` 并停车，有旧走廊时继续执行，完成后再原子替换走廊；沉没单位的排队请求会取消。紧急避险仍直接使用短时动力学候选，不进入战略队列。

复测中战略走廊单 Tick峰值已稳定为 `1`：开阔 11v11 的平均/P95/P99 从 `23.05/66.20/103.05ms` 降至 `18.28/42.81/57.33ms`。港湾 3v3 仍为 `13.14/17.85/177.40ms`，基本没有改善，证明剩余尖峰主要来自单条不可抢占路线调用，而不是多请求叠加。

因此当前只完成了“请求数量硬预算”，尚未完成严格的“微秒/节点扩展硬预算”。现有 A* 一旦开始仍需在当前 Tick返回；`2000us` 时间额度只能阻止开始下一条请求，不能中断当前请求。下一阶段必须把起终连接检查、A* 节点展开和路线平滑改为可暂停续算的工作单元，才能把单 Tick时间上限称为真正完成。按当前明确范围，不增加请求合并和路线缓存。

### 14.5 单条路线尖峰分解

对港湾、散布岛屿和环礁泻湖的单条请求进一步拆分计时。当前每个导航 Profile 约 `462 -> 540` 个节点，最慢样本的 A* 实际展开 `2 -> 210` 个节点；尖峰并不主要来自堆和节点展开，而来自 A* 前后的权威线段合法性查询。

| 代表样本 | 总耗时 | 起终接图 | A* / 展开数 | 平滑 | 主要占比 |
|---|---:|---:|---:|---:|---|
| 港湾最慢 | `256.08ms` | `103.76ms` | `36.42ms / 196` | `115.57ms` | 接图 `40.5%`，平滑 `45.1%` |
| 港湾低展开尖峰 | `196.80ms` | `148.61ms` | `8.64ms / 38` | `39.15ms` | 接图 `75.5%` |
| 散布岛屿最慢 | `219.43ms` | `197.58ms` | `0.13ms / 2` | `20.92ms` | 接图 `90.0%` |
| 散布岛屿长线 | `163.40ms` | `20.88ms` | `14.03ms / 132` | `127.39ms` | 平滑 `78.0%` |
| 环礁泻湖最慢 | `187.00ms` | `11.59ms` | `5.97ms / 60` | `168.74ms` | 平滑 `90.2%` |

根因是 `is_movement_segment_clear` 除岸线扫掠外，还通过 `_first_illegal_movement_fraction` 以约 `max(4, radius*0.25)` 的步长扫描整条线段，每个样点再次执行圆占位与区域多边形查询，遇到边界还会做 `16` 次二分。起终接图会对 `5x5` 空间单元内、距离 `420` 内的多个节点逐一执行该查询；当前平滑又从近到远测试全部剩余航点，长路线形成近似二次的重复长线扫描。

后续优化顺序应为：平滑改为从最远候选向近端搜索并命中即停；接图候选先按距离排序、找到 `8` 个可见节点后停止；静态水深/岸线边界使用烘焙 Profile 或空间索引下的精确边界相交，避免固定步长扫描。完成这些之后再判断是否需要优化 A* 本体；当前数据不支持优先重写堆或启发函数。

### 14.6 稀疏拓扑走廊实施与参数选择

战略层现改为只解决长期可达与拓扑进展：复用三档审核导航图，以中心线和距离做廉价候选预筛，A* 决定岛屿绕行侧和水道序列，再输出有半径的走廊门。烘焙边、直达段、最终采用的起终接入段和稀疏门间段统一用 `is_navigation_segment_clear` 做一次带 Profile 半径的连续校验：硬岸与地图边界使用扫掠，水域按区域边界交点分段并取最高优先级移动语义。战略层不对全部候选重复完整扫掠，不执行固定步长水深长线扫描、精确折线平滑或逐边水流收益积分；非法浅水目标投影到最近可达门。短时动力学航迹负责门间操舰和避岸，Domain 每 Tick仍执行权威扫掠碰撞。
