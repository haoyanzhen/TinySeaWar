# 航行走廊、短时动力学轨迹与紧急规避解决方案

> 状态：方案定稿且核心运行时已实施；全部高威胁类别实战覆盖、带画面人工航行审查和剩余绝对性能门槛待完成

> 关联设计：`docs/16_enemy_ai_behavior_design.md`、`docs/21_combat_data_schema.md`、`docs/22_scene_environment_data_schema.md`、`docs/24_ai_data_schema.md`、`docs/32_domain_design_phase1.md`、`docs/35_scene_combat_domain_design.md`
> 关联方案：`docs/technical/t00_coastal_ai_performance_solution.md`

## 1. 结论

正式方案采用：

```text
战略/任务目标
  -> 3-5s 后台战略走廊
    -> 1.0s 常规动力学航迹
      -> 0.1s 高威胁紧急避险
        -> Domain 每 Tick 权威运动与碰撞校验
```

**航点连线不再是 AI 舰船的核心航迹模型。** 航点只保留为玩家连续命令、任务目标和全局走廊门户的兼容输入；舰船实际执行的是一段在航行走廊内、由当前航向、航速、推进变化、最大转向能力、海况和水流共同预测得到的短时轨迹。

舰船移动慢、推力变化慢、转向变化慢，正常航迹没有必要每帧重新求解。三层规划分别治理不同时间尺度：

- 后台战略走廊：通常每 `3.0s` 评估一次，高稳定任务可放宽到 `5.0s`；评估只在意图或 revision 为 dirty 时提交完整搜索，其余继续复用旧走廊。
- 常规动力学航迹：约每 `1.0s` 规划一次，以当前战略走廊的前向区域为目标，负责推进、转弯、水流补偿、避岸、边界、编组和普通舰船避让。
- 高威胁扫描：每 `0.1s` 只检查已知鱼雷，或符合白名单的大口径主炮、高等级航空编队、伤害类技能是否形成迫近命中风险。
- 紧急避险航迹：只有高威胁满足进入条件后才按 `0.1s` 重算；避险时完全忽略战略走廊的收益与进度，只服从攻击生存和硬通行。
- Domain 移动：继续每个固定 Tick 积分和校验，不因规划降频而降频。

本方案追求的是**安全、稳定、顺利且高效地实现移动意图的满意轨迹**，不是精准跟线、全局最短或连续最优。成功必须同时包含持续任务进展、合理安全余量和可接受的交通/计算成本；请求变少、失败变少或短暂停车本身不等于路线成功。

当前定稿参数与运行时状态：战略走廊门间距 `180`、起终接入候选 `4`；常规航迹周期 `1.0s`、最多 `6` 个候选、预测时域 `6.0s`；高威胁扫描和紧急航迹周期 `0.1s`，紧急基础 `5` 个候选、扩展后最多 `7` 个，预测时域 `1.2s`；紧急威胁连续清除 `4` Tick 后退出。战略请求统一进入 `t00` Broker，不合并、不缓存，每 Tick最多完成 `1` 条。

## 2. 为什么不使用传统航点连线

传统航点路径默认单位可以随时朝向下一点并沿线移动，而舰船至少具有以下约束：

- 当前速度具有惯性，推进与减速需要时间。
- 航向变化受最大转向速度或最大侧向能力限制。
- 同一转向命令在不同速度下需要不同空间。
- 水流会产生与舰首方向不同的地面位移。
- 海况、状态效果和编组修正会改变推进与转向能力。
- 舰体是随航向旋转的椭圆，而不是导航图上的无方向点。

因此一条几何上不穿陆地的折线，仍可能发生：

- 大型舰来不及在门户前完成转向。
- 高速舰切过折线内角并触岸。
- 舰船为了追逐下一个点连续左右摆动。
- 逆流把舰船推离航线，控制器不断修正又无法收敛。
- 紧急规避选择了位置安全、但以当前速度和航向无法到达的航点。

另一方面，完整动力学 A*、连续最优控制或高精度水动力学求解对 MVP 过重：状态空间会包含位置、航向、速度、转向状态、环境和时间，性能、确定性与调参成本都远高于收益。因而采用“低频走廊 + 有限短轨迹”的折中。

## 3. 已实施基线与兼容边界

当前运行时基线：

- `RoutePlanner` 已改为使用共享导航图搜索拓扑可达性并输出稀疏走廊门；中心线只预筛候选，最终采用的直达、接入和稀疏门间段仍执行一次带 Profile 半径的连续合法性查询，不再对全部候选重复完整扫掠或执行折线路径平滑。
- 战略语义目标与执行阶段目标已分离；目标不能直接接图时，在动态可达分量中选择减少剩余距离的阶段门，完成后仍按原语义目标重评。
- `BattleSession` 已按 `current_speed`、`heading`、`turn_speed` 和 `current_vector` 计算连续位移。
- Domain 已有随航向旋转的舰体碰撞、整段地形扫掠、水深、潮汐和边界校验。
- `ShipMotionService.simulate_control_sequence()` 已按战斗 `0.1s` 固定 Tick 展开完整姿态样本，规划预测与权威移动共享推进、转向、水流、倒车和环境倍率的积分顺序。
- 常规航迹固定验证未来 `6.0s`，紧急航迹验证 `1.2s`；每个相邻样本段先经过静态碰撞场宽相，不确定时再做带舰体半径的规则多边形连续窄相。
- `4` 世界单位额外导航余量只约束新移动：Domain 硬半径合法的静止姿态仍可保持，朝岸外侧的控制可经精确扫掠脱离软余量，避免在岸边每秒重复 `NO_SAFE_TRAJECTORY`。
- 玩家直接目标优先使用全推力、最大有效舵角持续转至对齐，再以全推力直行；仅当该轨迹不安全时才依次尝试直行后转、减速转或外扩恢复模板。
- 同 revision 的已承诺航迹一旦被 Domain 拒绝，当前控制和计划在同 Tick 立即失效，下一个 Tick 从真实状态重算并产生契约诊断。
- AI 已有鱼雷 CPA、岸线/边界常规航迹约束、停车/倒车恢复和被打断前移动状态。
- `t00` 已定义空间索引、分层导航、revision、固定 Tick 调度与完整路径预算；当前明确不做路线缓存和请求合并。

玩家目标点和连续航点保留为意图输入，但运行时不再执行旧折线跟随。玩家命令仍表达“去哪里”，不要求舰船精确经过每个数学点；只有关卡明确标记的强制门户、靠泊入口和任务区域才具有必须通过或满足到达姿态的语义。旧 `ShoreEscape`、`BoundaryEscape`、`PathRecovery` 和鱼雷规避临时航点链已被当前状态机与动力学控制替换，不得重新接回运行时。

## 4. 目标与非目标

### 4.1 目标

- 合法移动意图能够形成持续正向进展，并以可接受的路线长度、交通冲突和计算成本完成；节流、等待和恢复不得成为掩盖无效移动的完成口径。
- 拓扑连接和门户中心必须合法；常规/紧急候选轨迹不能穿过陆地、非法浅水、不可进入的潮滩、硬边界或显式硬禁区。走廊门半径只表达进度容差，不宣称门内每一点都可通行。
- 正常航行具有连续、缓慢且可读的加减速和转向，不追逐折线产生蛇形。
- 水流影响轨迹预测和地面位移，AI 能提前补偿但不要求精确抵消。
- 大小舰和不同航速使用各自的转向空间、停车距离和自适应预测时域。
- 战略走廊保持 `3-5s` 低频，常规航迹保持约 `1.0s`；只有迫近高威胁攻击进入后使用 `0.1s` 级避险重算。
- 全局走廊、正常轨迹、紧急轨迹和 Domain 权威规则职责分离。
- 同输入、配置和固定种子产生相同走廊、轨迹候选顺序、打断与恢复结果。

### 4.2 非目标

- 不模拟真实舵机、螺旋桨、波浪六自由度或精确船舶水动力；倒车只保留满足脱困所需的简化推进过程。
- 不要求舰船精准经过走廊中心线或精准抵达普通目标点。
- 不进行覆盖整段战场航程的连续动力学轨迹计算。
- 不保证全局最短、绝对最安全或数学意义上的最优轨迹。
- 不把目标选择、武器射击、设施收益或战略模式塞入轨迹求解器。
- 不用预测结果代替 Domain 的权威运动、碰撞和通行校验。

## 5. 简化动力学模型

### 5.1 状态与控制

短时预测只使用游戏已经拥有或容易稳定推导的状态：

```text
state = {
  position,
  heading,
  current_speed,
  acceleration_limit,
  braking_limit,
  turn_rate_limit,
  lateral_acceleration_limit(optional),
  collision_extents,
  movement_tags,
  current_vector,
  movement_speed_multiplier
}

control = {
  thrust_ratio[-1, 1],
  turn_ratio
}
```

- `thrust_ratio` 表示期望推进档或期望速度趋势，不直接修改位置；负值表示倒车推进。
- `turn_ratio` 位于 `[-1, 1]`，表示左右转向能力使用比例。
- 首轮可继续使用现有 `turn_speed` 作为最大航向变化率。
- 若后续增加最大侧向能力，则用速度相关上限约束转率：高速下不能保持与低速相同的极小转弯半径。
- 水流是外部地面速度，不改变舰首朝向；预测轨迹必须叠加水流位移。
- 倒车不能从前进瞬时切换：必须先按制动能力降到近零，再进入受限倒车速度；倒车上限应显著低于前进航速，并继续受水流、转向和碰撞规则约束。

简化积分概念为：

```text
speed      <- approach(speed, desired_speed, acceleration_or_braking * dt)
turn_rate  <- clamp(turn_ratio * turn_rate_limit, lateral_limit_at(speed))
heading    <- heading + turn_rate * dt
position   <- position + (forward(heading) * speed + current_vector) * dt
```

实际实现必须复用 Domain 当前运动公式或抽出同源的纯计算函数，不能让规划器和权威移动分别维护两套近似公式。

### 5.2 精度边界

轨迹预测允许近似：

- 环境在短预测窗内按当前公开值保持不变。
- 推力和转向在一个控制片段内保持常量或只取少量档位。
- 碰撞使用保守膨胀舰体或扫掠包络，不要求预测每一帧的精确椭圆接触点。
- 友军在正常规划中按当前控制趋势或已发布轨迹预测，敌舰只按合法观察信息做保守短期外推。

误差由安全余量、下一次重算和 Domain 每 Tick 校验吸收。预测不精确不是频繁重规划的理由；只有轨迹安全性、走廊归属或任务进展明显失效才重算。倒车只用于靠泊、脱困或紧急恢复，不参与普通远航候选，避免常规航迹频繁前后切换。

非玩家航路连续 `4s` 既无至少 `18` 单位位移、也无至少 `8°` 有效转向且未进入目标邻域时，先执行一次确定性的短时倒车转艏并重算常规航迹；只有恢复后累计至 `20s` 仍无进展才记录 `AIPathStuck`。短时转艏、等待战略走廊或抵达目标附近不属于路径卡住。

## 6. 系统分层

```text
RouteIntent
  去哪里、为何去、容许怎样到达
        |
        v
NavigationCorridor
  3-5s 后台战略：连通水域、门户、宽度和方向
        |
        v
TrajectoryWindow
  1.0s 常规规划：兼顾战略目标与航行安全
        |
        +----> EmergencyTrajectory
        |      0.1s 高威胁避险：暂时忽略战略走廊
        v
Domain Authority
  每 Tick 真实积分、地形/水深/潮汐/碰撞与最终位移
```

| 层级 | 更新频率 | 输出 | 不负责 |
|---|---|---|---|
| `RouteIntent` | 任务、目标或玩家命令变化 | 目标区域、到达容差、策略 ID | 绕岛细节 |
| `NavigationCorridor` | 通常 `3.0s` 评估，稳定任务可 `5.0s` | dirty 时更新分区/门户及有宽度的战略走廊 | 逐 Tick 操舰与紧急避险 |
| `TrajectoryWindow` | 正常约 `1.0s` | 兼顾战略进展的常规控制序列和预测包络 | 全图搜索与攻击闪避 |
| `EmergencyScan` | 每 `0.1s` | 已知攻击的命中风险、CPA/预计影响时间 | 岸线、边界和普通交通治理 |
| `EmergencyTrajectory` | 仅紧急状态每 `0.1s` | 极短避险控制序列 | 战略进展与永久任务替换 |
| Domain | 每固定 Tick | 权威位置、碰撞和拒绝结果 | 战术收益选择 |

`OffshoreTransit`、`CoastalDefense` 等是轨迹/走廊策略，只改变走廊代价、目标进展和控制偏好；它们不是 `ReconAvoid`、`TorpedoFlank`、`GunlineSupport` 等战略 AI 模式。

### 6.1 航行状态机

```text
                 高威胁进入条件满足
NormalNavigation ----------------------> EmergencyEvasion
       ^                                      |
       |                                      | 全部退出条件持续满足
       +--------------------------------------+

任一状态无法生成硬合法控制
       -> SafetyHold
       -> 制动并等待下一次合法常规/紧急计划
```

状态职责：

| 状态 | 使用战略走廊 | 规划周期 | 负责 |
|---|---:|---:|---|
| `NormalNavigation` | 是 | `1.0s` | 日常航行、避岸、边界、普通避碰、编组、设施接近和战略进展 |
| `EmergencyEvasion` | 否，仅保存引用 | `0.1s` | 已知鱼雷或白名单高威胁伤害攻击的即时闪避 |
| `SafetyHold` | 否 | 每 Tick 执行最低风险控制，按对应状态周期重试 | 没有完全安全候选时的确定性降级 |

后台战略走廊不是航行状态。进入 `EmergencyEvasion` 后保留现有走廊引用；到达 `3-5s` 更新槽时只记录 `strategic_update_due`，普通收益型重算延后到退出紧急状态，避免计算暂时不会使用的战略结果。只有地图、潮汐等硬 revision 变化需要立即把旧走廊标记失效。紧急状态不读取走廊进度、阵位、岸距偏好、武器舷角或任务收益。退出时先处理延期的战略更新，再立即触发一次 `NormalNavigation` 规划。

`SafetyHold` 保存进入前状态：仍存在高威胁时按紧急周期寻找避险控制；没有高威胁时按常规周期寻找合法航迹。它不是固定最大制动：紧急情况下选择所有可执行结果中预计伤害最低或 CPA 最大者，必要时允许受控触岸/短暂停止；常规情况下才优先制动。找到候选后回到对应状态，持续失败则保持当前最低风险控制并输出明确原因。

### 6.2 不启用紧急规划的情况

以下情况由 `NormalNavigation` 或 Domain 治理，不启动 `0.1s` 紧急候选规划：

- 正常靠岸、弯道、浅水、潮汐边界和地图边界处理。
- 普通友军避让、编组调整、瓶颈排队和航道会船。
- 走廊偏离、逆流漂移、航速不匹配和航迹进展不足。
- 目标、设施、阵位、射程带或战略模式变化。
- 仅仅被敌舰发现、锁定或进入敌方理论射程，但尚无已提交的高威胁攻击。
- 低威胁攻击，或即使保持当前常规轨迹也不会形成有效命中的攻击。

常规规划必须预先生成不触岸、不越界的航迹。若仍发生地形风险，视为常规航迹失效或实现缺陷，由 Domain 截停并立即请求常规重算，而不是长期依赖紧急状态修补。

## 7. 航行走廊

### 7.1 表达

全局规划返回有宽度的连通走廊，而不是要求舰船追踪节点连线：

```text
NavigationCorridor = {
  region_ids,
  portals,
  local_bounds,
  minimum_clearance,
  preferred_flow_direction,
  bottleneck_flags,
  navigation_revision,
  tide_revision,
  known_hazard_revision
}
```

- `region_ids` 和 `portals` 解决从当前水域到目标水域的拓扑连通。
- `local_bounds` 表示舰体中心在扣除碰撞安全尺度后可活动的区域。
- `minimum_clearance` 用于提前拒绝不适合大型舰或当前转向状态的瓶颈。
- 中心线只用于启发式进度估计和调试显示，不是必须精准跟随的轨迹。
- 走廊可以比导航节点路径宽，允许舰船为了转弯、水流补偿、编组和避让在其中横向移动。

当前实现复用三档审核导航图作为拓扑骨架，以中心线和距离廉价预筛起终候选，按 `180` 世界单位前视间距输出圆形走廊门；每次最多保留 `4` 个起终接入候选。最终采用的直达、起终接入和稀疏门间线段使用 `is_navigation_segment_clear` 校验：连续扫掠硬岸与地图边界，并按区域边界分段验证最高优先级移动语义。门是局部航迹的进度区域，不是必须命中中心的数学航点。

`RouteIntent` 保存原始语义目标，`NavigationCorridor.target_position` 保存当前可执行阶段目标。语义目标无法直接接图时，规划器遍历当前动态可达分量，选择比起点更接近语义目标的阶段门；找不到正向进展才报告失败。完成阶段走廊不能清除或改写原始意图。

### 7.2 必须满足的硬原则

1. 拓扑节点、连接和门户中心不得位于陆地或对当前吃水非法的水域；走廊门的几何包络只表达进度容差，不能替代局部航迹与 Domain 的硬通行检查。
2. 拓扑连接按舰体安全尺度使用对应审核 Profile；大型舰不能复用小型舰的窄通道结论。
3. 烘焙边、直达段、最终接入段和被选中的稀疏门间段必须通过与运行时同口径的带半径连续线段查询；廉价候选预筛不能成为合法性结论。
4. 吃水、潮汐和明确禁区是硬通行；已知雷区、岸炮、威胁、逆流和拥堵通常是软代价。
5. 未知雷区、隐藏敌舰和未公开设施不能进入走廊代价或请求内容。
6. 走廊只描述可活动区域，不承诺任意入口状态都能完成任意急转；短时轨迹仍须验证当前控制是否可执行。但“未来不能直接转出”不是硬拒绝条件，舰船可以停车并通过倒车脱离。
7. 门户必须保存有效宽度和推荐通过方向；瓶颈前的减速、排队和阵型转换空间属于优先偏好，不把缺少前向出口误判为永久不可达。
8. 编组共享主走廊，成员各自规划短轨迹；阵位不能把成员推出合法走廊。
9. 走廊结果使用稳定排序和统一 Broker；按当前范围不合并请求、不做正负路线缓存。
10. 相同语义目标已有排队请求时不得重复提交；分类失败后使用确定性退避，并在单位明显移动或意图改变时重新开放。退避只限制失败风暴，不得替代阶段推进。

### 7.3 长距离规划

- 长距离只搜索拓扑连接和走廊门，不执行整段精确扫掠、动力学轨迹或水流收益积分。
- 当前舰船只读取当前走廊段及足够计算短时轨迹的前方局部段。
- 远端走廊细节在接近时再加载或细化，不随总航程生成线性增长的航点。
- 仍合法且能取得进展的旧走廊优先复用；新走廊只有在明显更安全、任务改变或旧走廊失效时替换。
- 直达水域可使用单一宽走廊，不必为了形式统一插入导航节点。

## 8. 短时动力学轨迹规划

轨迹层采用**滚动时域**：每次只预测未来数秒，提交并执行控制计划的前部；到下一规划槽后，从 Domain 的真实位置、航向和速度重新预测。规划器不要求实际轨迹逐采样点重合，只要求单位保持在预测安全包络和走廊容差内，并持续取得足够进展。

### 8.1 固定 Tick 预测窗

正常轨迹约每 `1.0s` 重算一次。当前实现按战斗 `0.1s` 固定 Tick 验证未来 `6.0s`，共保存初始姿态加 `60` 个逐 Tick 样本；紧急轨迹验证 `1.2s`。预测距离仍由速度、转向半径、水流和每 Tick 环境上下文自然决定，而不是用粗时间步或固定航点数近似：

```text
required_horizon_distance = max(
  minimum_lookahead,
  stopping_distance * braking_safety_factor,
  turning_radius * upcoming_turn_factor,
  current_drift_distance
)
```

- 慢速小舰在相同时域内形成较短空间前视。
- 高速、大型或低转向能力舰船在同一 `6.0s` 窗内自然覆盖更长停止距离和转弯弧线。
- 轨迹只读取当前战略走廊的一至两个前向门和局部环境，不展开全局精细航迹。
- 若走廊前方存在急弯或窄门户，允许在当前轨迹中提前降推力，而不是等到下一门户才制动。
- 固定 Tick 展开可以用局部标量状态消除逐段对象复制，但每个输出样本必须继续与 `ShipMotionService.step()` 的 Domain 顺序逐 Tick 等价；当前地图没有活动的空间运动区时，可复用起点已解析的全局运动上下文，存在局部水流、海况或移动倍率区时仍须逐样本重查。

### 8.2 有限控制序列

不进行连续变量优化。规划器从固定且有稳定顺序的控制模板生成少量轨迹：

- 保持当前推进与转向趋势。
- 保持航向并巡航、减速或制动。
- 左/右小幅转向。
- 左/右中等转向并保持或减速。
- 左/右最大允许转向并减速。
- 面向靠泊或任务入口的低速接近。
- 玩家直接目标的首选模板保持全推力，以最大有效舵角转到实际对齐后归中直行；对齐可能跨越多个控制秒，不得为了 `1s` 承诺窗口提前放平舵。

每个候选由有限个分段常量控制组成。正常状态优先在上次控制附近采样，减少视觉抖动；只有上次计划失效时才扩大候选集合。候选数量必须固定封顶，不能随地图节点数、障碍数或总航程增长。模板按保持全速进展到减速/恢复的稳定顺序验证；只要意图保持模板在整个预测窗内达到当前 `96` 世界单位舒适净空带，即可提前接受，不再为软收益计算更慢候选。`96/80/64/48` 跨图扫描后保留 `96`；近岸不确定、弯道/终点接近、恢复和紧急场景仍验证所需候选集。

### 8.3 硬过滤与满意度评分

候选首先通过硬过滤：

- 预测包络不穿陆地、非法水深、不可进入潮滩和硬边界。
- 每段转向与推力不超过当前动力学上限。
- 进入瓶颈前具有足够舰体通过宽度；出口姿态和继续前进空间作为软评分，不作为动力学死湾硬约束。
- 不与已确认近距友军轨迹产生不可恢复的碰撞。

硬过滤后再按满意度评分：

```text
trajectory_utility =
  corridor_progress
  + clearance_margin
  + terminal_goal_fit
  + control_continuity
  + formation_fit
  + tactical_soft_value
  - soft_hazard_cost
  - unnecessary_control_change
```

安全采用词典序优先：穿越陆地等硬非法候选永不因目标收益高而胜出。常规候选达到最低安全、进展和稳定阈值后即可接受；新候选若没有超过切换收益阈值，则继续执行旧计划，不追求每次最优。紧急状态允许“停在岸线接触前”作为最后手段，因为短暂停止或随后倒车通常优于硬吃高额伤害。

### 8.4 正常重算条件

正常轨迹满足任一条件才重算：

- 到达约 `1.0s` 固定规划槽。
- 当前轨迹即将耗尽。
- 舰船明显偏出预测包络或走廊安全带。
- 环境/潮汐 revision 使当前局部段失效。
- 任务目标、到达姿态或编组职责改变。
- 当前轨迹连续未取得最低进展。
- 廉价普通交通 CPA 发现下一常规槽前可能发生近距冲突；此时只提前触发一次常规重算，不进入 `EmergencyEvasion`。

普通软威胁的小幅变化、轻微水流误差或发现略优路线不触发立即重算。交通事件提前重算必须有单独的最小间隔和稳定让行优先级，不能退化为所有舰船每 `0.1s` 执行常规规划。

## 9. 高威胁扫描与紧急避险

### 9.1 紧急状态的治理范围

首轮只有以下两类已知攻击可以进入 `EmergencyEvasion`：

| 类型 | 必要证据 | 典型判据 |
|---|---|---|
| `TorpedoEvasion` | 本阵营已经发现、仍存活且正在接近的鱼雷 | 保持当前控制或常规候选时，CPA 小于安全半径且预计到达 CPA 的时间进入反应窗 |
| `CommittedHighThreatEvasion` | 已经提交并具有公开落区/轨迹/预警区的大口径主炮、高等级航空编队或伤害类技能 | 预测舰体包络与攻击有效区相交，预计伤害超过高威胁阈值，且影响时间进入反应窗 |

“高威胁”不能只由敌舰火力评分、被锁定或进入射程推断。必须已经存在合法观察到的攻击实体、固定落区或规则明确公开的预警区，并满足以下白名单之一：

- **大口径主炮**：武器被正式配置标记为主炮且口径/伤害等级达到规则阈值；副炮、普通小口径主炮和持续低伤害弹幕不触发。
- **高等级航空编队**：已提交的攻击编队达到航空威胁等级阈值，并公开合法攻击区域与预计影响时刻；普通侦察、巡逻和低等级编队不触发。
- **伤害类技能**：技能已经提交、具有直接伤害语义和公开影响区/时刻，且预计伤害达到阈值；纯控制、侦察、增益、减益和无伤害技能不触发。

未提交攻击仍由常规战斗机动处理。白名单、伤害阈值和等级来自正式武器/攻击语义，不在扫描阶段重新分析完整技能或角色配置。

### 9.2 每 0.1s 只先做廉价扫描

`NormalNavigation` 下每 `0.1s` 只执行：

1. 从阵营已知攻击空间索引取得反应窗内的少量候选，不重建观察快照。
2. 按鱼雷或正式高威胁语义白名单过滤，不遍历敌舰理论火力、岸线、设施或完整技能配置。
3. 按预计影响时间、距离和稳定攻击 ID 排序，只保留预算允许的候选。
4. 鱼雷使用解析 CPA；固定落区/预警区使用当前常规轨迹包络相交。
5. 计算命中压力、预计影响时间、伤害压力和当前航迹自然脱险能力。
6. 只有综合风险达到进入阈值，且当前常规航迹不能自然避开时，才切换 `EmergencyEvasion`。

未命中进入条件时不生成紧急控制候选。岸线、边界、友军和走廊也不进入该扫描，只在最终紧急候选硬过滤时用于阻止避险轨迹穿陆地或撞舰。

### 9.3 紧急航段长度

必须区分两个时间范围：

- **威胁判断窗**可以覆盖完整反应时间，例如鱼雷 CPA 的 `6-8s`；该部分使用解析外推或低成本包络，只判断是否需要避险。
- **紧急控制航段**只生成很短的实际动力学轨迹，首轮建议预测 `0.8-1.5s`，并且每次只承诺执行前 `0.1-0.3s` 控制。

紧急控制航段不超过“足以比较当前左转、右转、加减速结果”的范围。由于下一次规划只相隔 `0.1s`，生成 `2-4s` 甚至更长的精细紧急轨迹不会提高执行质量，反而会增加积分、碰撞检查和对未来误差的敏感性。

为判断左转还是右转能否最终避开较远鱼雷，可以从 `0.8-1.5s` 详细航段的末状态继续做一次低成本解析外推，延伸到 CPA/攻击影响时刻。延伸段只估计威胁分离趋势，不生成精细采样、不承诺执行，也不能用来证明远期地形合法；实际控制仍在下一个 `0.1s` 重新评估。

紧急候选只保留少量模板：

- 保持当前控制，用作基线。
- 左/右最大有效转向。
- 左/右转向并制动。
- 直线加速穿越或最大制动；仅在威胁几何允许时启用。
- 受控触岸：只在其他候选预计承受更高伤害时启用，轨迹在 Domain 判定的首次岸线接触前终止，绝不穿越陆地。

候选评分只考虑：预期是否命中、最小安全距离、预计伤害、硬地形、近距舰船、控制可执行性，以及触岸/短停/倒车恢复代价。受控触岸具有明显代价，但可以优于预计重创或致命伤害。不得加入战略走廊进度、阵位、设施、武器舷角、岸距偏好或任务收益。

正常紧急候选先使用保持、左转、右转、左转制动和右转制动五项基础集；基础集没有满意结果时才扩展加速穿越、最大制动和受控触岸。威胁集合和环境 revision 未显著变化、旧避险控制仍保持风险下降时允许复用，避免每 `0.1s` 重做完整候选集。

### 9.4 进入条件

满足以下全部条件才从 `NormalNavigation` 进入 `EmergencyEvasion`：

1. 威胁是本阵营合法已知的鱼雷或已提交高威胁攻击。
2. 威胁仍有效且正在接近，预计影响时间位于对应反应窗内。
3. 保持当前控制或继续当前常规航迹会与威胁有效包络相交，或安全距离低于阈值。
4. 预计伤害达到高威胁阈值；致命或可能重创攻击可直接满足。
5. 当前常规航迹不能在不切换状态的情况下自然脱离。

进入时保存战略意图和走廊引用，但立即停止读取其收益。多个威胁同时存在时以最早预计影响时间为主威胁，并在候选硬过滤中同时检查其余威胁。

### 9.5 退出条件

满足以下全部条件并持续一个恢复驻留时间后，才退出 `EmergencyEvasion`：

1. 所有仍有效的已知鱼雷在预测判断窗内均不会与舰体安全包络相交，CPA 大于退出安全距离。
2. 所有已提交高威胁攻击的有效区均不会与当前短期预测包络相交，或攻击已经结算/失效。
3. 综合风险低于退出阈值，且没有预计影响时间更早的新威胁进入。
4. 当前速度与航向至少存在一个硬合法的常规轨迹候选，不会在退出后立即触岸、越界或撞上近距舰船。
5. 上述条件连续保持建议 `0.3-0.5s`，防止在风险阈值附近反复切换。

退出前还需用准备采用的第一条常规航迹检查原主威胁：该航迹在威胁判断窗内不得立即让同一攻击重新达到进入阈值。退出后立即从 Domain 真实状态生成新的 `NormalNavigation` 轨迹。原战略走廊只作为新的目标背景，不要求返回避险前的位置、轨迹或数学航点；若走廊已失效，先使用不依赖新战略结果的局部安全常规控制，再通过 Broker 错峰更新战略走廊。

跟踪集合应立即移除已经结算/失效、CPA 已经过且持续远离、超出反应窗且不可能重新接近，或因观察规则不允许继续精确跟踪的攻击。长时间存在但已不构成命中风险的对象不能阻止退出。

## 10. 轨迹/走廊策略模式

### 10.1 MVP 必须具备

| 模式 | 走廊偏好 | 轨迹偏好 |
|---|---|---|
| `OffshoreTransit` 离岸远航 | 宽阔水域、主航道和较大岸距 | 稳定巡航、少控制切换、提前处理远端瓶颈 |
| `CombatManeuver` 战斗机动 | 允许在射程带内横向移动 | 保持武器舷角、转弯余量和有限威胁成本 |
| `CoastalDefense` 贴岸防御 | 合法岸距带、遮挡和可恢复水域 | 低于远航速度；允许停车/倒车脱离，不把缺少前向出口视为永久死湾 |
| `ObjectiveApproach` 目标接近 | 合法进场区域、靠泊入口或交互水域 | 满足到达航向、速度和停留条件，不要求精准点到达 |
| `FormationTransit` 编组航行 | 共享主走廊、瓶颈预约和阵型降级区 | 成员各自规划，保持包络而非精准阵位 |

这些常规模式共享同一走廊与轨迹规划器，只切换代价、到达条件和控制偏好。`EmergencyEvasion` 是覆盖常规模式的航行状态，不是并列路线策略；`RouteRecovery` 是常规航迹失败处理流程，也不参与策略模式选择。战略模式不得复制一套独立导航算法。

### 10.2 后续可考虑

- `ChannelTransit`：对长海峡和港口瓶颈增加短时预约、错峰和临时纵队。
- `CoverApproach`：偏好具有前向出口的掩体区域，但允许停车并倒车离开封闭近岸水域。
- `ThreatBypass`：绕开已知岸炮、已知雷区或高暴露走廊。
- `EscortScreen`：围绕保护对象的已发布走廊保持弹性屏卫包络。
- `RetreatDisengage`：偏好视线中断、友方支援和宽阔转出空间。
- `SearchSweep`：围绕合法残影或搜索区生成覆盖走廊，不追踪隐藏真值。

优先把这些能力实现为基础模式的代价配置。只有进入、退出、走廊占用或轨迹控制确实不同，才新增独立状态。

## 11. 狭窄水域与编组

普通动态舰船不进入全局导航 revision，主要在短时轨迹层避碰；但狭窄门户需要轻量协调：

- 门户标记有效宽度、推荐方向、是否允许双向会船和入口等待区。
- 编组进入瓶颈前共享一次走廊申请，临时转换为纵队或分批通过。
- 对向冲突按任务优先级、机动能力、是否旗舰和稳定实体 ID 决定让行顺序。
- 等待舰在宽水域提前减速，不在海峡内部互相大角度避让。
- 预约只覆盖短期瓶颈占用，不扩展为全图时空寻路。
- 紧急规避可以打破预约，但解除后必须重新申请，不能假定旧时隙仍有效。

首轮若不实现正式预约，也必须具备瓶颈前减速、临时纵队、稳定让行优先级和超时恢复，避免多舰共享走廊变成拥堵放大器。

## 12. 与 t00 性能方案的统一

- 战略走廊按编组或共享 `RouteIntent` 通常使用 `3.0s`、稳定任务使用 `5.0s` 时间轮评估；只有 dirty 时才把完整搜索交给 `NavigationRequestBroker`。紧急状态只标记收益型更新到期并延后计算，硬 revision 仍立即使旧结果失效。
- 正常轨迹按稳定实体 ID 错峰到约 `1.0s` 时间轮，避免全舰同 Tick 重算。
- 双方时间轮错开半轮，11v11 基础槽位每 Tick 为 `2-3` 艘；碰撞或 revision 失效可立即追加重算，不能为了平滑预算继续执行已知危险控制。
- 每 `0.1s` 高威胁扫描只查询反应窗覆盖的已知攻击空间单元，不遍历岸线、普通舰船、设施或完整走廊。
- 仅处于 `EmergencyEvasion` 的舰船执行 `0.1s` 候选轨迹规划；紧急候选预测仅 `0.8-1.5s`，只承诺前 `0.1-0.3s`。
- 轨迹候选数量、控制段数、积分步数和预测时域均设置硬上限。
- 编组共享走廊；单舰只计算自己的短时轨迹和局部接入。
- 仍安全的旧轨迹可跨规划槽继续使用；预算积压只延迟收益型改善，不延迟致命危险扫描。
- 线程只允许处理不可变候选输入；主线程按战斗 Tick 和请求序号接纳结果，不能由线程完成顺序改变决策。

`t00` 中“每 Tick 即时生存”在本方案中收窄为每 `0.1s` 高威胁攻击扫描。岸线、边界和普通动态避碰由 `1.0s` 常规航迹预防并由 Domain 每 Tick 兜底，不再无条件触发高频规划。只有攻击扫描满足完整进入条件后，才进入紧急轨迹规划。

### 12.1 首轮硬预算

| 项目 | 硬上限/初始值 |
|---|---:|
| 战略评估周期 | `3-5s`，仅 dirty 时搜索 |

| 常规预测/承诺 | `6.0s / 1.0s`，每 `0.1s` 完整验证 |
| 高威胁扫描周期 | `0.1s` |
| 常规候选数 | `<=12` |
| 紧急基础候选数 | `<=5` |

| 常规控制段数 | `<=3` |
| 紧急控制段数 | `<=2` |

## 14. 实施阶段

### 阶段 A：同源运动预测与诊断

- 从当前 Domain 移动中抽出纯计算预测函数，确保规划与权威积分使用同一推进、转向、水流和环境公式。
- 为 Domain 增加简化倒车：前进先制动到近零，再进入受限倒车；补齐倒车转向、水流和碰撞测试。
- 记录当前折线路线、碰撞、转向振荡、无进展、紧急打断和恢复基线。
- 建立战略 `3-5s`、常规 `1.0s`、高威胁扫描/紧急 `0.1s` 的固定 Tick 时间轮和耗时统计，不立即改变行为。

### 阶段 B：走廊兼容层

- 把现有导航节点/平滑路径转换为保守的分区、门户和局部边界。
- 中心线继续用于调试和进度，不再直接作为 AI 必须跟随的命令。
- 验证不同舰体尺寸、吃水和潮汐下走廊不包含非法可活动区域。

### 阶段 C：正常短时轨迹

- 实现固定模板控制序列、同源前向积分、硬过滤和满意度评分。
- 先接入开阔海域 `OffshoreTransit`，验证秒级规划、轨迹复用和无蛇形。
- 再接入弯道减速、逆流补偿、`CombatManeuver` 和 `ObjectiveApproach`。
- 验证岸线、边界、普通避碰和走廊恢复均由常规状态完成，不依赖高频紧急规划。

### 阶段 D：紧急轨迹与恢复

- 接入只读取已知鱼雷、大口径主炮、高等级航空编队和伤害类技能的 `0.1s` 廉价扫描。
- 先接入 `TorpedoEvasion`，再按正式语义白名单接入具有公开落区/时刻的 `CommittedHighThreatEvasion`。
- 实现 `NormalNavigation`、`EmergencyEvasion`、`SafetyHold` 转换，以及全部进入/退出判据和驻留时间。
- 验证紧急状态不读取战略走廊收益，退出后从真实状态重新生成常规轨迹。
- 接入基础/扩展候选、旧紧急控制复用、受控触岸、最低风险 `SafetyHold` 和同威胁退出防振荡。

### 阶段 E：贴岸、编组与 t00 Broker

- 接入 `CoastalDefense`、前向出口软评分、受控停止和倒车恢复，不建立动力学死湾硬判定。
- 编组共享走廊，瓶颈前降级阵型并建立稳定让行；根据测试决定是否需要正式短时预约。
- 所有全局走廊请求迁移到 `t00` Broker、revision 和预算；不合并、不缓存。

### 阶段 F：验收

- 单项变更默认执行 `1 -> 3` 个固定种子。
- 港湾及至少两类不同岸线地图完成 3v3 自动验证和人工航行可读性检查。
- 11v11 有岸压力测试随人工明确指定的 `t00` 大版本性能验收执行。

## 15. 降级与安全网

1. 软代价或特定策略异常时回退基础 `OffshoreTransit`/`CombatManeuver` 参数。
2. 常规候选生成超预算时优先保留继续当前控制、巡航、制动、左转制动和右转制动；紧急状态只保留五项基础候选。
3. 正常规划积压时继续执行仍安全的旧轨迹；旧轨迹接近耗尽则安全减速。
4. 紧急候选都无法完全脱险时选择预计伤害最低/CPA 最大的可执行结果；受控触岸或短停可以优于硬吃重创，不固定选择最大制动。
5. 走廊不可用时保持或驶向已验证的局部安全水域，不回退为穿陆地直达。
6. Domain 的连续积分、舰体扫掠、吃水、潮汐、边界和碰撞始终是最终安全网。

降级不能关闭观察隔离、改变随机源或使用墙钟时间决定候选顺序。

## 16. 测试与验收

### 16.1 运动模型一致性

- 相同初始状态和控制序列下，预测函数与 Domain 实际积分在允许误差内一致。
- 推进、制动、最大转向、水流和环境倍率分别有固定种子测试。
- 若增加最大侧向能力，高速转弯半径不得小于同舰低速结果的规则下限。
- 前进转倒车必须经过近零速度，倒车速度受限；倒车仍受水流、转向、地形和碰撞约束。

### 16.2 走廊与硬通行

- 不同舰体尺度和吃水档的走廊均不包含陆地或非法水域。
- 不可直接接入的语义目标解析为动态可达且有正向进展的阶段目标；无正向进展时返回稳定分类失败，不永久重复同一请求。
- 每条候选轨迹的扫掠包络通过地形、水深、潮汐和边界检查。
- 潮汐改变只失效受影响走廊；区内合法退出契约保持一致。
- 未发现鱼雷、雷区、设施和隐藏敌舰不会改变走廊或候选。

### 16.3 游戏内表现

- 稳定直航不蛇形，不为追踪中心线持续左右修正。
- 大型高速舰在急弯和窄门户前提前减速，不依赖撞岸停车。
- 顺流、逆流和横流下能够保持走廊进展，不要求精准压线。
- `CoastalDefense` 将前向出口质量作为软偏好；进入封闭近岸水域后仍能停车并倒车恢复，不作动力学死湾硬拒绝。
- 封闭近岸水域允许舰船停车并倒车脱离；不因缺少前向出口判为永久不可达。
- 致命威胁下允许选择受控岸线接触或短停，轨迹在首次接触前终止且实际结果优于基线硬吃伤害。
- 编组在宽水域保持弹性包络，在瓶颈前有序降级，不在海峡内互相大角度避让。
- 大编队验收同时检查正向位移、路线失败、结束等待、碰撞/振荡与 Tick 成本；任何单一计数下降都不能替代顺利、高效移动。
- 紧急状态解除后恢复前向走廊进展，不返回旧数学点、不永久停车。
- 普通靠岸、边界和友军会船不会进入 `EmergencyEvasion`；已知致命鱼雷进入反应窗时能够在下一个 `0.1s` 扫描槽切换。
- 紧急状态中改变战略目标、阵位或武器舷角收益不会改变当前避险控制；退出后才重新读取最新战略走廊。
- 所有威胁安全条件连续满足退出驻留时间后能够退出，单一威胁仍不安全时不得提前恢复常规航迹。
- 退出采用的首条常规航迹不会让同一威胁立即重新达到进入阈值；已失效、CPA 已过且远离或不可继续精确观察的攻击会及时移出跟踪集合。
- 普通交通冲突可以提前触发受限的常规重算，但不会切换紧急状态或退化为固定 `0.1s` 常规规划。
- 只有已发现鱼雷、符合阈值的大口径主炮、高等级航空编队和伤害类技能能进入紧急状态；其余类别具有负例测试。

### 16.4 性能与确定性

- 战略走廊通常不高于 `3.0s` 评估一次，稳定任务可放宽至 `5.0s`；只有 dirty 时搜索，紧急状态延后收益型重算，旧走廊仍合法时继续使用。
- 非紧急舰船不高于约 `1.0s` 一次正常轨迹规划，且按稳定槽位错峰。
- 所有舰船可每 `0.1s` 完成只针对已知高威胁攻击的廉价扫描；只有紧急舰船执行同频候选规划。
- 紧急候选预测航段不超过配置硬上限，默认验证范围 `0.8-1.5s`；提交控制不超过 `0.1-0.3s`。
- 常规候选 `<=12`；紧急基础候选 `<=5`、扩展后 `<=7`、控制段 `<=2`、常规/紧急单候选积分样本分别 `<=61/13`、单舰精算攻击 `<=8`。
- 长距离目标只增加走廊门户，不生成覆盖全航程的精细轨迹样本。
- 常规预测后缀只能在真实状态、地形 revision、环境上下文和后续控制逐 Tick 全部一致时复用；当前三张高压图严格可复用率仅约 `2.8%-4.3%`，不得仅因候选标签相同而沿用上一轮控制。固定删减候选序位也不合法，后续裁剪必须由安全或评分上界证明不会移除可能胜出的模板。
- 同固定种子重复运行的走廊摘要、轨迹控制、紧急进入 Tick 和恢复结果一致。
- `t00` 的港湾/普通海域比率、P95/P99 和队列门槛继续适用。

## 17. 完成定义

本方案只有同时满足以下条件才可标记为“已完成”：

1. 规划与 Domain 使用同源的简化运动预测，水流、推进、转向、倒车和环境修正均有测试。
2. AI 实际执行以航行走廊和短时动力学轨迹为主，不再精准追踪导航折线。
3. 战略 `3-5s`、常规 `1.0s`、高威胁扫描/紧急 `0.1s` 进入确定性时间轮并具有独立耗时指标。
4. `NormalNavigation`、`EmergencyEvasion` 和 `SafetyHold` 状态机完成；只有已知鱼雷、符合阈值的大口径主炮、高等级航空编队或伤害类技能可以进入紧急状态。
5. 紧急控制预测和承诺航段受短上限约束，全部进入与退出条件具有独立测试。
6. 所有走廊与轨迹包络通过地形、水深、潮汐、边界和 Domain 回归。
7. 全局走廊请求服从 `t00` Broker、revision 和预算，不合并、不缓存。
8. 港湾及至少两类不同岸线地图通过 3v3 自动验证和人工可读性检查。
9. 无高频全局重规划、长距离精细轨迹膨胀、持续蛇形、非受控撞岸、瓶颈死锁、紧急状态滥用或退出振荡；受控触岸能够通过停车/倒车恢复。
10. `docs/00_project_status.md`、所属 `docs/21-24` 数据契约、实现索引和相关测试按实际实施状态同步更新。
