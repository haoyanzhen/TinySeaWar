# 航母作战战斗画面实施方案

> **功能与边界**：本方案负责航母航空攻击从规则事实到战场画面、HUD 与小地图的接入顺序、缺口治理和验收。规则、字段、架构、美术分别服从 `10/12/18`、`21/22/25`、`32/33/38`、`42/44/45`；本文不成为第二份规则或配置真源。
>
> **方案日期：2026-09-29；状态：A 已接入默认运行时，B 已作为显式 Physical 模式接入；自动与画面检查见第12节，人工、GPU与正式平衡仍待验收。** 第 1 节保留审计时的代码证据；资产最新交付和验证见 [00](../00_project_status.md)。静态资源检查不代表带画面验收。下文设计阶段的拟议接口已按第12节落实；最终字段以所属契约为准。

## 1. 检查结论与证据

用户感受到的缺口成立：现有系统有航空延迟伤害、一些起飞/命中特效与航空伤害数字，但没有把一次航空任务作为可持续观察的作战过程展示出来。问题主要在事实发布、持续视图和规则完整性，不是从零缺所有美术资源。

| 环节 | 本次确认的现状 | 缺口与影响 |
|---|---|---|
| 普通航空攻击 | `BattleSession._fire_weapon/_fire_weapon_at_position` 将 `Aviation` 放入 `delayed_attacks`，按距离、武器速度与天气延迟结算 | 没有对应的持续飞行编队状态投影；玩家只能看到零散首尾反馈 |
| 飞行节点 | `BattleEffectDirector.sync_snapshot` 只同步单位和 `projectiles`；`_spawn_shell_flights` 只接受 `Gun` | `aircraft.*` 配置存在不等于有飞机节点；普通航空没有进入鱼雷实体分支 |
| 起飞/命中 | `WeaponFired` 触发角色开火姿态、挂点 VFX；`AttackResolved` 触发命中特效和按航空类型区分的数字 | 缺编队航行、投弹、任务收尾；未命中落水目前只对大口径炮有专门分支；部分效果还依赖角色 role 存在 |
| 防空 | `_aviation_survival_ratio` 到达时按目标点附近防空估算折损，使用基础航空 HP 及修正；没有沿飞行路线逐轮射击事实 | 无法诚实画出“某门防空炮此时命中这架飞机”；不能用装饰弹幕冒充真实拦截 |
| 侦察 | 技能创建 `Reconnaissance` 区域，保存 HP/剩余时间；`_anti_air_dps_at_position` 按每 Tick DPS 扣血 | 快照有 `skill_effects`，当前战斗协调器未把它接入持续侦察视图；不是已有移动侦察机实体 |
| 航空鱼雷 | `weapon.shokaku_torpedo_bomber` 为 `Aviation`，引用 `projectile.surface_torpedo`；仍走航空延迟区域攻击 | 没有“飞机投雷→入水→鱼雷航行→碰撞”的闭环；不能展示假的可规避鱼雷 |
| 岸基航空 | 机场有任务与效果；`TerrainView` 绘制支援区域，空袭完成播放通用水柱 | 缺任务飞行；战斗机巡逻主要影响航空命中修正，不是逐机空战 |
| HUD/小地图 | 已有航空图标文件；当前小地图主要绘制舰艇、接触、设施、环境和水雷 | 无持续编队标记、己方任务阶段、合法可见的空袭威胁读数 |
| 隐藏信息 | 舰艇/投射物快照有过滤；场景把原始事件及 session 传给导演，导演多处读取 `session.state` | 新航空链必须先建立过滤后的表现事实；不能把敌航母起点、隐藏防空舰或落点全量交给视图 |
| 资产 | 审计时公共飞机为带光晕符号，角色飞机存在视角混杂与残片 | 改为共享五类正俯视机体，独立于角色包；旧专属飞机仅保留历史兼容，新资产与映射交付见 `00` |
| 文档 | 审计发现 `42` 的返航降落要求与 `10/12` 冲突，本轮已同步修订设计 | 从角色位置生成飞机、攻击后脱离淡出；设计修订不代表运行时已接入 |

## 2. 交付范围与推荐取舍

完整交付需回答四个玩家问题：哪艘航母出击了、编队正去哪里、为什么攻击被削弱或未命中、下一次何时可以下令。

分为两个可单独发布的里程碑，但第一步不得宣称完成真实航空交战：

1. **A：航空过程可见。** 保留现有战斗结果，补普通攻击/技能波次的时间线投影、飞行、投弹、落点反馈、侦察区域、HUD、观察过滤。防空只展示当前算法实际产出的到达折损结果，不伪造沿途交战。
2. **B：航空交战闭环。** 建立权威航空任务/编队状态，落实周期防空和真实航空鱼雷，再由同一套视图表达受击、击落和投雷。此步改变计算过程与平衡，独立版本、独立验证，不能混入纯视觉补丁。

共同边界：不新增航母操作小玩法，不增加返航/机库/补充飞机经济，不要求逐机控制，不把所有航母武器替换成统一模板；航母原有手动主要武器、自动辅助开关与手动技能保持其操作契约。音效另走正式音频设计与总线方案，本次画面完成不代表音频完成。

新航空链统一使用公共飞机，不再要求或优先加载角色专属机体。机型按实际武器/技能任务选择，不按航母身份换机体；角色差异通过本体、技能提示和合法可见的编队演出表达。旧专属飞机、起飞/回收标记及包含飞机的角色 VFX 保留历史兼容，不进入新链的机体依赖，也不因停用而要求重做角色包。

设计审计轮的范围曾限于文档与公共机体资产；当前运行时实施进展见第12节。B 的规则正确性、观察隔离和事件唯一性仍是实现验收要求；胜率、伤害预算及舰种强弱的平衡实验放到功能接入之后，不阻塞当前资产接入，也不在本轮执行或标记通过。

## 3. 玩家实际看到的一次出击

| 阶段 | 世界画面 | 玩家信息 | 权威约束 |
|---|---|---|---|
| 瞄准 | 在合法目标区显示空袭轮廓、进入方向提示；合法/非法同时用形状与颜色区分 | 原有武器控件显示就绪、装填或具体拒绝原因 | 范围来自公共命令预检；不能扩大成视觉自定义伤害区 |
| 出击 | 在该波出发时的角色位置直接生成 2–4 个飞机图形，从小到大渐变，可配合短淡入；不使用甲板起飞点或甲板拖迹 | 己方短提示“航空编队出击”；技能标实际波次 | 接受命令且到达实际出发时刻后才生成；缩放不增加准备时间，展示数量不是新增弹药数 |
| 飞行 | 可辨飞机轮廓、短尾迹、轻量阴影；选中航母时显示己方任务引导 | 己方显示任务阶段与剩余到达时间；敌方只显示依法观察的信息 | 位置、落点与时间从投影读取，不从表现配置重算速度 |
| 进入攻击 | 轰炸机抬升/俯冲，炸弹与飞机分离；落区轮廓逐渐收束 | 敌方预警仅在具备相应观察权限时显示；精确目标未知时只提示来袭方向 | 短距离压缩起飞与俯冲装饰，不能拖延结算 |
| 防空 | A 只显示到达时确认的拦截结果；B 根据实际射击事件播放克制曳光、空爆、机体受击 | 受损显示效能下降；真正全灭才显示“编队被击落” | 无伤害事件不制造命中，不以贴图数量计算损失 |
| 命中/落空 | 同一结算时点生成甲板爆炸或固定落点水花；与伤害数字同步 | 可用简短“未命中”或“拦截”说明；不把所有零伤害都称为击落 | `AttackResolved`/任务终态为唯一依据；不跟随已经移开的原目标 |
| 结束 | 幸存图形继续飞越很短距离并淡出，坠毁另有短火花与缩小 | 本次任务从己方列表移除；装填仍读取武器状态 | 脱离为纯视觉收尾，不回收飞机、不阻止下一次出击 |

显示比例首轮建议：1080p 常用缩放下单机有效轮廓约 24–28 屏幕像素，不能将含透明边距的画布宽度当作主体尺寸；18 像素附近细节与机型区分不足时降为编队符号。以实际海域与角色尺寸校准后写入 `25/data/visuals`。阴影从同一机体 Alpha 生成暗色副本，以小偏移表达高度，不烘焙进机体；飞机旋转独立于母舰，不能随母舰转向而整条航线旋转。UI、旗舰标记、鱼雷威胁和必要航空预警优先于尾烟。

## 4. 各类航空任务的表现与真实能力边界

| 类型 | 应实施画面 | 实施前提/限制 |
|---|---|---|
| 常规轰炸 | 共享轰炸机、编队、俯冲/飞越、独立炸弹、甲板/海面反馈 | A 即可完成；AP/HE 只按实际武器元数据区分爆烟/穿透，不能从角色名字猜测 |
| 多波次技能 | 先显示准备，按每波 `launch_at_time` 出击，分别抵达与结算 | 不能只监听 `SkillCast` 后一次性放出全部编队；源舰沉没后未出发波次取消逻辑沿用现有权威行为 |
| 侦察 | 区域中心盘旋的侦察符号/飞机、选中时显示范围和剩余时间、受击与失效 | A 读取已生效的 `skill_effects`，盘旋只是装饰，不改变区域中心；不添加假的航程等待时间 |
| 战斗机巡逻 | 当前巡逻区域、巡逻飞机、有效期；阻滞效果只在有事实时提示 | 现有机场是区域修正，A 不画逐机击杀；真正追击/空战是独立规则扩展，不因存在 fighter 图就自动启用 |
| 航空鱼雷 | B 的鱼雷机低空接近、投雷入水、公共鱼雷视图与发现规则 | A 保持真实的抽象航空打击反馈，不画会误导规避的假鱼雷；B 必须由 Domain 创建鱼雷 |
| 航空反潜 | 飞越、投放、延迟水下爆炸与气泡 | 只接实际配置为航空反潜的攻击来源；有 asw 图不等于每艘航母获得反潜武器 |
| 岸基航空 | 机场任务准备、出击、区域生效、结束，同一公共飞机视图 | 保留设施任务来源与冷却/次数；不伪造航母来源，不重复生成侦察视野或伤害 |

首轮角色覆盖固定为数据中实际七名航母：企业、百眼巨人、胜利、凤翔、光辉、齐柏林伯爵、翔鹤。企业先作纵切；随后一期四舰、二期三舰全映射。伊-19 的侦察能力作为跨舰种复用样例，不扩大为新增航母。纯 `_visual` 武器配置不能当作角色实际装备清单。

## 5. 数据流与系统分工

```text
公共命令/技能/设施任务
        ↓
权威攻击与任务时间线 ──→ 原有伤害/侦查/统计（A 保持结果）
        ↓
Application 阵营观察投影与事件过滤
        ↓
航空快照 + 一次性可见事件
        ↓
BattleEffectDirector
        ├─ AircraftSquadronView：编队、阴影、受击、退出
        ├─ AviationPayloadView：炸弹；真实鱼雷转交 ProjectileView
        ├─ 航空预警叠层：当前可知范围与方向
        └─ HUD / 小地图 / 合并战况
```

### 5.1 A 阶段的事实桥接

拟新增 Application `aviation_presentation_projection.gd`，从普通攻击、技能波次和设施任务的权威排程生成只读投影；不依靠表现层扫描 `delayed_attacks`，不创建第二个伤害队列。

- 为一次任务建立稳定 `mission_id`，每波建立 `wave_id`，关联原有 `attack_id[]`；同一波可汇总为一个编队视图，但逐次攻击结果不丢失。A 的任务/波次 ID 使用独立序列或从既有攻击关联派生，不调用公共 `_next_entity_id`，不消耗规则随机源。新增事件允许使用事件序号，但不得改变原有事实的相对顺序。
- 权威排程发布出发时间、规则原点、已固定目标/落点、预计结算时间。当前普通 `WeaponFired` 没有完整逐次 attack ID 与到达时间，需要在排程生成处补足关联。
- A 区分规则原点与表现生成位置：现有技能在施法时固定后续波次的规则原点和到达时间，这些保持不变；Application 在每波真正出发时采样角色当前位置一次，保存为表现生成位置。飞机从该位置向既定落点按原出发/结算时刻映射飞行，不据新距离重算伤害、天气修正或到达时间，生成后不再跟随角色移动。极短剩余时间压缩或跳过生成装饰。迟到事件和视图重建读取该次采样，不重新读取角色位置；源舰沉没的未出发波次沿用取消规则。B 的规则位置由航空服务拥有，出发时从角色位置初始化。已立即生效的侦察仍在区域中心显示，机场沿用设施任务来源，不虚构角色起点。
- 生命周期至少包含排程、出发、抵达、结果、取消/过期。技能尚未出发与已经出发必须区分，不能根据一次 `SkillCast` 猜测。
- 视图重建从当前可见快照恢复，而不是必须从开局收到每个事件。迟到事件按当前战斗时钟跳到合适阶段。
- A 的防空折损记录沿用现有算法并增加可审计结果，不新增随机抽样，不补造沿途 HP 历史。若零伤害无法证明是拦截导致，只报告实际原因。

### 5.3 时钟与生命周期

- 时间使用会话时钟；暂停冻结飞行、投放和装饰收尾，暂停计划只有恢复后被权威接受才产生飞机。
- 表现插值不越过最新权威时间；A 的路径由确定的出发/到达时刻映射，B 只插值规则位置，不能另算巡航路径。
- `event_id` 去重，按 Tick/序号稳定消费；重新绑定对象池清除旧阵营、目标、Tween、HP、事件缓存。
- 命中在固定结算时点反馈，炸弹不能在伤害出现后还缓慢飞行。低帧率跳过非关键中间动作，保留唯一结果。
- 同源多波次、同 Tick 多次命中、源舰沉没、目标沉没/移出落区、编队失去可见性、视图重建、重开/退出都有独立测试。
- 未被看见不等于被击落；隐藏直接清除当前可见段与敏感缓存，不能播放坠毁或继续飞往秘密目标。

### 5.4 现有事件接管与唯一消费

新事件是既有事实的表现适配，不是第二套结算。P0 必须沿排程、原始事件、导演、HUD、战况逐一校对下表并记录接管入口；航空表现不得继续从 `session.state` 补取隐藏来源、目标或位置。原始事实保留给规则、统计和授权诊断，局内表现统一消费 Application 过滤后的输入。

| 现有事实 | 新链负责 | 旧表现分支处理 |
|---|---|---|
| `WeaponFired` | 普通航空任务关联、出发视图；可见来源的开火姿态 | 航空分支移交新链，不再独立播放旧起飞/挂点 VFX；非航空保持原职责 |
| `SkillCast` / `SkillAttackScheduled` | 前者只驱动获准的技能提示/姿态，后者关联逐波排程，到实际出发时再生成飞机 | 取消以一次施法生成全部飞机的路径，保留非重复的通用技能反馈 |
| `AttackResolved` | 每个攻击结果驱动唯一命中/落空效果，并调用共享伤害数字入口一次 | 对已接管航空攻击跳过旧命中特效和数字入口；`AviationWaveResolved` 只汇总阶段，不再重放逐次命中或生成伤害 |
| 侦察部署/摧毁/到期事实 | 统一适配持续侦察视图和终态 | 旧入口不重复生成、销毁或播放终态 |
| 设施任务阶段 / `SupportMissionResolved` | 适配岸基飞行、区域与完成反馈，按任务及攻击关联区分阶段和命中 | 原通用水柱与新命中效果只能有一个消费者；区域绘制保留唯一所有者，不新增视野或伤害 |
| B 的防空/载荷事实 | 受损、坠毁、投放；入水鱼雷交公共投射物链 | 鱼雷命中只由公共链反馈，航空任务收尾不再产生一次命中 |

过滤发生在发布给世界/HUD/小地图/战况之前；匿名事实不得携带可反查秘密身份的武器、角色或内部来源字段。`event_id` 处理重送去重，另用战斗/攻击 ID 与反馈类别关联同一事实的新旧适配；逐波汇总不得吞掉同 Tick 不同 `attack_id` 的合法结果。重建只恢复持续状态，不重放历史命中。切换旧/新航空表现消费者在会话初始化时固定；关闭新视图不允许恢复未过滤的原始航空事件。

## 6. B 阶段：让防空与投雷拥有可显示的真实事实

这是现有航空规则的运行时补齐及部分具体语义定稿，需单独改 `21/32`、规则测试和实验基线。不能只在 Presentation 实现。

1. **权威任务服务**：拟新增 `AviationService`，拥有任务与编队 HP、位置、阶段、载荷和攻击关联；由 BattleSession 在固定 Tick 推进。MVP 使用一个逻辑编队、2–4 架装饰图形，不引入逐架独立寻路或复杂空战。HP 对应哪个攻击包/波次必须明确配置，不能把同一 HP 预算无意复制到每枚炸弹。
2. **固定 Tick 顺序建议**：推进航空位置→刷新航空可见性→周期防空选择与伤害→终态处理→幸存编队投放/抵达→公共载荷伤害。到达同 Tick 可否被防空拦下在 `32` 固定，建议防空先于投放；已有空中载荷不受投放后的飞机死亡影响。
3. **真实防空装填**：遵循 `10/12`：每轮伤害分别作用于该防空圈内所有合法敌方编队，不选择单个目标、不按编队数分摊。使用武器状态、有效射程、实际装填和炮座射击次数；在该轮结算时确定合法集合，稳定实体序仅决定遍历和事件顺序。每轮只消耗一次装填，每个编队只承受该轮一次完整伤害，2–4 架装饰图形不增加受击次数；多个防空武器按各自装填独立结算。移除新航空路径上的到达估算及侦察 DPS 扣血，不能新旧算法重复扣血。两用炮冷却组与现有未关闭专项衔接，不宣称这一步已解决所有共享炮塔问题。
4. **折损与伤害**：实际剩余 HP 比例在投放时冻结到载荷；没有载荷的被击落编队终止攻击。`AviationDamageFloor` 等既有技能语义必须明确是存活编队伤害下限还是能阻止全灭，先对齐所属规则与技能再实现，不能让已全灭的编队无说明地产生炸弹。
5. **航空鱼雷**：由权威投放点创建公共鱼雷实体，记录来源任务与武器，入水后遵守公共发现、碰撞、地形、航程和统计；删除对应旧延迟伤害。投放点必须可入水，方向来自固定进攻意图，不追踪未发现潜艇，不为命中偷偷移动到目标旁。
6. **航空雷的契约先决项**：当前翔鹤武器允许 `Surface/Submerged`，但能否表现为低空普通投雷、是否沿用潜艇合法性、飞机航程与水中航程怎样拆分、鱼雷伤害公式与折损如何组合，都须在 `10/12/14/21` 明确。推荐先沿用现有目标类型与公共鱼雷合法性，不擅自改对潜能力；不具备明确投放参数时禁止把配置标为实体投雷完成。
7. **侦察与机场**：侦察视野半径和有效期继续由权威任务拥有；如把原本立即生效的侦察改为抵达生效，须视作规则改动单列验收。巡逻的区域修正可以继续保留，不强制升级为追击空战；不能同时获得区域修正和未定义的击杀收益。
8. **全系统一致性**：玩家、AI、Headless 模拟共用航空服务；B 的航空观察加入 AI 合法观察输入，不将飞机塞入舰船导航。性能加速只能筛掉不可能交战的配对，不减少合法防空射击或遗漏圈内编队。

旧航空折损使用 DPS × `0.12` 的一次估算，旧侦察扣血使用 DPS × `0.25` 持续结算；两者是旧实现口径，不作为真实周期射击的隐藏补偿系数继续叠加。B 先保证公式、装填、HP 和事件正确，记录迁移后的差异，平衡性随后专项测试；不得为追平旧胜率而暗中修改这次已确定的全圈结算规则。

## 7. 隐藏信息与预警政策

航空侦测目前缺专门完整契约，这是敌机持续显示的前置依赖。

- 己方任务显示自己的编队、计划落点与到达时间；己方打向隐藏海域的攻击不获得隐藏目标的身份、当前位置、伤害与沉没信息。
- 敌方飞机只显示已获观察的当前片段，来源舰未发现时不显示舰名、角色专属标识或角色位置处的生成过程，也不反推出发点。
- 建议敌机通过独立航空观察查询，在己方合法观察区域内共享发现；具体距离、遮挡与天气在 `10/12/21` 定义，不能直接套用鱼雷发现距离。确定契约前，A 可先交付己方飞行及既有合法受击反馈，不能打开全图敌机。
- 看到飞机不自动等于知道精确攻击落点。精确落区/剩余时间仅在规则明确公开攻击意图时发布，否则只显示机型、航向和来袭提示。预警开放本身可能影响玩法，不能由美术随意提前。
- 隐藏防空舰只能产生规则允许的匿名可感知空爆，不能绘制连回秘密舰位的曳光。若该事实本身也不可感知则完全过滤。
- 观战全知是独立调试入口；世界节点、日志、伤害数字、任务列表和小地图都必须测试泄露，不能仅检查 sprite.visible。

## 8. HUD、美术资源与性能

**HUD：** 沿用现有上下右分区。底部选中航母摘要增设紧凑的“本次任务：飞行/攻击/已结束”与剩余时间；武器装填与在途任务分开显示，允许多个任务并存，不能以“有飞机在天上”禁用已装填武器。右侧战况只合并重要出击、有效拦截与任务失败；无新弹窗、不抢镜头。小地图每个可见编队一个带方向符号，按敌我形状区分；点击/交互若新增需同步 `11`，首轮只展示。

**资产接入：** “具体武器/技能→任务类型→公共飞机/独立载荷→公共 VFX→生成位置→HUD”是唯一机体选择链。统一五类为短翼战斗机、宽翼轰炸机、长机身鱼雷机、细长翼侦察机及双发动机反潜机；全部正俯视、机头向右、透明背景、收起起落架、无永久光晕/阴影/尾迹。资产规格归 `42`、字段归 `25`、语义归 `45`。已有炸弹、鱼雷、防空与水花先复用，正式观感仍需实机验收；有战斗机或反潜机资产不等于新增相应能力。出击仍采用角色位置生成和缩放渐变。

新消费者先用 `weapon_visual(character_id, weapon_id)` 查询具体武器映射，缺省才查询武器组；翔鹤轰炸与投雷共用组名，不能只凭组名或 `secondary_projectile_visual_id` 猜测本次载荷。公共资源查询沿用 `visual.projectile.aircraft.*`，不根据角色目录拼机体路径。敌我共享机体，颜色与形状标记由观察过滤后的叠层表达；HUD 图标不烘焙到机体，方向和任务类型不能只靠颜色区分。

**降级：** 对应公共机型→可辨方向与任务类别的程序符号，不回退到旧专属飞机。角色局部姿态/技能 VFX 可继续使用专属资产，但机体、载荷、通用受击和坠毁不得依赖角色 role 存在；旧 `_spawn_role_vfx` 的空 role 提前返回不得吞掉这些反馈。单机、VFX 都应有最大生命期；到期回收是故障兜底，正常结束仍来自快照/事件。回收/降落资产保留但不自动启用。

**性能建议目标（待实测）：** 固定同一录像/命令、种子、窗口与镜头，分别测关闭/开启航空表现的增量；1080p、11v11、32 个并发可见编队（最多 128 个装饰飞机）的压力样例，航空表现 CPU 增量 mean ≤1 ms、P95 ≤2 ms，记录 GPU/整帧 P95/P99、活动节点和内存。此为提议预算，不能用当前导航未达标解释新增无上限开销。32 是测试负载而非规则上限；更多编队合并装饰或改符号，不能删除真实任务。

纹理预载、语义查询缓存、持续实体映射和对象池先行；不要复制 `TerrainView.sync_dynamic` 每次全删全建的做法。远景优先减少阴影/尾迹/装饰架数，所有合法威胁与命中仍保留。B 的领域成本单独量测，不能隐藏在渲染总耗时中。
