# Tinny Sea War 技术设计文档

## 1. 项目定位

Tinny Sea War 是一款基于 Godot 的 2D 二次元拟人化海战游戏。玩家通过指派不同舰种、不同等级的舰娘组成舰队，在海面战场中进行半即时战斗。第一版目标不是完整养成游戏，而是做出可验证手感、规则和数值框架的战斗切片。

核心方向：

- 2D 俯视或斜俯视海战表现。
- 舰船以二次元舰娘作为主要角色表达。
- 主炮、鱼雷、舰载机、防空、潜艇等海战元素用二次元化特效表现。
- 战斗规则吸收海战中的射程、侦查、闪避、装甲、制空、火力压制等概念，但第一版做轻量抽象。
- MVP 阶段不做抽卡、养成、剧情、装备、基地和长线经济系统。

## 2. 技术路线

### 2.1 引擎

第一版使用 Godot 4.x。

选择理由：

- 2D 能力成熟，适合单位、弹幕、技能、UI 和地图交互。
- macOS 可作为主开发环境，并可导出 Windows 11 可运行版本。
- 节点和场景系统适合拆分舰娘、投射物、技能、战场、关卡等模块。
- GDScript 开发效率高，适合快速迭代 MVP。
- 项目体量轻，适合独立开发和早期玩法验证。

### 2.2 目标平台

MVP 阶段目标平台：

- 开发平台：macOS。
- 运行平台：Windows 11, macOS。
- 可选调试平台：macOS 本机运行。

发布前必须在真实或干净的 Windows 11 / macOS 环境中验证：

- 游戏能启动。
- 分辨率和全屏/窗口模式正常。
- 鼠标操作正常。
- 中文字体显示正常。
- 存档或配置文件路径正常。
- Godot 导出包不缺依赖。

### 2.3 推荐项目结构

后续 Godot 项目可按以下结构组织：

```text
assets/
  art/
  audio/
  fonts/
  vfx/
docs/
scenes/
  battle/
  units/
  ui/
  projectiles/
scripts/
  battle/
  data/
  units/
  skills/
  ui/
data/
  levels/
  ships/
  skills/
```

其中：

- `scenes/` 存放 Godot 场景。
- `scripts/` 存放 GDScript 逻辑。
- `data/` 存放关卡、舰娘、技能等配置数据。
- `docs/` 存放设计文档和技术文档。

## 3. MVP 范围

### 3.1 第一版只做战斗切片

MVP 不包含：

- 舰娘养成。
- 抽卡。
- 装备强化。
- 剧情章节。
- 基地经营。
- 皮肤系统。
- 多结局。
- 联机。

MVP 包含：

- 关卡选择或简单关卡列表。
- 开阔海域同等级海战。
- 1v1 教学关。
- 3v3 标准关。
- 最多 11v11 的大规模验证关。
- 舰娘资源消耗和关卡资源上限。
- 六大初始舰种。
- 1 到 3 级舰娘强度框架。
- 旗舰被击沉作为胜负条件。
- 每名舰娘一个可双击触发的特殊技能。

### 3.2 第一版战斗模式

项目预期后续支持多种战斗模式：

- 开阔海域同等级海战。
- 带陆地和岛屿的海战。
- 压制非对称海战。
- 突围模式。
- 占点模式。
- Roguelike 连续关卡模式。

MVP 只实现：

- 开阔海域同等级海战。
- 按关卡逐步增加难度。
- 不加入岛屿、陆地、防御设施、占点区域、连续奖励和随机事件。

## 4. 战斗规模与编队规则

### 4.1 战斗规模

关卡规模从小到大推进：

- 教学关：1v1。
- 早期标准关：3v3。
- 中期扩展关：5v5 到 7v7。
- 压力测试关：最多 11v11。

11v11 是第一版的上限，用于验证性能、寻路、索敌、技能释放、UI 信息密度和战场可读性。

### 4.2 资源上限

每一关拥有固定资源上限。玩家在进入战斗前使用资源指派舰娘。

规则：

- 每名舰娘有资源消耗。
- 舰娘越强，资源消耗越高。
- 玩家选择的舰娘总资源消耗不能超过当前关卡资源上限。
- 资源上限用于限制高等级舰娘堆叠，迫使玩家做舰种搭配。

示例：

```text
关卡 A：资源上限 6
可选择：
- 1 级驱逐，消耗 1
- 1 级轻巡，消耗 2
- 2 级重巡，消耗 4

玩家可以选择 3 名低级舰娘，也可以选择 1 名较强舰娘加少量辅助舰娘。
```

### 4.3 旗舰

每一方必须有一名旗舰。

规则：

- 我方旗舰被击沉则失败。
- 敌方旗舰被击沉则胜利。
- 非旗舰舰娘被击沉不会立刻结束战斗。
- MVP 阶段先不做撤退、俘获、士气崩溃等附加规则。

## 5. 舰娘强度设计

舰娘强度由两个关键维度构成：

- 种类：决定主要输出方式、装甲特征、定位和战场职责。
- 等级：决定同类舰娘中的基础强度。

### 5.1 种类

MVP 初期包含六大舰种：

- 驱逐。
- 轻巡。
- 重巡。
- 战列。
- 航母。
- 潜艇。

### 5.2 等级

舰娘等级分为 1 到 3 级。

等级含义：

- 1 级：初始级。
- 2 级：护航级。
- 3 级：主力级。

等级影响：

- 最大生命值。
- 伤害。
- 航速。
- 装填速度。
- 侦查能力。
- 闪避能力。
- 技能强度。
- 资源消耗。

### 5.3 等级定位

1 级舰娘：

- 血量低。
- 伤害低。
- 航速慢。
- 技能简单。
- 资源消耗低。
- 适合作为教学、低难度关卡和数量填充单位。

2 级舰娘：

- 数值中等。
- 战斗能力稳定。
- 开始出现少量特种舰船。
- 资源消耗中等。
- 适合作为标准战斗主力。

3 级舰娘：

- 具备碾压性的能力。
- 存在许多特种舰船。
- 资源消耗高。
- 适合作为旗舰、核心输出或关键战术单位。

## 6. 舰种职责与攻击手段

### 6.1 驱逐

主要职责：

- 侦查。
- 鱼雷攻击。
- 近端火炮输出。
- 骚扰和牵制。

特征：

- 高闪避。
- 低可侦查性。
- 火炮伤害较低。
- 鱼雷爆发较高。
- 装甲薄。

实现重点：

- 侦查范围和被侦查距离需要和其他舰种明显区分。
- 鱼雷需要有轨迹和预警，让玩家能理解威胁来源。

### 6.2 轻巡

主要职责：

- 防空。
- 压制驱逐。
- 中近距离火力支援。

特征：

- 对驱逐命中和压制能力较强。
- 防空能力较好。
- 火力和装甲介于驱逐与重巡之间。

实现重点：

- MVP 可先将防空抽象为对敌方飞机造成持续伤害或降低空袭命中率。
- 轻巡应成为反驱逐和反飞机的可靠选择。

### 6.3 重巡

主要职责：

- 火力支援。
- 中距离持续输出。
- 承担部分正面压力。

特征：

- 火炮强于轻巡。
- 装甲强于轻巡。
- 机动性弱于驱逐和轻巡。

实现重点：

- 重巡应当是稳定输出单位。
- 不应在 MVP 中抢走战列的远程压制定位。

### 6.4 战列

主要职责：

- 战场火力压制。
- 远程主炮输出。
- 致命打击。

特征：

- 血量高。
- 装甲厚。
- 主炮伤害高。
- 装填慢。
- 航速慢。
- 资源消耗高。

实现重点：

- 主炮需要有明显前摇、弹道或落点提示。
- 命中后反馈要强，形成“致命打击”的表现。

### 6.5 航母

主要职责：

- 制空。
- 侦查。
- 空袭。

特征：

- 本体近战能力弱。
- 可远距离投放舰载机。
- 能扩大视野或发现低可侦查单位。
- 依赖飞机进行输出。

实现重点：

- MVP 可将飞机简化为自动飞向目标的编队单位。
- 空袭可以拆为轰炸和航空鱼雷，第一版可先实现一种。
- 制空可先抽象为影响敌我空袭效率。

### 6.6 潜艇

主要职责：

- 阻止敌方突进。
- 绕后斩首。
- 威胁敌方旗舰或后排单位。

特征：

- 低可侦查性。
- 可使用鱼雷。
- 生存依赖隐蔽而非装甲。
- 对反潜单位敏感。

实现重点：

- MVP 可先用“潜航状态”和“被侦查状态”表示。
- 潜艇不应过早加入复杂深度、氧气、声呐系统。
- 若第一版工期紧，潜艇可作为后续舰种保留，但数据结构需要提前兼容。

## 7. 战斗系统设计

### 7.1 战斗节奏

MVP 推荐采用半即时战斗：

- 舰娘按 AI 自动移动、索敌和普通攻击。
- 玩家通过双击舰娘或对应 UI 触发特殊技能。
- 战斗持续时间目标为 2 到 5 分钟。
- 关卡难度通过敌方数量、等级、资源上限、旗舰类型和 AI 参数提升。

### 7.2 移动

第一版可采用简单移动模型：

- 每个舰娘拥有航速。
- 单位在 2D 平面上移动。
- 开阔海域没有地形阻挡。
- MVP 不做复杂碰撞避让，只做基础单位分离和边界限制。

后续在加入岛屿与陆地模式时，再引入导航区域、避障和视线遮挡。

### 7.3 侦查

侦查是海战差异化的重要系统，但 MVP 需要轻量实现。

基础规则：

- 每个舰娘拥有侦查范围。
- 每个舰娘拥有可侦查性。
- 敌方是否被发现由侦查范围和可侦查性共同决定。
- 未被发现的敌人不可被普通攻击锁定。

可简化公式：

```text
发现距离 = 侦查方侦查范围 - 目标隐蔽修正
```

### 7.4 攻击

MVP 攻击类型：

- 主炮。
- 鱼雷。
- 空袭。

后续攻击类型：

- 防空。
- 反潜。
- 副炮。
- 技能弹幕。
- 状态伤害。

### 7.5 技能

每个舰娘拥有一个特殊技能。

触发方式：

- 玩家双击舰娘触发。
- 或双击战斗 UI 中的舰娘头像触发。

MVP 规则：

- 每个舰娘只拥有一个技能。
- 技能有冷却时间。
- 技能可有释放条件，例如目标存在、能量充足、未被沉没。
- 技能释放需要有明确视觉反馈。

技能类型示例：

- 强化下一轮主炮。
- 发射扇形鱼雷。
- 召唤空袭。
- 短时间提升闪避。
- 短时间提升防空。
- 对敌方旗舰进行锁定打击。

## 9. AI 设计

MVP AI 目标是“能打起来且行为可理解”，不追求复杂战术。

基础行为：

- 搜索最近或威胁最高的已发现敌人。
- 进入武器射程后攻击。
- 驱逐优先尝试靠近后发射鱼雷。
- 战列保持较远距离输出。
- 航母保持后方并释放飞机。
- 潜艇优先绕向旗舰或后排。

旗舰目标：

- 默认保护己方旗舰。
- 敌方可根据关卡设计优先攻击我方旗舰。

## 10. UI 设计

MVP 战斗 UI 需要支持：

- 我方舰娘列表。
- 旗舰标记。
- 血量显示。
- 技能冷却显示。
- 当前关卡资源上限和已用资源。
- 胜利/失败结算。
- 暂停和重开。

双击技能触发需要明确：

- 双击舰娘本体。
- 或双击舰娘头像。
- 技能可用时给出高亮。
- 技能冷却中给出剩余时间。

## 11. 后续扩展预留

虽然 MVP 只做开阔海域同等级海战，但技术结构需要预留：

- 地形与岛屿遮挡。
- 占点区域。
- 突围目标点。
- 非对称资源配置。
- 连续关卡奖励。
- 随机事件。
- 更多技能。
- 更多舰娘个体差异。
- 简单养成系统。
- Live2D 或 Spine 角色表现。

## 12. MVP 验收标准

第一版战斗切片达到以下标准可认为完成：

- 可在 macOS 编辑器中运行。
- 可导出并在 Windows 11 上运行。
- 至少有 3 个关卡：1v1、3v3、压力测试关。
- 玩家可在资源上限内选择舰娘。
- 至少实现驱逐、轻巡、重巡、战列、航母中的 3 类。
- 如果潜艇未实现，数据结构和枚举需要预留。
- 每名舰娘有生命值、移动、侦查、普通攻击和一个技能。
- 双击舰娘或头像可以触发技能。
- 我方旗舰沉没后失败。
- 敌方旗舰沉没后胜利。
- 主炮、鱼雷、空袭至少实现其中两种。
- 战斗结果可稳定结算。

## 13. 当前决策

已确定：

- 使用 Godot 4.x。
- 第一版不做养成，只做战斗切片。
- 第一版只做开阔海域同等级海战。
- 战斗规模从 1v1 到最多 11v11。
- 通过关卡资源上限限制舰娘选择。
- 舰娘强度由种类和等级共同决定。
- 初始规划六大舰种：驱逐、轻巡、重巡、战列、航母、潜艇。
- 舰娘等级为 1 到 3 级。
- 胜负条件为旗舰沉没。
- 每个舰娘拥有一个可由玩家双击触发的特殊技能。
