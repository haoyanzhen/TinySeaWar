# 潜艇战斗 AI 与潜航运行时闭环工单

> 建立日期：2026-08-10
>
> 状态：待正式验证（基础规则、六阶段 AI 运行时、长期聚合诊断报告与 S-04/S-05 `1 -> 3` 固定种子门禁已完成；各 20 种子正式复验待独立授权）
>
> 优先级：P0 运行时正确性 / P1 潜艇战术质量与动态平衡
>
> **功能与边界**：本工单解决潜艇已经取得可见目标和合法鱼雷窗口，却长期不提交主要武器攻击，以及氧气耗尽上浮后无法重新下潜的问题。实施必须复用公共侦查、武器合法性、逐座装填、鱼雷投射物、导航和伤害规则，不得为潜艇建立绕过 Domain 的特殊命中或伤害通道。本工单不授权通过修改战列舰主炮、驱逐舰/潜艇鱼雷伤害或挑战关舰队配置掩盖零开火；运行时缺陷关闭前，S-04/S-05 的胜率只作探索证据，不作平衡调参依据。

## 1. 问题结论

2026-08-09 的当前 10 种子挑战探索报告中：

| 关卡 | 潜艇 | 样本 | 开火 | 命中 | 有效伤害 |
|---|---|---:|---:|---:|---:|
| S-04 | 海狮号 | 10 | 0 | 0 | 0 |
| S-05 | U-47 | 10 | 0 | 0 | 0 |

这不是武器配置缺失，也不是鱼雷伤害偏低导致的“统计上接近零”。两艘潜艇实际没有发射主要武器，因此任何伤害数值调整都不能修复该问题。

当前结论适用于潜艇公共运行时链路，并已由两名配置不同、分属双方阵营的 1 级潜艇复现。第二期潜艇尚未进入正式关卡，本工单不得只对海狮或 U-47 写角色 ID 特判。

## 2. 当前证据

### 2.1 固定种子诊断

一次性诊断使用当前双方 `LatestRuntimeAI`、正式关卡数据和 `0.1s` 权威 Tick；诊断脚本未作为运行时或长期测试入口保留。

| 指标 | S-04 海狮，种子 8401 | S-05 U-47，种子 8501 |
|---|---:|---:|
| 存活/观察时长 | 149.9s | 141.7s |
| 有可见目标 Tick | 454 | 460 |
| 主武器合法 Tick | 227 | 204 |
| 达到当前纪律阈值 Tick | 0 | 1 |
| `AIFireCommitted` | 0 | 0 |
| `WeaponFired` | 0 | 0 |
| `FIRE_ARC_INVALID` / `OK` | 227 / 227 | 256 / 204 |
| 主要模式驻留 | `ReconAvoid` 140.3s；`TorpedoFlank` 9.6s | `ReconAvoid` 125.6s；`TorpedoFlank` 16.1s |
| 合法窗口最高分 | 72.54 | 68.19 |
| 最近目标距离 | 204.24 | 179.10 |

海狮全部合法窗口处于 `Silent`。U-47 有 65 个合法 Tick 处于 `HoldUntilWindow`，但只有一个普通 Tick 刚超过 `68`，没有与当前每 `0.5s` 一次的主要武器决策点重合。

### 2.2 已确认正常的公共链路

- 海狮和 U-47 均配置前、后鱼雷，主武器组引用有效，射程、首尾射界、管数、装填和投射物定义完整。
- `_validate_primary_fire()` 能在目标进入首/尾扇区时返回合法武器状态；诊断中两艇已有数百个合法 Tick。
- 核心规则测试已经验证潜艇首、尾鱼雷可手动发射，两舷方向会被射界拒绝。
- 鱼雷投射物、几何碰撞和伤害统计使用公共运行时；当前没有证据表明潜艇专用鱼雷无法造成伤害。

因此，修复入口应位于“AI 模式与开火纪律 -> 候选武器/瞄准 -> 命令提交 -> 潜航资源状态”，不应从伤害公式开始。

## 3. 已定位根因

### 3.1 `ReconAvoid -> Silent` 形成事实上的永久禁火

潜艇允许模式当前为：

```text
TorpedoFlank | ReconAvoid | DisengageRegroup
```

`ReconAvoid` 映射到 `Silent`。`Silent` 常规阈值为 `101`，紧急自卫才降为 `72`；公共攻击窗口评分最高为 `100`。潜艇一旦长期停留在 `ReconAvoid`，正常状态下便不可能开火。

模式评分会让视野需求、生存、边界安全和凝聚度持续抬高 `ReconAvoid`。现有接敌压力虽然提高 `TorpedoFlank`、降低 `ReconAvoid`，但不足以保证潜艇在可用鱼雷窗口前进入并保持雷击模式。

### 3.2 评分武器与实际合法发射器不一致

`_update_ai_primary_weapons()` 当前先取主武器状态数组的第一个条目作为 `aim_weapon`，再用它计算目标预测、命中质量、预期伤害、友军风险和伤害预留；随后 `_validate_primary_fire()` 才遍历全部前/后发射器判断是否合法。

另一方面，自动武器更新会原地按 `definition_id` 排序 `unit.weapon_states`。潜艇的 `aft_torpedo` 在字母序中排在 `fore_torpedo` 前，排序一旦发生，后续 AI 通常固定用尾鱼雷评分，即使当前合法窗口来自前鱼雷。

最终执行 `_fire_primary_weapon()` 又从本次合法状态中按稳定底座顺序选择第一座。于是可能出现：

```text
用于预测/评分/预留的武器
!= 产生合法窗口的武器
!= 命令执行时真正发射的武器
```

这属于公共多发射器主武器语义错误，潜艇首尾射界使其最容易暴露；修复不得依赖恢复某个数组初始顺序。

### 3.3 航行意图没有形成首尾雷击解

当前移动主要围绕目标位置、战略模式、编队和安全航迹，不会把“哪一座前/后鱼雷即将可用、需要把哪个射界转向目标”作为明确的局部火力解。诊断中大约一半可见目标 Tick 因 `FIRE_ARC_INVALID` 失去发射机会。

射界拒绝本身是正确规则，不能放宽为全向发射；需要由 AI 航向与位置选择主动形成合法首/尾扇区。

### 3.4 潜航资源曾只有强制上浮，没有重新下潜路径

截至 2026-08-10，潜艇开局为 `Submerged`，未配置独立氧气速率时默认约 90 秒耗尽并强制切换到 `Surface`；上浮后氧气恢复，但没有玩家命令、AI 决策或状态机把单位重新切回 `Submerged`。

2026-08-11 已补上公共 `SetSubmarineDepth`、主动转换、最短保持、低氧拒绝、零氧强制上浮、氧气恢复和玩家 `C` 重新下潜路径；完整 AI 也已通过同一命令生产雷击前上浮和补氧后下潜请求。`RecoverOxygen` 内保存请求目标与拒绝原因，不增加独立 `Redive` 阶段；请求被拒绝或再次强制上浮时保持补氧阶段。

### 3.5 报告缺少“有机会但为何没开火”的稳定证据

现有逐舰报告能看到 `shots=0`，但不能区分：

- 从未发现目标；
- 没有装填完成的武器；
- 目标不在射程或射界；
- 被 `Silent` / `HoldUntilWindow` 阈值拦截；
- 合法窗口与决策节拍错开；
- 已提交命令但被 Domain 拒绝。

缺少这些聚合事实，会把 AI 执行缺陷误判成伤害或关卡平衡问题。

## 5. 目标与非目标

### 5.1 目标

1. 让 AI 的瞄准、合法性、评分、预留和最终发射使用同一个确定性武器候选。
2. 让潜艇在已发现目标、武器就绪且能够形成雷击解时进入并保持 `TorpedoFlank`，不长期停在不可开火的 `Silent`。
3. 让首尾鱼雷继续遵守真实射界，并由航行层形成射角，而不是放宽规则。
4. 消除短暂合法窗口与 `0.5s` 决策节拍错开造成的无理由漏发；不得简单把全部 AI 决策提升为每 Tick 重算。
5. 为上浮、恢复氧气、重新下潜建立显式且有迟滞的命令/状态/AI 闭环。
6. 让报告可以解释潜艇零开火是缺目标、缺合法窗口、纪律保留、节拍漏失还是命令拒绝。
7. 修复后先恢复潜艇职责，再重新评估 S-04/S-05 胜率；两类结论不得混在同一次调参中。

### 5.2 非目标

- 不在本工单调整战列舰主炮、驱逐舰鱼雷或潜艇鱼雷基础伤害。
- 不通过提高海狮/U-47 HP、Cost、射程、管数或技能倍率掩盖零开火。
- 不为潜艇增加全向鱼雷、忽略射界、瞬时转向、无视装填或保证命中的特殊规则。
- 不在本工单一次性完成全部声呐、深水炸弹、反潜直升机和航空侦察潜艇；首轮设计复用 `ReconAvoid / TorpedoFlank / DisengageRegroup`，不另建平行的 `SubmarineAmbush` 战略模式。
- 不以“至少造成一次伤害”作为确定性正确性门禁；鱼雷仍可能被规避或未命中。
- 本工单的建立不等于授权立即执行 20 局以上统计、侧别交换或平衡矩阵。

## 6. 必须保持的正确性不变量

1. **同一武器候选**：AI 选择的 `weapon_state` 必须贯穿瞄准、命中/伤害评分、友军风险、伤害预留、命令验证和实际发射。
2. **稳定选择**：多个合法候选同分时按显式稳定键选择；结果不得依赖 `unit.weapon_states` 曾被哪个系统原地排序。
3. **Domain 权威**：AI 只能提交普通 `FirePrimaryWeapon` 或正式新增的公共命令，最终射程、射界、装填、管组间隔和目标类型仍由 Domain 校验。
4. **不全局降低纪律**：不得通过降低所有单位的 `Silent` 或 `HoldUntilWindow` 阈值修复潜艇；水面侦查舰与鱼雷舰现有纪律语义必须保持。
5. **无特定角色分支**：角色 ID、关卡 ID 和阵营不得进入公共潜艇开火算法。
6. **深度迟滞**：氧气耗尽必须强制上浮；氧气未恢复到配置门槛不得重新下潜；上浮/下潜必须有最短保持或迟滞，不能逐 Tick 抖动。
7. **状态可观察**：深度转换、纪律阻止、窗口保留、命令提交与拒绝必须产生可聚合事实，但不能把隐藏敌方状态泄漏给玩家表现层。
8. **固定种子确定性**：相同配置、种子和 Tick 顺序必须得到相同的模式、候选武器、深度转换和首个发射 Tick。

## 7. 实施拆分

2026-08-11 已按“公共 AI 管线 + 潜艇阶段策略层”完成设计和运行时接入。`submarine_combat_phase` 只有 `Search -> Approach -> SurfaceForAttack -> AttackRun -> BreakContact -> RecoverOxygen -> Search` 六个阶段；特殊潜射艇可由 `Approach` 直接进入 `AttackRun`，重新下潜是 `RecoverOxygen` 内的深度请求。阶段固定投影模式与纪律，潜艇跳过公共模式/战术状态切换；目标与雷击解分别复用公共 `target_score`、`attack_window` 后作分层稳定排序，不维护专属加权公式。

### 7.1 建立可长期复验的诊断指标

- **优先级 / 状态**：P0 / 已完成
- 在 AI/战斗记录中聚合：可见目标决策样本、就绪样本、合法射程/射界样本、纪律与阈值、窗口分数、被节拍错过的保持窗口、选中武器 ID/底座、提交数、拒绝原因和实际发射数。
- 记录潜艇在 `Submerged/Surface` 的驻留时间、强制上浮次数、主动上浮/下潜次数和氧气区间。
- 默认报告保留聚合值与少量首例，不输出每 Tick 巨量日志。
- **关闭条件**：单局报告能区分第 3.5 节的六类零开火原因；相同固定种子指标一致。

2026-08-16 实施证据：`BattleRecorder` 每个固定 Tick 累积潜艇阶段、深度与氧气区间，并按主要武器决策点记录可见、就绪、合法候选、窗口评分/阈值、纪律结果、发射器实例、机会触发/过期、命令拒绝和实际开火。模拟单局与聚合结构新增 `submarine_ai`，报告写出 `submarine_ai.csv`、`submarine_ai.md` 及主报告摘要；零开火按无决策、无目标、无就绪、无合法解、至少 5 个合法窗口仍零开火、已提交未执行、纪律保留或未分类分别归因。友军雷道另记评分忽略样本、观察阳性样本和最高观察值。报告只保留聚合与最多 6 个循环样例，不输出逐 Tick 日志。

### 7.2 统一候选武器的评估与执行

- **优先级 / 状态**：P0 / 已完成
- 从每个“启用且装填完成”的主要武器状态构建候选；按该武器生成瞄准解并验证自己的射程/射界。
- 对合法候选分别计算窗口评分，选择稳定最优候选；评分、伤害预留和实际发射必须引用同一状态。
- 复核 `FirePrimaryWeapon` 的组级命令语义：优先复用一个返回确定性首选状态的公共 helper；若必须传递内部首选底座提示，需由 Domain 重新验证，不能直接信任 AI。
- 禁止在任何更新循环中原地重排权威 `unit.weapon_states`；需要排序时对 ID 或浅拷贝排序。
- **关闭条件**：前管合法、后管合法、两者均合法、一座装填、一座禁用和数组预先乱序均有测试；事件中的实际武器与评分候选一致。

2026-08-11 实施证据：`FirePrimaryWeapon` 新增可选 `weapon_state_instance_id` 提示，Domain 按该实例重新验证并在失效时拒绝；瞄准、公共窗口、伤害预留、命令和 `WeaponFired` 使用同一实例。权威 `weapon_states` 不再被自动武器更新原地排序；核心专项覆盖首尾射界、非法提示、数组乱序和实际事件实例，六个固定种子均为零实例偏移、零 AI 主武器拒绝。

### 7.3 修复潜艇模式与开火纪律衔接

- **优先级 / 状态**：P0 / 已完成
- 潜艇发现合法目标、至少一座鱼雷接近就绪且存在可达雷击解时，提高并保持 `TorpedoFlank`；`ReconAvoid` 只承担搜索、控制暴露或主动脱离。
- 运行时按正式阶段推进；只有同源候选实际产生 `WeaponFired` 才能从 `AttackRun` 进入 `BreakContact`，纪律保留、窗口过期或命令拒绝不得伪造任务完成。
- 保留 `Silent=101/紧急72` 和 `HoldUntilWindow=68` 的公共语义；通过模式选择和明确的潜艇任务状态解决永久禁火，不修改全局阈值。
- 为短暂窗口增加有限有效期的“已观测雷击机会”或在 0.5 秒决策点重新计算当前候选，消除一个 Tick 窗口无理由丢失；缓存不得绕过最新 Domain 校验。
- 有效发射后才进入脱离/重新装填循环；不能在从未发射时把“等待窗口”当成任务完成。
- **关闭条件**：海狮/U-47 在固定种子中不再长期处于“有多个合法决策样本但零提交”；水面侦查舰的 `ReconAvoid/Silent` 回归签名不变。

2026-08-11 实施证据：阶段直接投影 `ReconAvoid/TorpedoFlank/DisengageRegroup` 和 `Silent/HoldUntilWindow/SelfDefense`，潜艇不写入持久 `Attack/Defend/Kite`。只有计划实例的实际 `WeaponFired` 才完成 `AttackRun`；补氧阶段的 `SelfDefense` 开火保持在补氧/脱离语义中。公共接敌压力不再把潜艇的“仅形成合法窗口”误记成已解决，生效且等待当前武器消耗的技能增益也正确进入公共 `skill_synergy`；没有修改公共窗口权重或纪律阈值。AI 量化回归 `58/58`。
