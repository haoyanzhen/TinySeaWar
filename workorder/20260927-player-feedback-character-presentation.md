# 玩家战斗反馈与角色表现闭环工单

> 建立日期：2026-09-27；状态：调研完成，实施与人工验收待执行。
>
> **功能与边界**：记录玩家理解战斗事实、识别威胁、辨认角色与复盘的表现缺口、修改价值和验收任务。本轮只建立工单，没有实现这些表现，也没有进行实机视觉验收。当前完成度仍以 [00](../docs/00_project_status.md) 为准；本工单不成为第二套规则或资产契约。

## 1. 范围与依据

规则与计算由 `10/12/18/32/37` 拥有，操作由 `11` 拥有；表现架构见 [33](../docs/33_domain_design_phase2.md)，角色方向见 [40](../docs/40_art_direction_design.md)，战斗特效见 [42](../docs/42_combat_art_design.md)，环境视觉见 [43](../docs/43_scene_art_design.md)，HUD 与可读性见 [44](../docs/44_ui_art_design.md)，语义接口见 [45](../docs/45_art_asset_interface_design.md)，角色生产与交付见 [46](../docs/46_character_art_asset_pipeline.md)。代码位置总入口见 [34](../docs/34_implementation_map.md)。

本次证据来自仓库文档及实际函数链路静态检查。下列“证据”是建单时快照，“建议”是待实施方案，不表示已验证的玩家效果。未运行新平衡实验，未以素材齐备推断演出完成。

明确排除：

- 潜艇寻敌、航行、发射器选择、开火纪律及完整进攻循环修复继续由 [潜艇运行时工单](20260810-submarine-combat-ai-runtime-closure.md) 承担，用户已明确本轮暂不处理。

- 通用命令拒绝、暂停、HUD 控件、结算标题及保存失败重试由本轮独立实现任务承担；本工单只要求复用其最终接口，不另建通知系统。
- 不调整伤害、发现距离、天气倍率、角色 Cost 或关卡胜率掩盖反馈缺口。

## 2. 优先级与修改价值

P1：高价值，优先保障事实可信、危险可辨及角色识别；P2：在 P1 成立后补完整过程与复盘；P3：装饰增强。优先级是建议实施顺序，不表示本轮授权实施全部内容。

| 任务 | 优先级 | 玩家价值 | 状态 / 依赖 |
| --- | --- | --- | --- |
| F01 攻击结果原因与事实一致 | P1 | 减少“打中了为什么没伤害”的错误归因 | 待实施；伤害事实字段审查 |
| F02 已发现鱼雷危险提示 | P1 | 在连续操作中及时注意可反应威胁 | 待实施；合法观察和公共威胁事实 |
| F03 航空、防空与反潜过程 | P2 | 看懂护航与支援贡献，形成舰种价值感 | 待实施；先界定当前规则抽象 |
| F04 潜航可见状态与操作条件 | P1 | 减少深度、氧气、发射限制的记忆负担 | 待实施；只消费现有权威状态 |
| F05 天气与局部环境影响摘要 | P1 | 能把观感变化关联到战术选择 | 待实施；环境有效上下文 |
| F06 有证据的战后复盘 | P2 | 让失败成为下一次可改变的决定 | 待实施；结果与事实留存 |
| F07 角色、舰装和动画装配 | P1 | 保持角色辨识，消除旋转与重影观感 | 部分复用旧工单；资产审查 |
| F08 最小语义音频闭环 | P1 | 让重要状态不依赖持续盯 HUD | 待设计后实施；目前没有正式音频系统 |
| F09 可访问性与信息预算 | P1，贯穿以上任务 | 连续操作不被提示、闪光和演出打断 | 待实施与人工验收 |

## 3. 具体任务

### F01 攻击结果必须能解释且不虚构原因

**证据**：[battle_effect_director.gd](../scripts/presentation/battle/battle_effect_director.gd) 的 `_handle_attack_resolved`、`_spawn_large_gun_water_column` 已消费固定落点和命中事实；`_damage_number_style` 将所有 `hit=false` 显示为“未命中”，将零伤害按武器 ID 是否含 `_ap` 直接命名为“跳弹”或“格挡”。这是表现层从名称推断结算原因，不能证明领域实际发生跳弹或格挡。已有跳字按目标合并且最多保留三条，应继续复用。

**方案**：先盘点 `DamageService` 与 `AttackResolved.damage_result` 能提供的真实原因。区分落点未接触、接触后概率未命中、伤害被防护削减、岛岸阻挡；如果缺少足以证明的原因，仅使用“未造成伤害”等中性描述。新增原因字段应在权威结算点记录并同步所属 Schema，不在视图重新计算。正伤害的装甲削减优先放入选中目标详情或复盘，不逐发弹出完整公式。保留小中口径不生成重水柱的既有规格。

**验收**：固定场景覆盖落空、几何接触但未命中、正伤害减免、零伤害、炮弹/鱼雷撞岸；每个标签可回溯同一事件事实。重炮水柱停留在权威落点；一次事实不能重复生成多组伤害数字；无原因字段不得猜测机制。

### F02 鱼雷危险可注意，但不泄露隐藏威胁

**证据**：`BattleEffectDirector._sync_projectiles` 已从快照维护投射物，`prototype_battle.gd` 的 `_draw_torpedo_aim_overlay` 已绘制己方瞄准扇区；这两项不等于面向受威胁己舰的完整危险提示。鱼雷是否发现由规则与阵营共享决定。

**方案**：选中舰附近使用克制的方向/危险标记，画外受威胁舰用头像角标与可选屏幕边缘箭头；只处理本队已发现鱼雷。风险等级读取公共威胁评估的合法输出，缺少稳定预计接触时间时不显示精确倒计时。不得把“预测相交”写成“必定命中”，也不得暴露发射者位置或尚未发现的其他雷道。危险解除、鱼雷失效和切换场景及时清除。

**验收**：未发现时无方向、音效或角标泄露；首次发现、持续危险、解除、重新进入危险、画外威胁均可复现；密集鱼雷按受威胁舰聚合；连续移动/瞄准期间不夺焦点、不自动切舰、不暂停。

### F03 航空、防空、反潜要有可追踪的过程

**证据**：表现导演为 `Gun` 专门创建 `ShellFlightView`，其余武器使用通用开火/命中角色；`_handle_support_resolved` 对空袭主要产生水面命中特效。`battle_session.gd` 的 `_resolve_attack` 使用 `_aviation_survival_ratio` 缩放航空伤害，当前防空存在聚合计算，不可据此直接宣称有逐架飞机 HP、逐架击落或完整返航模拟。已有 `AntiAir/AntiSubmarine/Aviation` 跳字分类是基础，不能替代过程表现。

**方案**：先给航空建立“出击→抵达/受拦截→结算”的表现时间线，读取同一攻击 ID 和延时事实；防空用覆盖/拦截参与及有据的削弱结果体现护航贡献。规则未提供飞机数量与击落事实时，只显示抽象编队及“遭拦截”，不编造击落架数。反潜复用 `asw_launch_*` 挂点，表现投放、入水和权威结算，不从主炮口发射深弹。角色/公共资产缺失时必须有可读降级。

**验收**：出击来源、结算目标和时刻可关联；被防空削弱与未被削弱两条路径能看出差别；全拦截/目标消失等边界按实际规则收尾；反潜与炮击、鱼雷视觉可区分；隐藏潜艇不因特效显示精确位置。两用炮共享装填仍引用旧审计工单 §2.2，不在表现任务私自决定。

### F04 潜航表现只解释已有事实

**证据**：`ShipUnitView._submarine_depth_blend` 已按权威转换进度调制颜色与透明度；HUD 已显示氧气、深度、转换剩余时间与深度操作可用性。因此应补齐可读性，不能从零重做或宣称潜航毫无表现。

**方案**：在选中舰操作区解释当前转换、氧气不足、最短保持或普通鱼雷要求稳定上浮等实际限制；复用通用拒绝反馈。已可见潜艇可加入低密度气泡/水波，使上下潜变化更容易辨认。未来预计可用时间只在所需权威字段完整时显示；不能把预计恢复当作保证。

**验收**：上浮、下潜、转换中、零氧强制上浮和可再次下潜条件各有一致状态；切换选中舰不残留旧倒计时；晴昼与雷雨夜间均可读。任何表现完成不得关闭潜艇 AI 执行问题或替代其正式验证。

### F05 天气影响从背景变为可理解的信息

**证据**：HUD 已绘制环境区图标，环境玩法与视觉分别由 `18/37` 和 `43` 拥有。图标与天气外观不能直接解释本舰当前叠加后的机动、侦查和武器影响。

**方案**：战前展示本局最重要的少量天气/时段影响，选中舰详情展示当前有效环境摘要及来源；采用“进入高海况区”等短状态变化提示，不逐 Tick 重复广播。若显示数值，直接读取环境上下文/正式配置的有效结果，不在 HUD 复制修正公式。潮汐相关提示只显示玩家合法知道的状态。

**验收**：全局与局部叠加、离开区域、天气/潮汐切换后摘要与权威上下文同步；覆盖晴昼、浓雾、雷雨夜；视觉弱化选项不改变数值，也不使关键危险标记消失。

### F06 复盘先说事实，再给有限建议

**证据**：建单时 HUD `_draw_result_panel` 已显示终局原因摘要，但复盘仍是固定的“留意主要武器待发时间、集火目标和旗舰位置”。现有终局原因、目标事实与伤害统计可作为输入，不足以自动证明“如果做 X 就会获胜”。

**方案**：先显示任务终止的具体条件，再展示最多数项可定位的关键事实，如旗舰沉没时刻、关键目标未完成、主要伤害类别与来自合法记录的命令失败。建议须明确区分“观察事实”和“下次可尝试”；没有足够证据时省略建议。战后全知视图需独立授权，不能把全量敌方内部信息倒灌局内 HUD。技术无效与保存失败分别使用各自状态，不制造战术失败原因。

**验收**：胜/负/平/任务取消/技术无效均有正确说明；每个事实可关联事件或聚合字段；无记录时可降级；重复查看不会重复发奖励；存档重试行为归独立任务测试。

### F07 角色本体、舰装、武器与动画分层

**证据**：`ShipUnitView._draw_unit_art` 将动画帧/静态本体按 `heading` 旋转，并额外绘制 `rig_texture`；`_unit_art_scales` 用静态 `body_texture` 宽度计算动画共用比例；`bind_point_world` 统一应用航向旋转。素材交付状态不能证明组合帧与底座无重复、各状态尺寸一致或武器节点已经独立装配。

**职责去重**：角色左右朝向、防抖和不可镜像元素继续由 [第四轮未闭环工单 §2.4](20260717-design-audit-round4-unclosed-items.md#24-角色本体朝向与翻转防抖) 负责；技能 cut-in 由该工单 §2.5 负责。本工单仅补充装配、比例和整体玩家验收，旧项必须在原工单关闭，不复制一套完成状态。

**方案**：先按六舰种各选代表角色，盘点组合帧实际包含的本体、底座与武器，确定每个部件唯一绘制者；不得直接叠上全部拆件。角色本体左右朝向，舰装保留航向旋转，独立武器按合法方向表现；挂点变换跟随对应图层，同步镜像、旋转、缩放。各动画状态采用明确画布/基准尺度与锚点，避免仅因 PNG 宽度变化造成角色伸缩跳动。先验证已有资产能否满足，再决定必要的重制，不默认重生全部 48 套。

**验收**：代表舰通过四象限、垂直临界、连续转弯以及待机/移动/攻击/受击/技能切换；炮口与弹体起点无漂移，无双底座/重复武器，无明显尺度突变。再对 48 名角色执行加载/挂点/跨状态比例检查及逐件人工审查；资产内容改变时按 `46` 重做当前哈希交付审查。碰撞椭圆与规则射界不随美术修正改变。

### F08 最小语义音频基线

**证据**：当前状态明确没有正式音频设计、资产、总线和播放代码；仓库运行代码检索未找到 `AudioStream` 播放链。不得将已有 VFX 或音频建议描述成完成。

**方案顺序**：先补正式音频设计、事件语义、总线和资产归属，再导入有来源/使用权记录的声音。首批建议为命令拒绝、选中舰主要武器就绪、主要武器发射、已发现鱼雷危险、旗舰危急、结算；高频操作确认应短促、可关闭，拒绝声音服从统一去重与限频。总线至少区分主音量、战斗效果与提示；音乐及角色语音后置。总线名称与精确音量在正式契约中定稿，本工单不作为音频 Schema。

**验收**：声音来自实际事实且不提前；连续拒绝、齐射和多舰就绪不形成音量堆叠；隐藏敌人不通过声像位置泄露；暂停/恢复/重开不残留循环声或重复播放；静音仍保留等价视觉提示，配置持久化正确。

### F09 可访问性与信息预算

**基线**：`44` 已要求敌我、可用性、潜航与生存状态不能只靠色相。当前鱼雷瞄准合法/非法扇区依赖显著红绿颜色，后续应增加轮廓、图标或短文本辅助；已有跳字聚合应保留。

**方案**：重要状态使用文字/形状/颜色冗余；支持降低闪光、震屏和装饰粒子，保留必要战术提示。提示不抢焦点、不改选中对象、不移动镜头、不关闭瞄准；同源重复合并，瞬时提示消失后可从简短历史查看。cut-in 若实施，遵循原工单确定的简化/关闭及并发策略，不占用连续操作窗口。

**验收**：静音、降低动态效果、低色彩辨识情境下仍能完成同样指令；常用分辨率及缩放下文字不溢出、不盖住准心/舰船操作区；密集事件与持续鼠标/键盘输入同时发生时没有焦点丢失和输入吞噬。人工记录哪里没看懂、哪里被打断，不能只用截图存在判定通过。

## 4. 实施依赖与关闭条件

1. 先确认本轮通用拒绝、控件、暂停和结算结果接口，避免两个通知或结果展示系统并存。
2. 对 F01/F03/F06 逐项建立“权威事实→允许披露字段→表现消费者”映射；缺失事实先补契约，不能用表现猜测填空。
3. F07 先完成代表角色装配证明；F08 先补音频设计与资产语义。新增字段更新 `21/25/26` 中实际所属契约，代码入口变化更新 `34`，资产接口变化更新 `45`。
4. 每个任务分别记录实现、自动验证、人工体验验收；状态只能在证据形成后由待实施转待验证/已关闭。纯文档本轮不运行战斗模拟，也不更新为“美术完成”。

共同关闭证据应包含：具体场景与种子、角色/天气/分辨率、事件事实与可见性断言、正常/缺资产降级截图或短录像、人工观察记录及未关闭问题。自动测试覆盖原因映射、隐藏信息、事件重复、生命周期和设置持久化；人工覆盖连续操作、画外危险、短时密集攻击与晴昼/恶劣夜间可读性。绝对性能和潜艇完整循环不纳入本工单关闭条件，仍明确保留在原工单。
